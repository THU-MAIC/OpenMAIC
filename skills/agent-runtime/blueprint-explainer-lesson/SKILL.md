# 蓝图说明书风讲解课

先加载 `/stage-design`，按它的流程建课、写 roster、逐页 `generate_scene`、最后 `generate_tts`；本 Skill 只规定这一段讲解的结构、视觉和讲稿。在 OpenMAIC 里，「讲稿」就是每页的旁白：按页内的块拆成短段，配聚光灯或激光笔指向对应的元素。已有本风格的 .pptx 时走 `/pptx-import`；要补页时按 `/page-clone` 用 `duplicate_scene` 复制相邻页再只换字；页面元素的写法以 `/slide-craft` 为准；有 `render_scene_preview` 时，交付前逐页渲染检查。

## 什么时候用

- 一节课里专门讲清**一个原理或机制**的那一段：3–5 分钟，约 6 页幻灯片，画面是蓝底白线的工程图纸，每页配一段讲稿。
- 讲完以后学员带着正确的理解进入下一个环节（练习、实验、讨论、作业、下一节课），并在那里认出图纸上标过的零件。
- 不限学科。适合讲结构、流程、因果链条；尤其适合「看起来像魔法，其实有零件」的话题。
- 它的气质是「把机器摊在桌上拆开看」：冷静、精确、有编号。气质偏冷，建议和一种暖一点的风格（如漫画、像素）在同一门课里搭配使用——图纸段只负责把机制摊开。
- 不适用于：整门课的完整课程设计、纯操作实训、习题讲评课。这里只负责机制讲解那一段。

## 一、开工前先弄清楚四件事

1. **核心理解**：一句话，学员学完必须带走的那条道理。
2. **讲完之后学员去做什么**：练习、实验、讨论、作业还是下一节课。讲解要为它铺路，但不提前替学员做完。
3. **要落到的知识点**：本节的术语、概念、公式、原理，最多四个。它们会变成零件表上的零件。
4. **课程里真实存在的设定**：用到的案例、对象、编号体系，课程里有没有。不要发明课程里没有的角色、型号或情节。

缺任何一样，先问，不要猜。

## 二、结构：图签、故障单、结构图、装配步骤、零件表、验收

总时长 3–5 分钟，讲稿合计 1000–1500 字。默认 6 页：

| 页 | 环节 | 时长 | 做什么 |
|---|---|---|---|
| 1 | 图签 | 约 30 秒 | 封面：大标题、右侧一张简化结构图、右下角图签表（图名、课程、页数、比例） |
| 2 | 故障单 | 约 30 秒 | 一张故障报告：现象、复现方式、预期结果，点出本节问题 |
| 3 | 结构图 | 约 60 秒 | 讲透核心理解：总装图或爆炸图，标注线加编号圈，关键零件用黄色标出；也可以是「正常件 vs 问题件」并排 |
| 4 | 装配步骤 | 约 75 秒 | 生活场景类比，画成四个编号步骤框：第 1 步是问题，后三步各是一条规矩 |
| 5 | 零件表 | 约 60 秒 | 表格：左列是类比里的东西，右列是本学科术语，再加一列「作用」 |
| 6 | 验收 | 约 30 秒 | 验收清单：带进下一个环节的三项检验，每项写「怎么查」，不写结果 |

规则：

- **一个类比只占一页。**
- **装配四步和零件表一一对应。** 第 4 页每一步一条规矩，第 5 页都要找到对应的术语和作用。
- **后续环节的答案不进幻灯片。** 练习题化成验收清单上的检验项，只写怎么查，不写查出来是什么。
- **故障单页可选。** 没有合适的现象，去掉，改为 5 页。
- **页数可伸缩，环节顺序不变。** 知识点少时可以把结构图和零件表合成一页。

各学科的例子（只是举例，按实际主题重选）：

| 学科 | 核心理解 | 装配步骤场景 |
|---|---|---|
| AI | 模型读的是 token，不是一个个字母 | 快递分拣：包裹按整箱扫码，不拆箱数里面几件 |
| 生物 | 神经冲动沿反射弧单向传导 | 接力赛：棒只能往前传 |
| 化学 | 催化剂降低活化能，本身不被消耗 | 修一条隧道，翻山变穿山，隧道还在 |

## 三、内容的严谨性

图纸给人「精确」的感觉，所以说法更要准确。

- **主语要准。** 每个编号零件对应一个确切的部分，不要用笼统的大词代替。
- **不要说过头。** 结论只说到证据支持的范围。
- **简化必须标注。** 图纸上的切法、比例、数值如果是示意，在图上或表格下用一行小字写「注：……为简化示意」。
- **类比要标边界。** 类比里成立、本学科里不成立的地方，讲稿里点一句。
- **区分「看起来对」和「确实对」。** 验收页提醒学员用证据检验。

## 四、页面文字

- **图号行**：每页左上一行等宽字，`DWG NO. 课程代号-节号 · SHEET n/6`。
- **标题**：图号下方一句话，不超过 20 字。全课用同一种句式（如「结构图：…」「爆炸图：…」）。
- **编号圈**：①②③④，圈里只放数字，说明写在右侧零件清单里。
- **英文角标**：只用短英文大写（PARTS LIST、TOKEN #1、STEP 1、CHECK）。
- **注释**：表格或图下方一行小字，以「注：」开头。
- **页面上写过的，讲稿里不再念。**

## 五、视觉规范

画布 16:9，按 1920×1080 设计。

**字体**

- 标题、正文：**思源黑体**（Noto Sans SC），标题 900 字重，正文 400–700。
- 图号、编号、英文角标、代码：**等宽字体**（Courier New 或 JetBrains Mono），700 字重。

**颜色**

| 用途 | 色值 |
|---|---|
| 背景（蓝图纸） | `#1D4E89`，叠 48px 网格线 `#2B5E9B`（横竖各一层，2px） |
| 图框 | 3px `#9EC3EA`，距边 96px |
| 大标题 | `#FFFFFF` |
| 线条、正文 | `#E8F1FB` |
| 辅助线、尺寸线、图号、表头 | `#9EC3EA` |
| 次要说明、注释 | `#BFD6EE` |
| 关键零件、出问题的地方 | `#FFC857`（全页只给一个零件用） |
| 零件填充（需要时） | `#2B5E9B` |

**版式元素**

- **图框**：每页一个细线外框，像真的图纸。
- **图签**：封面右下角的表格，四行：图名、课程、风格或版本、比例。
- **结构图**：只用线框，不填色；3px 实线画零件，2px 虚线画基准线，尺寸线两端带短横。
- **标注线 + 编号圈**：从零件引一条细线到 26px 半径的圆圈，圈里放编号。
- **爆炸图**：总装件在左，拆出的零件在右，中间虚线箭头连起来，零件框用 3px 虚线边。
- **零件表 / 规格表**：表格，表头用 `#9EC3EA`，关键单元格用黄色字。
- **装配步骤框**：四个等宽线框横排，左上角 `STEP n`，框里一幅简笔示意 + 一句规矩。
- 每个零件、步骤框都是独立元素，方便 AI 老师用聚光灯和激光笔逐个指；标注线天然适合配激光笔。
- 不加阴影、不加渐变光效、不倾斜。

**人物与道具**

- 尽量不画人。需要人时，用线框简笔人形（圆头 + 线条身体），白色 3px 线。
- 道具画成线框正视图或等轴测图：箱子、齿轮、管道、卡片。
- 图上的文字一律放在 SVG 外面，用文本元素叠上去，不写进 SVG。
- **不要画真实产品的结构图、品牌 logo 或受版权保护的技术图纸。**

## 六、讲稿

讲稿要像一个工程师拿着图纸给你讲，清楚、有顺序，不炫技。讲稿单独成一份文档，按页分节。

- **每页开头先写一行【屏幕替你说了：……】**，列出屏幕上已有、不用念的内容。正文只讲屏幕上没有的：为什么、容易栽在哪、下一步去哪。
- **按编号走。** 「先看①号，再看②号」，顺序和图上的编号一致。
- **用口语。** 短句。术语第一次出现时用一句大白话解释。
- **留出互动。** 括号标动作提示：`（激光笔指③号）`、`（停三秒，让大家比一下两列）`。
- **装配步骤页先交代结构。** 「第 1 步是问题，后面三步各是一条规矩」，每步按「报名字 → 讲道理 → 落回本学科」三步讲。
- **埋一条暗线。** 让一个零件贯穿：故障单里出问题的那个东西，在结构图上被标成黄色，在零件表里有了名字，验收页再回去查它。
- **结尾不总结全课**，直接把学员送进下一个环节：三项验收。

## 七、交付前自查

- [ ] 核心理解在结构图页讲透了，主语、范围都对。
- [ ] 装配步骤只占一页；四步和零件表一一对应。
- [ ] 后续环节的答案没有出现在幻灯片上。
- [ ] 没有课程里不存在的角色、型号或设定。
- [ ] 所有简化、示意都有「注：」说明。
- [ ] 黄色全页只用在一个关键零件上。
- [ ] 编号圈和右侧说明一一对应，顺序和讲稿一致。
- [ ] 没有真实产品图纸或品牌 logo。
- [ ] 讲稿每页有【屏幕替你说了】，总字数 1000–1500。

## 八、例外

- **这门课后面没有承接环节**（这一段讲完就结束，没有练习、实验或下一节接着）：不写「接下来进练习／工作台／项目」这类没有下文的词。三项检验改成当堂能自查的检验项，仍只写「怎么查」、不写结果；讲稿结尾说「讲到这儿这一节就完了」，并把最要紧那项检验变成一句回头路——「答不出来回第 3 页看那个黄色零件」。
- **课程本身已有另一套视觉体系**（浅色极简课件等）且用户要求保持一致时，视觉规范让位给原课件，只借用「六环节顺序 + 图号行 + 编号圈 + 黄色只标一处 + 一个零件贯穿 + 验收清单往前送」这套做法。
- **用户给了逐字稿原话**：保留其事实与顺序，只压缩句式、拆分段，不新增内容。
- **故障单找不到合适的现象**：去掉第 2 页，5 页；顺序不变。
- **用户明确说「不要类比」「直接讲结构」**：去掉装配步骤页，把该页的规矩并进结构图页，顺序不变。
- **同一门课里已经有漫画或像素风格的段落**：图纸段只做机制那一段，不要把整门课都改成图纸；两段之间靠同一个零件或同一个编号呼应，让学员在暖风格段里认出图纸上标过的东西。
- **知识点少**：结构图和零件表合成一页，编号圈与表格同屏，黄色仍只标一处。

## 附：完整示例（AI 原理 · 它为什么数不清 strawberry 里的 r）

核心理解：模型读文本时，先把文本切成 token 再处理；单个字母常常藏在 token 里面，所以「数字母」这类任务它没法直接看着数。

1. **图签**：标题「你的小 AI 聪明得一块一块」。右侧结构图三个高矮不一的模块，最矮的一个标黄。图签：图名「小 AI 能力结构图」，课程，SHEET 1/6，比例 1:1。
2. **故障单**：现象「问 strawberry 里有几个 r，答 2 个」；复现「换个单词也会数错」；预期「3 个」。
3. **爆炸图**：左边总装件 strawberry（10 个字母）；右边拆出两个零件 straw、berry，标 TOKEN #1、#2，零件框标黄。注：切法为简化示意，不同模型切法不同。
4. **装配步骤：快递分拣**。STEP 1：问「这批货里有几支笔」，分拣员答不上。STEP 2：包裹按整箱扫码入库。STEP 3：扫码只认箱子编号，不拆箱。STEP 4：要数笔，得先开箱一件件摆出来。
5. **零件表**：整箱 → token → 模型处理的最小单位；箱子编号 → token 编号 → 模型实际收到的东西；不拆箱 → 不直接看字母 → 数字母靠推断；开箱摆出来 → 先拆成单个字母再数 → 补救办法。
6. **验收**：CHECK 1 这个任务需要看到单个字母吗？怎么查：看任务是不是在数、拼、倒序字母。CHECK 2 你给它的材料，字母是拆开的吗？CHECK 3 它答对了，是数出来的还是猜中的？怎么查：换一个词再问一次。
