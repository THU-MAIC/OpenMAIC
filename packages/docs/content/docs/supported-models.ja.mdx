このページでは、オープンソース版 OpenMAIC に組み込まれているプロバイダーとモデルを一覧にしています。[`openmaic.yml`](./configuration.mdx) では、プロバイダーがこのいずれかを `preset` として指定し、Web アプリのモデル設定も同じカタログを提供します。実際に使えるかどうかはプロバイダーのアカウント、地域、サーバー設定にも依存し、プロバイダーの `models` 一覧でモデル設定に表示される選択肢を絞り込むこともできます。

## プリセット

プリセットは組み込みのプロバイダーテンプレートで、どのベンダーか、どのエンドポイントか、1 つのアカウントでどの機能をカバーするかを表します。`openmaic.yml` やモデル設定のすべてのプロバイダーはプリセットを指定します。

**単一機能のプリセット**は、以下の各表のプロバイダー ID を機能ごとに 1 つずつ使います。`openai` は OpenAI のチャットで、OpenAI の画像・音声合成・文字起こしはそれぞれ `openai-image`、`openai-tts`、`openai-whisper` です。3 つの ID は他のプリセットが既に使っているため、レジストリ ID と異なります。MiniMax の Web 検索は `minimax-search`、Doubao の Web 検索は `doubao-search`、Lemonade の画像生成は `lemonade-image` です。

**Token Plan プリセット**は 1 つのキーで複数の機能をカバーし、各機能はプラン独自のエンドポイントを使います。**設定 → Token Plan** でこれを接続すると、プランがモデルを推奨しているスロットのうち未割り当てのものにもモデルが設定されます。

| プリセット | プラン | カバーする機能 |
| --- | --- | --- |
| `minimax` | MiniMax | チャット、画像、動画、TTS、Web 検索 |
| `tokendance` | TokenDance | チャット、画像、動画、TTS、Web 検索 |
| `volcengine-ark` | Volcengine Ark Agent Plan | チャット、画像、動画、TTS、Web 検索 |
| `kimi-coding-plan` | Kimi コーディングプラン | チャット、Web 検索、Webページ取得 |

**設定 → Token Plan** で Kimi Coding Plan を接続すると、プランのキーと `https://api.kimi.com/coding/v1` を共有するチャット、ウェブ検索、ウェブ取得が推奨されます。ウェブ取得が暗黙の内蔵リーダーの既定値のみを使っている場合、現在の設定を保持する場合も、競合の確認なしで Kimi が直接割り当てられます。ワークスペースの明示的な選択（`null` を含む）と、デプロイ設定の内蔵以外のリーダーまたは `null` には既存の競合時の選択肢が適用されます。切断するとプランの割り当てが削除され、サーバーの既定値（リーダー未設定時は内蔵リーダー）に戻りますが、以前のワークスペースの明示的な選択は復元されません。ロックされたスロットは変更されません。ウェブ取得を宣言しないプランは、このスロットを変更しません。

初回設定ウィザードではウェブ取得に内蔵リーダーを維持し、Token Plan 設定ページからプランを接続した場合にのみ、その取得の推奨設定が適用されます。

`openai-compatible` は任意の OpenAI 互換チャットサーバーに接続します。`baseUrl` が必要で、モデル設定に表示されるのはその `models` 一覧です。

## Web Search プロバイダー

ほとんどの Web 検索プロバイダーにはモデル選択がないため、スロットでは通常プロバイダー ID だけを書きます（`webSearch: tavily`）。SearXNG は `openmaic.yml` でのみ設定できます。その他のプロバイダーは表のとおり API キーまたは Base URL が必要です。MiniMax と Doubao の Web 検索のプリセット ID は `minimax-search` と `doubao-search` です。

| Provider | Provider ID | Models |

### DeepSeek の Web 検索と取得

`deepseek` プリセットはチャット、Web 検索、ホスト型 Markdown 抽出で `DEEPSEEK_API_KEY` と API ベース URL を共有します。検索は `POST /v1/tools/search` を使い、最大 50 件を返します。クエリは Unicode コードポイント単位で 128 文字に切り詰め、結果には `summary`、空の場合は `snippet` を使います。取得は `POST /v1/tools/fetch` を使い、`content` と空でない任意の `title` を読み取ります。

旧設定では `WEB_SEARCH_DEEPSEEK_ENABLED=true`、または `server-providers.yml` の明示的な `web-search.deepseek` エントリーで有効にします。チャットの認証情報だけでは検索を有効にせず、既存の検索の既定値も変更しません。`WEB_SEARCH_DEEPSEEK_ENABLED=false` は検索を強制無効化します。`openmaic.yml` がある場合、旧変数はスロットを割り当てられません。プロバイダーを宣言し、`webSearch` と／または `webFetch` を明示的に割り当ててください。

The default API base is `https://api.deepseek.com/v1`. On `api.deepseek.com`, every base path (including `/beta`) is normalized to `/v1` before appending `/tools/search` or `/tools/fetch`. Custom gateway bases preserve their configured path prefix; a bare root gets `/v1` first. Custom endpoints belong in deployment configuration, while client and workspace overrides remain restricted to official endpoints. The default fetch reader remains `builtin`. See [DeepSeek official pricing](https://api-docs.deepseek.com/quick_start/pricing) for current request charges. Failed requests and searches with no results are not billed.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### Kimi の Web 検索

`kimi` プリセット（Moonshot Open Platform）と `kimi-coding-plan` プリセットは、同じ API キーとベース URL でチャットと Web 検索を提供します。`webSearch` をチャットと同じプロバイダーに割り当てれば、追加のキーや検索モデルは不要です。

Open Platform の `https://api.moonshot.cn/v1` と `https://api.moonshot.ai/v1` は `/tools/search_pro` を使用します。結果の本文はページの断片を連結し、本文がなければ要約を使用します。コーディングプランの `https://api.kimi.com/coding/v1` と `https://api.kimi.ai/coding/v1` は `/search` を使用し、ページの取得を有効にします。結果には要約よりもページ本文を優先します。1 回のリクエストで返す結果は最大 20 件です。

従来の設定では、チャットの認証情報だけで検索が有効になることはありません。`WEB_SEARCH_KIMI_ENABLED=true` を設定するか、`server-providers.yml` に `web-search.kimi` を明示的に追加してください。`openmaic.yml` では `webSearch` スロットを明示的に割り当てます。ウィザードが検索を推奨するのは、公式のベース URL を使用するアカウントだけです。

エンドポイントはベース URL のパスで決まります。末尾のスラッシュを除いたパスが `/coding/v1` で終わる場合は `/search`、それ以外は `/tools/search_pro` を使用します。`openmaic.yml` で設定するカスタムプロキシも、このパス構造を維持する必要があります。

`openmaic.yml` がある場合、従来の環境変数 `WEB_SEARCH_KIMI_ENABLED` だけでは検索スロットは割り当てられないため、`providers.<id>: { preset: kimi }` を宣言し、`slots.webSearch: <id>` を指定してください。

## Webページ取得

`webFetch` スロットの既定は、キー不要の `builtin`（Readability と Turndown。PDF は引き続き `document` を使用）です。`kimi` と `kimi-coding-plan` は、それぞれのプロバイダーのキーと API ベース URL をホスト型抽出に再利用します。Moonshot Open Platform は `/tools/fetch`、Coding Plan は `/fetch` を使用します。`firecrawl` は専用の Firecrawl キー（Firecrawl の Web 検索と共通）を使い、`/v2/scrape` を呼び出します。フォールバックはありません。モデルサービスやコースモデル設定でサービスを選ぶか、`openmaic.yml` で `slots.webFetch` を指定します。Kimi のキーはチャットと共有されます。すべてのサービスで、ローカルのセッション許可と公開アドレスの検査を行い、結果を信頼できないデータとして扱います。

DeepSeek は `deepseek` プリセットでホスト型 Markdown 抽出も提供し、チャットのキーと API ベースを共有します。上の例のように `webFetch` を明示的に割り当てます。`/v1/tools/fetch` を使い、デプロイで指定したゲートウェイのベースを保持します。タイムアウトと転送エラーのみ 1 回再試行する動作は Kimi と同じで、HTTP エラーや不正な応答は再試行しません。
