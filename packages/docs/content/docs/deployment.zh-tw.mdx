OpenMAIC 是一個標準的 Next.js 應用程式，任何能執行 Next.js 的環境都可以部署。

## Vercel（一鍵）

最快的方式是點選[儲存庫 README](https://github.com/THU-MAIC/OpenMAIC) 中的 Deploy 按鈕，fork 儲存庫，並依照提示填入至少一個 LLM 的 API key。

Vercel 會在每次提交後重新建置並部署 Next.js 應用程式。部署時需要在專案設定中設定至少一個 LLM 供應商。

Vercel 以 Serverless 函式執行 OpenMAIC，無法自帶資料庫。請在專案設定中把 `DATABASE_URL` 指向外部 PostgreSQL 資料庫（託管服務；有連線池端點時優先使用）；沒有它服務會拒絕啟動。

## Docker

儲存庫中提供適合正式環境的 `Dockerfile`。映像內部使用 Node.js 22，建置及執行方式如下：

```bash
docker build -t openmaic .

docker run --env-file .env.local -e DATABASE_URL=postgres://user:password@db-host:5432/openmaic -p 3000:3000 openmaic
```

建議使用儲存庫中的 Docker Compose 設定：

```bash
cp .env.example .env.local
# 編輯 .env.local，填入至少一個 LLM 供應商的設定，然後執行：
docker compose up --build
```

預設 Compose 部署會啟動 OpenMAIC 應用程式和 PostgreSQL 兩個容器，自動設定兩者之間的 `DATABASE_URL`，並掛載 `openmaic-data` 與 `openmaic-postgres` 資料卷。其他 provider 與功能可依需求設定，詳見[設定說明](./configuration.mdx)。

`NEXT_PUBLIC_*` 功能開關會在 Docker 建置時編譯至用戶端，不能只寫在執行時的 `.env.local` 中。例如啟用影片匯出和實驗性 PPTX 匯入：

```bash
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true \
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true \
docker compose --profile video-export up --build
```

其他用戶端功能開關也可以用相同方式傳入。若使用 `docker build`，請改用對應的 `--build-arg`。

如需使用伺服器端 provider 設定，把檔案掛載到容器內的固定路徑：

```yaml
services:
  openmaic:
    volumes:
      - ./server-providers.yml:/app/server-providers.yml:ro
```

Docker 容器中的 `localhost` 指向容器本身。若 Ollama、Lemonade、VoxCPM 或 ComfyUI 執行在主機上，請使用 `host.docker.internal`，例如 `http://host.docker.internal:11434/v1` 或 `http://host.docker.internal:8188`。Linux Docker 通常還需要為 `openmaic` 服務新增 `extra_hosts: ["host.docker.internal:host-gateway"]`。ComfyUI 目前不是伺服器端託管 provider，因此正式環境還必須設定 `ALLOW_LOCAL_NETWORKS=true`，否則 SSRF 防護會拒絕此位址。

## 自建 VM

主機需要 Node.js `22.19.0` 或更新版本，以及 pnpm `10.28.0`。使用 `pnpm` 建置並啟動：

```bash
pnpm install
pnpm build
DATABASE_URL=postgres://user:password@db-host:5432/openmaic pnpm start      # 預設監聽 3000 連接埠
```

可在前方使用 nginx 或 Caddy 終止 TLS。課程、執行階段資料和產生的媒體都儲存在 PostgreSQL 中，多個實例可以共用同一個資料庫。

## 伺服器端持久化（PostgreSQL）

OpenMAIC 把課程、對話紀錄、學習進度和產生的媒體儲存在 PostgreSQL 中，**必須提供 `DATABASE_URL`**：沒有它服務會輸出 `[boot] Invalid server configuration; the server will not start: DATABASE_URL is not set. ...` 及修復方法，並以結束碼 `1` 結束。持久化 HTTP API 內嵌在 OpenMAIC 中，不需要額外的 persistence 服務。

`docker compose up` 會在應用程式旁啟動 PostgreSQL 並為其設定 `DATABASE_URL`。本機開發時，`pnpm db:up` 以同一服務定義啟動一個獨立的開發資料庫（單獨的 Compose 專案與資料卷 `openmaic-dev-db`，本機所有檢出共用，不會影響該堆疊的資料庫），並發布到 `127.0.0.1`（連接埠 `OPENMAIC_DB_PORT`，預設 `5432`）；`pnpm db:down` 可將其停止。然後在 `.env.local` 中設定連線：

```bash
DATABASE_URL=postgres://openmaic:openmaic-dev@127.0.0.1:5432/openmaic
```

持久化不再有單獨的憑證：每個請求都歸屬於所有者解析得出的所有者（預設是每個瀏覽器一個的匿名 cookie），執行時工作階段和媒體按該所有者分區。預設身分只隔離瀏覽器、並不驗證任何人，面向真實使用者的部署應註冊基於自有帳號體系的所有者驗證方法。早期版本使用的 `PERSISTENCE_DEV_TOKEN` / `NEXT_PUBLIC_PERSISTENCE_TOKEN` 已移除並被忽略；以舊的瀏覽器自行產生學習者 key 儲存的執行時工作階段將無法再存取。如果 `PERSISTENCE_DEV_TOKEN` 曾是唯一的存取門檻，請在升級前以 `ACCESS_CODE` 或閘道保護部署，或註冊所有者驗證方法。

PostgreSQL 資料儲存在 `openmaic-postgres` volume 中。`PERSISTENCE_POSTGRES_PASSWORD` 只會在資料庫目錄首次初始化時設定密碼，之後修改環境變數不會自動修改已有資料庫使用者密碼。

早期版本可以把課程儲存在瀏覽器（IndexedDB）中。該模式已移除，`NEXT_PUBLIC_PERSISTENCE` 建置變數會被忽略。以這種方式儲存在瀏覽器中的課程會原樣保留在該瀏覽器裡，直到同一版本中發布的單向「瀏覽器到伺服器」匯入器把它們搬到伺服器。

## 選用：MP4 影片匯出

「匯出影片」功能會先在瀏覽器中生成完整的 Hyperframes 專案，再由獨立的 `render-service` 使用 Chromium 和 FFmpeg 渲染為 MP4。此服務為選用項目，不影響一般課堂生成。

啟用 `video-export` profile：

```bash
docker compose --profile video-export up --build
```

Compose 會透過 `RENDER_SERVICE_URL` 讓 OpenMAIC 連線至渲染服務。若未啟用此 profile，或渲染服務無法使用，匯出功能會改為下載專案 ZIP，以供本機 CLI 渲染。渲染服務使用隔離網路，啟動時需要 `NET_ADMIN` capability；其他限制與獨立部署方式請見儲存庫中的 [`render-service/README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/main/render-service/README.md)。
