本頁列出開源版 OpenMAIC 內建的供應商和模型。在 [`openmaic.yml`](./configuration.mdx) 中，供應商透過 `preset` 指定其中之一；Web 端的模型設定提供同一份目錄。實際可用性也取決於供應商帳號、所在地區和伺服器端設定，供應商的 `models` 清單也可以縮小模型設定中提供的選項。

## 範本

範本（preset）是內建的供應商樣板：哪家廠商、哪個端點，以及一個帳號涵蓋哪些能力。`openmaic.yml` 或模型設定中的每個供應商都要指定一個範本。

**單一能力範本**使用下方各表中的 provider ID，每種能力一個：`openai` 是 OpenAI 對話，OpenAI 的圖像、語音合成和語音辨識分別是 `openai-image`、`openai-tts` 和 `openai-whisper`。有三個 ID 因為已被其他範本占用而與 registry ID 不同：MiniMax 網路搜尋是 `minimax-search`，豆包網路搜尋是 `doubao-search`，Lemonade 圖像生成是 `lemonade-image`。

**Token Plan 範本**用一把 key 涵蓋多種能力，每種能力使用該方案自己的端點。在 **設定 → Token Plan** 中連接這類供應商時，也會為方案推薦了模型且仍未指派的插槽填入模型。

| 範本 | 方案 | 涵蓋能力 |
| --- | --- | --- |
| `minimax` | MiniMax | 對話、圖像、影片、TTS、網路搜尋 |
| `tokendance` | TokenDance | 對話、圖像、影片、TTS、網路搜尋 |
| `volcengine-ark` | 火山方舟 Agent Plan | 對話、圖像、影片、TTS、網路搜尋 |
| `kimi-coding-plan` | Kimi 程式設計方案 | 對話、網路搜尋、網頁擷取 |

在**設定 → Token Plan** 中連接 Kimi Coding Plan，會同時推薦對話、網路搜尋和網頁擷取，共用方案金鑰和 `https://api.kimi.com/coding/v1`。如果網頁擷取僅使用隱含的內建預設值，連接會直接指定 Kimi，不顯示衝突確認，即使選擇保留目前設定也是如此。工作區的明確選擇（包括 `null`）以及部署設定的非內建讀取器或 `null` 仍按現有衝突選項處理。中斷連接會移除方案的指定值，恢復伺服器預設值（未設定讀取器時為內建讀取器），不會恢復先前工作區的明確選擇。鎖定的欄位保持不變，未宣告網頁擷取的方案不會修改該欄位。

首次設定精靈會將網頁擷取保留為內建讀取器；只有透過 Token Plan 設定頁面連接方案，才會套用方案的擷取建議設定。

`openai-compatible` 用於連接任何 OpenAI 相容的對話服務：需要填寫 `baseUrl`，模型設定中提供的就是它的 `models` 清單。

### DeepSeek 網路搜尋與網頁擷取

`deepseek` 預設在對話、網路搜尋和託管 Markdown 擷取之間共用 `DEEPSEEK_API_KEY` 與 API 基底位址。搜尋使用 `POST /v1/tools/search`，最多傳回 50 筆結果，查詢依 Unicode code point 截斷至 128 個字元，優先使用 `summary`，空白時改用 `snippet`。擷取使用 `POST /v1/tools/fetch`，讀取 `content` 與非空的選填 `title`。

舊版設定需使用 `WEB_SEARCH_DEEPSEEK_ENABLED=true`，或在 `server-providers.yml` 明確加入 `web-search.deepseek`。僅設定對話憑證不會啟用搜尋或取代現有預設搜尋。`WEB_SEARCH_DEEPSEEK_ENABLED=false` 會強制停用搜尋。有 `openmaic.yml` 時，舊版變數無法指定插槽，必須明確宣告提供者並指定 `webSearch` 和／或 `webFetch`。

The default API base is `https://api.deepseek.com/v1`. On `api.deepseek.com`, every base path (including `/beta`) is normalized to `/v1` before appending `/tools/search` or `/tools/fetch`. Custom gateway bases preserve their configured path prefix; a bare root gets `/v1` first. Custom endpoints belong in deployment configuration, while client and workspace overrides remain restricted to official endpoints. The default fetch reader remains `builtin`. See [DeepSeek official pricing](https://api-docs.deepseek.com/zh-cn/quick_start/pricing) for current request charges. Failed requests and searches with no results are not billed.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### Kimi 網路搜尋

`kimi` 範本（Moonshot Open Platform）和 `kimi-coding-plan` 範本都支援使用同一個 API key 和 Base URL 進行對話與網路搜尋。將 `webSearch` 指向對話使用的同一供應商，不需要額外的金鑰或搜尋模型。

Open Platform 的 `https://api.moonshot.cn/v1` 和 `https://api.moonshot.ai/v1` 使用 `/tools/search_pro`，搜尋結果內文由頁面片段串接而成，沒有內文時改用摘要。程式設計方案的 `https://api.kimi.com/coding/v1` 和 `https://api.kimi.ai/coding/v1` 使用 `/search` 並啟用頁面擷取，優先使用頁面內文，其次使用摘要。每次請求最多傳回 20 筆結果。

在舊版設定中，僅設定對話金鑰不會啟用搜尋。請設定 `WEB_SEARCH_KIMI_ENABLED=true`，或在 `server-providers.yml` 中明確加入 `web-search.kimi`。使用 `openmaic.yml` 時，需要明確指定 `webSearch` 插槽。首次執行精靈僅為使用官方 Base URL 的帳戶建議搜尋。

端點依 Base URL 的路徑選擇：移除結尾斜線後，以 `/coding/v1` 結尾的路徑使用 `/search`，其他路徑使用 `/tools/search_pro`。在 `openmaic.yml` 中設定的自訂代理必須保留這個端點路徑結構。

存在 `openmaic.yml` 時，必須宣告 `providers.<id>: { preset: kimi }` 並指定 `slots.webSearch: <id>`；舊版環境變數 `WEB_SEARCH_KIMI_ENABLED` 無法為該插槽指定供應商。

## 網頁擷取

`webFetch` 插槽預設使用不需金鑰的 `builtin` 讀取服務（Readability 和 Turndown；PDF 仍使用 `document`）。`kimi` 和 `kimi-coding-plan` 都重用對應供應商的金鑰和 API 基底網址進行託管擷取。Moonshot 開放平台使用 `/tools/fetch`，Coding Plan 使用 `/fetch`。`firecrawl` 使用獨立的 Firecrawl 金鑰（與 Firecrawl 網路搜尋共用），呼叫 `/v2/scrape`。沒有備援服務。可在模型服務或課程模型設定中選擇讀取服務，也可在 `openmaic.yml` 中指定 `slots.webFetch`。Kimi 的金鑰與對話共用。所有讀取服務都保留本機工作階段授權、公開位址檢查和不可信結果邊界。

DeepSeek 也透過 `deepseek` 預設提供託管 Markdown 擷取，共用對話金鑰與 API 基底位址。依上述範例明確指定 `webFetch`，呼叫 `/v1/tools/fetch`，並保留部署中的閘道位址。逾時與僅對傳輸錯誤重試一次的行為與 Kimi 相同，不重試 HTTP 錯誤或無效回應。
