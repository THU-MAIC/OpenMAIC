本頁列出開源版 OpenMAIC 內建的供應商和模型。在 [`openmaic.yml`](./configuration.mdx) 中，供應商透過 `preset` 指定其中之一；Web 端的模型設定提供同一份目錄。實際可用性也取決於供應商帳號、所在地區和伺服器端設定，供應商的 `models` 清單也可以縮小模型設定中提供的選項。

## 範本

範本（preset）是內建的供應商樣板：哪家廠商、哪個端點，以及一個帳號涵蓋哪些能力。`openmaic.yml` 或模型設定中的每個供應商都要指定一個範本。

**單一能力範本**使用下方各表中的 provider ID，每種能力一個：`openai` 是 OpenAI 對話，OpenAI 的圖像、語音合成和語音辨識分別是 `openai-image`、`openai-tts` 和 `openai-whisper`。有三個 ID 因為已被其他範本占用而與 registry ID 不同：MiniMax 網路搜尋是 `minimax-search`，豆包網路搜尋是 `doubao-search`，Lemonade 圖像生成是 `lemonade-image`。

**Token Plan 範本**用一把 key 涵蓋多種能力，每種能力使用該方案自己的端點。首次使用引導連接這類供應商時，也會為方案推薦了模型的插槽填入模型。

| 範本 | 方案 | 涵蓋能力 |
| --- | --- | --- |
| `minimax` | MiniMax | 對話、圖像、影片、TTS、網路搜尋 |
| `tokendance` | TokenDance | 對話、圖像、影片、TTS、網路搜尋 |
| `volcengine-ark` | 火山方舟 Agent Plan | 對話、圖像、影片、TTS、網路搜尋 |
| `kimi-coding-plan` | Kimi 程式設計方案 | 對話 |

`openai-compatible` 用於連接任何 OpenAI 相容的對話服務：需要填寫 `baseUrl`，模型設定中提供的就是它的 `models` 清單。

全部範本 ID：

| 能力 | 範本 |
| --- | --- |
| 對話 | `openai`、`azure`、`atlascloud`、`anthropic`、`bedrock`、`google`、`glm`、`qwen`、`deepseek`、`kimi`、`siliconflow`、`doubao`、`openrouter`、`grok`、`tencent-hunyuan`、`xiaomi`、`ollama`、`lemonade`、`openai-compatible`，以及各 Token Plan |
| TTS | `openai-tts`、`azure-tts`、`glm-tts`、`qwen-tts`、`minimax-tts`、`voxcpm-tts`、`doubao-tts`、`elevenlabs-tts`、`browser-native-tts`、`lemonade-tts` |
| ASR | `openai-whisper`、`qwen-asr`、`azure-asr`、`browser-native`、`funasr-asr`、`lemonade-asr` |
| 圖像 | `seedream`、`openai-image`、`qwen-image`、`nano-banana`、`minimax-image`、`grok-image`、`comfyui-image`、`lemonade-image`、`openrouter-image` |

`azure`、`openai-compatible`、`searxng` 和 `mineru` 需要 `baseUrl`；`alidocmind` 使用 `credentials`（金鑰對）驗證。自架的 TTS、ASR、圖像、搜尋和文件範本、金鑰對範本以及 Bedrock 只能在 `openmaic.yml` 中設定，請見[設定說明](./configuration.mdx)。
