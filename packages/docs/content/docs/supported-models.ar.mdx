تسرد هذه الصفحة المزودين والنماذج المدمجة في نسخة OpenMAIC مفتوحة المصدر. في [`openmaic.yml`](./configuration.mdx) يسمّي المزود أحدها بوصفه `preset`، وتعرض إعدادات النماذج في تطبيق الويب الكتالوج نفسه. يعتمد التوفر أيضًا على حساب المزود والمنطقة وإعدادات الخادم، ويمكن لقائمة `models` الخاصة بالمزود أن تضيّق ما تعرضه إعدادات النماذج.

## الإعدادات المسبقة

الإعداد المسبق (preset) قالب مزود مدمج: أي مورّد، وأي عنوان، وأي قدرات يغطيها حساب واحد. كل مزود في `openmaic.yml` أو في إعدادات النماذج يسمّي إعدادًا مسبقًا.

**الإعدادات المسبقة ذات القدرة الواحدة** تستخدم معرّفات المزودين في الجداول أدناه، واحدًا لكل قدرة: `openai` هو محادثة OpenAI، أما صور OpenAI وتحويل النص إلى كلام والتفريغ الصوتي فهي `openai-image` و`openai-tts` و`openai-whisper`. تختلف ثلاثة معرّفات عن معرّف السجل لأن إعدادًا مسبقًا آخر يستخدمه: بحث MiniMax على الويب هو `minimax-search`، وبحث Doubao على الويب هو `doubao-search`، وتوليد صور Lemonade هو `lemonade-image`.

**إعدادات Token Plan المسبقة** تغطي عدة قدرات بمفتاح واحد، كل منها على عنوان الخطة الخاص. ربط أحدها في **الإعدادات ← Token Plan** يملأ أيضًا الخانات التي توصي الخطة بنماذج لها ولم تُعيّن بعد.

| الإعداد المسبق | الخطة | يغطي |
| --- | --- | --- |
| `minimax` | MiniMax | المحادثة والصور والفيديو وTTS والبحث على الويب |
| `tokendance` | TokenDance | المحادثة والصور والفيديو وTTS والبحث على الويب |
| `volcengine-ark` | Volcengine Ark Agent Plan | المحادثة والصور والفيديو وTTS والبحث على الويب |
| `kimi-coding-plan` | Kimi coding plan | المحادثة والبحث على الويب وجلب صفحات الويب |

يوصي ربط Kimi Coding Plan في **الإعدادات ← Token Plan** بالمحادثة والبحث على الويب وجلب الصفحات معًا، باستخدام مفتاح الخطة والعنوان `https://api.kimi.com/coding/v1`. إذا كان الجلب يستخدم القارئ المدمج الافتراضي الضمني فقط، فإن الربط يعيّن Kimi مباشرةً دون تأكيد تعارض، حتى عند الاحتفاظ بالإعدادات الحالية. تخضع اختيارات مساحة العمل الصريحة (بما فيها `null`) والقارئ غير المدمج أو `null` المحددان في إعداد النشر لخيارات التعارض الحالية. يزيل قطع الاتصال تعيينات الخطة ويعيد القيمة الافتراضية للخادم (القارئ المدمج عند عدم إعداد قارئ آخر)، ولا يعيد اختيارًا صريحًا سابقًا لمساحة العمل. تبقى الخانات المقفلة دون تغيير، ولا تغيّر الخطط التي لا تعلن جلب الصفحات هذه الخانة.

يُبقي معالج الإعداد الأولي جلب الصفحات على القارئ المدمج؛ ولا تُطبّق توصية الخطة للجلب إلا عند ربطها عبر صفحة إعدادات Token Plan.

يربط `openai-compatible` أي خادم محادثة متوافق مع OpenAI: يحتاج إلى `baseUrl`، وتعرض إعدادات النماذج قائمة `models` الخاصة به.

جميع معرّفات الإعدادات المسبقة:

| القدرة | الإعدادات المسبقة |

| TTS | `openai-tts` و`azure-tts` و`glm-tts` و`qwen-tts` و`minimax-tts` و`voxcpm-tts` و`doubao-tts` و`elevenlabs-tts` و`google-tts` و`browser-native-tts` و`lemonade-tts` |
| ASR | `openai-whisper` و`qwen-asr` و`azure-asr` و`browser-native` و`funasr-asr` و`lemonade-asr` |
| الصور | `seedream` و`openai-image` و`qwen-image` و`nano-banana` و`minimax-image` و`grok-image` و`comfyui-image` و`lemonade-image` و`openrouter-image` |

### البحث وجلب الصفحات باستخدام DeepSeek

يشترك الإعداد `deepseek` في `DEEPSEEK_API_KEY` وعنوان API الأساسي بين المحادثة والبحث واستخراج Markdown المستضاف. يستخدم البحث `POST /v1/tools/search` ويعيد حتى 50 نتيجة، ويقتطع الاستعلام إلى 128 نقطة ترميز Unicode. يستخدم `summary` ثم `snippet` عند فراغه. يستخدم الجلب `POST /v1/tools/fetch` ويقرأ `content` و`title` الاختياري غير الفارغ.

في الإعدادات القديمة، فعّل `WEB_SEARCH_DEEPSEEK_ENABLED=true` أو أضف `web-search.deepseek` صراحةً إلى `server-providers.yml`. بيانات اعتماد المحادثة وحدها لا تفعّل البحث ولا تستبدل مزود البحث الافتراضي الحالي. يعطّل `WEB_SEARCH_DEEPSEEK_ENABLED=false` البحث قسرًا. عند وجود `openmaic.yml` لا يستطيع المتغير القديم تعيين خانة؛ أعلن المزود وعيّن `webSearch` و/أو `webFetch` صراحةً.

The default API base is `https://api.deepseek.com/v1`. On `api.deepseek.com`, every base path (including `/beta`) is normalized to `/v1` before appending `/tools/search` or `/tools/fetch`. Custom gateway bases preserve their configured path prefix; a bare root gets `/v1` first. Custom endpoints belong in deployment configuration, while client and workspace overrides remain restricted to official endpoints. The default fetch reader remains `builtin`. See [DeepSeek official pricing](https://api-docs.deepseek.com/quick_start/pricing) for current request charges. Failed requests and searches with no results are not billed.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### بحث Kimi على الويب

يتيح الإعدادان المسبقان `kimi` (Moonshot Open Platform) و`kimi-coding-plan` المحادثة والبحث على الويب باستخدام مفتاح API وعنوان URL أساسي واحد. عيّن `webSearch` للمزود نفسه المستخدم للمحادثة؛ فلا حاجة إلى مفتاح إضافي أو نموذج بحث منفصل.

يستخدم عنوانا Open Platform الأساسيان `https://api.moonshot.cn/v1` و`https://api.moonshot.ai/v1` المسار `/tools/search_pro`. يُجمع نص النتيجة من مقاطع الصفحة، ويُستخدم الملخص عند غيابها. ويستخدم عنوانا خطة البرمجة `https://api.kimi.com/coding/v1` و`https://api.kimi.ai/coding/v1` المسار `/search` مع تفعيل جلب الصفحات. تكون الأولوية لنص الصفحة ثم للملخص. يعيد كل طلب 20 نتيجة كحد أقصى.

في الإعدادات القديمة، لا تؤدي بيانات اعتماد المحادثة وحدها إلى تفعيل البحث. اضبط `WEB_SEARCH_KIMI_ENABLED=true` أو أضف إدخال `web-search.kimi` صراحةً إلى `server-providers.yml`. وفي `openmaic.yml`، عيّن خانة `webSearch` صراحةً. لا يوصي معالج الإعداد بالبحث إلا للحسابات التي تستخدم عنوان URL أساسيًا رسميًا.

يُختار مسار الطلب وفق مسار عنوان URL الأساسي: بعد إزالة الشرطات المائلة النهائية، يُستخدم `/search` إذا انتهى المسار بـ `/coding/v1`، ويُستخدم `/tools/search_pro` في الحالات الأخرى. يجب أن تحافظ خدمات الوكيل المخصصة المضبوطة في `openmaic.yml` على بنية المسار هذه.

عند وجود `openmaic.yml`، يجب تعريف `providers.<id>: { preset: kimi }` وتعيين `slots.webSearch: <id>`؛ فمتغير الإعدادات القديمة `WEB_SEARCH_KIMI_ENABLED` لا يعيّن هذه الخانة.

## جلب صفحات الويب

تستخدم خانة `webFetch` افتراضيًا القارئ `builtin` دون مفتاح (Readability وTurndown؛ وتظل ملفات PDF تستخدم `document`). يعيد كل من `kimi` و`kimi-coding-plan` استخدام مفتاح مزوّده والعنوان الأساسي لواجهة API للاستخراج المستضاف. يستخدم Moonshot Open Platform المسار `/tools/fetch`، بينما يستخدم Coding Plan المسار `/fetch`. يستخدم `firecrawl` مفتاح Firecrawl خاصًا به، مشتركًا مع البحث على الويب عبر Firecrawl، ويستدعي `/v2/scrape`. لا توجد خدمة احتياطية. اختر القارئ في خدمات النماذج أو إعداد نماذج المقرر، أو اضبط `slots.webFetch` في `openmaic.yml`. مفتاح Kimi مشترك مع الدردشة. تحتفظ جميع الخدمات بفحوص الجلسة والعناوين العامة المحلية وتعيد بيانات غير موثوقة.

يوفر DeepSeek أيضًا استخراج Markdown المستضاف عبر الإعداد `deepseek` مع إعادة استخدام مفتاح المحادثة وعنوان API الأساسي. عيّن `webFetch` صراحةً كما في المثال أعلاه. يستخدم `/v1/tools/fetch` ويحفظ عنوان البوابة المضبوط في النشر. المهل الزمنية وإعادة المحاولة مرة واحدة لأخطاء النقل فقط مماثلة لـ Kimi، دون إعادة أخطاء HTTP أو الاستجابات غير الصالحة.
