This page lists the providers and models built into the open-source OpenMAIC edition. In [`openmaic.yml`](./configuration.mdx) a provider names one of these as its `preset`, and the model settings of the web app offer the same catalogue. Availability also depends on the provider account, region and server configuration, and a provider's `models` list can narrow what the model settings offer.

## Presets

A preset is a built-in provider template: which vendor, which endpoint, and which capabilities one account covers. Every provider in `openmaic.yml` or in the model settings names a preset.

**Single-capability presets** have the provider IDs of the tables below, one per capability: `openai` is OpenAI chat, while OpenAI images, speech and transcription are `openai-image`, `openai-tts` and `openai-whisper`. Three IDs differ from the registry ID because another preset already uses it: MiniMax web search is `minimax-search`, Doubao web search is `doubao-search`, and Lemonade image generation is `lemonade-image`.

**Token plan presets** cover several capabilities with one key, each at the plan's own endpoint. Connecting one in **Settings → Token Plan** also fills the slots the plan recommends models for that are still unassigned.

| Preset | Plan | Covers |
| --- | --- | --- |
| `minimax` | MiniMax | Chat, image, video, TTS, web search |
| `tokendance` | TokenDance | Chat, image, video, TTS, web search |
| `volcengine-ark` | Volcengine Ark Agent Plan | Chat, image, video, TTS, web search |
| `kimi-coding-plan` | Kimi Coding Plan | Chat, web search, web fetch |

Connecting Kimi Coding Plan in **Settings → Token Plan** recommends chat, web search and web fetch together, using the Coding Plan key and `https://api.kimi.com/coding/v1`. If web fetch only uses the implicit builtin default, connecting assigns Kimi directly without a conflict, even when keeping the current setup. Explicit workspace choices (including `null`) and deployment-configured non-builtin readers or `null` use the existing conflict choices. Disconnecting removes the plan's assignments and restores the server default (the builtin reader when no reader is configured); it does not restore a prior explicit workspace choice. Locked slots stay unchanged. Plans that do not declare web fetch leave it untouched.

The first-run wizard leaves web fetch on the builtin reader; only connecting the plan through the Token Plan settings page applies its fetch recommendation.

`openai-compatible` connects any OpenAI-compatible chat server: it needs a `baseUrl`, and its `models` list is what the model settings offer.

### DeepSeek web search and fetch

The `deepseek` preset shares `DEEPSEEK_API_KEY` and the API base across chat, web search and hosted Markdown extraction. Search uses `POST /v1/tools/search`, returns up to 50 results, truncates queries to 128 Unicode code points, and uses `summary` with `snippet` as a fallback. Fetch uses `POST /v1/tools/fetch` and reads `content` and an optional nonempty `title`.

In legacy configuration, opt in with `WEB_SEARCH_DEEPSEEK_ENABLED=true` or an explicit `web-search.deepseek` entry in `server-providers.yml`. Chat credentials alone never enable search or replace another search default. `WEB_SEARCH_DEEPSEEK_ENABLED=false` force-disables search. When `openmaic.yml` exists, the legacy variable cannot assign a slot: explicitly declare the provider and assign `webSearch` and/or `webFetch`.

The default API base is `https://api.deepseek.com/v1`. On `api.deepseek.com`, every base path (including `/beta`) is normalized to `/v1` before appending `/tools/search` or `/tools/fetch`. Custom gateway bases preserve their configured path prefix; a bare root gets `/v1` first. Custom endpoints belong in deployment configuration, while client and workspace overrides remain restricted to official endpoints. The default fetch reader remains `builtin`. See [DeepSeek official pricing](https://api-docs.deepseek.com/quick_start/pricing) for current request charges. Failed requests and searches with no results are not billed.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### Kimi web search

The `kimi` preset (Moonshot Open Platform) and `kimi-coding-plan` preset both serve chat and web search with one API key and base URL. Assign `webSearch` to the same provider used for chat; no second key or search model is needed.

Open Platform bases `https://api.moonshot.cn/v1` and `https://api.moonshot.ai/v1` use `/tools/search_pro`; result content joins page chunks, falling back to the snippet. Coding Plan bases `https://api.kimi.com/coding/v1` and `https://api.kimi.ai/coding/v1` use `/search` with page crawling enabled; result content prefers page content over the snippet. Each request returns at most 20 results.

Chat credentials alone do not enable search in legacy configuration. Opt in with `WEB_SEARCH_KIMI_ENABLED=true` or an explicit `web-search.kimi` entry in `server-providers.yml`. In `openmaic.yml`, explicitly assign the `webSearch` slot. The wizard recommends search only for official account bases.

Endpoint selection follows the base path: after removing trailing slashes, a path ending in `/coding/v1` uses `/search`; every other base uses `/tools/search_pro`. Custom proxies configured in `openmaic.yml` must preserve that path layout.

When `openmaic.yml` is present, declare `providers.<id>: { preset: kimi }` and assign `slots.webSearch: <id>`; the legacy `WEB_SEARCH_KIMI_ENABLED` variable cannot assign that slot.

## Web fetch

The `webFetch` slot defaults to the keyless `builtin` reader (Readability and Turndown; PDFs still use `document`). Both `kimi` and `kimi-coding-plan` reuse their provider's key and API base for hosted extraction. Moonshot Open Platform uses `/tools/fetch`, while Coding Plan uses `/fetch`. `firecrawl` uses its own Firecrawl key, shared with Firecrawl web search, and calls `/v2/scrape`. There is no fallback. Choose the reader in Model Services / Course Model Config or assign `slots.webFetch` in `openmaic.yml`. The Kimi key is shared with chat. All readers retain local session and public-address checks and untrusted results.

DeepSeek also offers hosted Markdown extraction through the `deepseek` preset, reusing the chat key and API base. Assign `webFetch` explicitly as shown above. It uses `/v1/tools/fetch`; an explicit deployment gateway base is preserved. It retains the same transport deadlines and single transport-error retry as Kimi, without retrying HTTP errors or invalid responses.
