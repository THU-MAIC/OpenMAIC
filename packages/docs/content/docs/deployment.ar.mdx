OpenMAIC هو تطبيق Next.js قياسي، حيث يمكن تشغيله في أي مكان يدعم Next.js.

## Vercel (بنقرة واحدة)

أسرع مسار. اضغط على زر النشر في [README المستودع](https://github.com/THU-MAIC/OpenMAIC)، قم بعمل fork للمستودع، واملأ مفتاح API لموفر LLM واحد على الأقل حسب التعليمات.

يعيد Vercel بناء تطبيق Next.js ونشره بعد كل commit. بعد النشر الأول افتح التطبيق واربط خدمة نماذج في إعدادات النماذج، أو اضبط المزودين عبر متغيرات البيئة في إعدادات المشروع ([المتغيرات القديمة](./configuration.mdx#الانتقال-من-الإعدادات-القديمة) ما زالت تعمل). لا يملك Vercel مجلد بيانات دائمًا، لذا اضبط `OPENMAIC_SECRET_KEY` في إعدادات المشروع قبل حفظ المفاتيح في إعدادات النماذج؛ راجع [الأسرار و OPENMAIC_SECRET_KEY](./configuration.mdx#الأسرار-و-openmaic_secret_key).

يشغّل Vercel تطبيق OpenMAIC كدوال بلا خادم (serverless) لا يمكنها استضافة قاعدة بيانات. عيّن `DATABASE_URL` في إعدادات المشروع إلى قاعدة بيانات PostgreSQL خارجية (خدمة مُدارة؛ ويُفضَّل عنوان الاتصال المجمّع إن توفر)؛ يرفض الخادم البدء بدونه.

## Docker

يحتوي المستودع على `Dockerfile` مناسب للإنتاج. يستخدم داخل الصورة Node.js 22، قم بالبناء والتشغيل:

```bash
docker build -t openmaic .

docker run --env-file .env.local -e DATABASE_URL=postgres://user:password@db-host:5432/openmaic -p 3000:3000 openmaic
```

يوصى باستخدام تكوين Docker Compose الموجود في المستودع:

```bash
cp .env.example .env.local
# عدّل .env.local (المفاتيح وخيارات الخادم)، ثم:
docker compose up --build
```

يبدأ نشر Compose الافتراضي حاويتين: تطبيق OpenMAIC وPostgreSQL، ويضبط `DATABASE_URL` بينهما، ويربط مجلدي البيانات `openmaic-data` و`openmaic-postgres`. يمكن تكوين مزودين ووظائف أخرى حسب الحاجة، راجع [شرح الإعدادات](./configuration.mdx).

تُضبط النماذج بإحدى طريقتين. في التثبيت الشخصي، شغّل الحزمة وافتح التطبيق واربط خدمة نماذج في إعدادات النماذج؛ تُحفظ الإعدادات في قاعدة البيانات. وفي النشر الذي تديره بالملفات، انسخ `openmaic.example.yml` إلى `openmaic.yml`، وأبقِ المفاتيح في `.env.local`، واربط الملف (انظر أدناه). راجع [الإعدادات](./configuration.mdx#النماذج-والمزودون).

تنشئ الصورة مجلد البيانات في وحدة التخزين بملكية مستخدم التشغيل، لذا تحفظ وحدات التخزين الجديدة الدروس وسجلات الاستخدام مباشرة. قد تكون وحدة التخزين التي أنشأتها صورة أقدم مملوكة لـ root، ما يجعل كل حفظ على الخادم يفشل بـ `EACCES` بينما يواصل التطبيق العمل كالمعتاد (لا تصل الدروس إلى القرص دون أن يلاحظ أحد؛ ويظهر في السجل `Failed to record usage ... EACCES: permission denied`). أصلح وحدة التخزين هذه مرة واحدة، ثم أعد تشغيل التطبيق:

```bash
docker exec -u root <container> chown -R 1001:1001 /app/data
```

تُحقن مفاتيح التكوين `NEXT_PUBLIC_*` أثناء بناء Docker، ولا يمكن الاعتماد فقط على `.env.local` وقت التشغيل. على سبيل المثال، لتمكين تصدير الفيديو واستيراد PPTX التجريبي:

```bash
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true \
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true \
docker compose --profile video-export up --build
```

يمكن تمرير مفاتيح وظائف العميل الأخرى بنفس الطريقة. إذا استخدمت `docker build`، فاستخدم `--build-arg` المقابلة.

لاستخدام `openmaic.yml` اربطه في مجلد عمل التطبيق، أو في أي مكان آخر مع ضبط `OPENMAIC_CONFIG` على مساره:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

لا تربط مسارًا غير موجود على المضيف: سينشئ Docker مجلدًا مكانه ويرفض الخادم البدء. مع `docker run` أضف `-v "$PWD/openmaic.yml:/app/openmaic.yml:ro"`. أعد تشغيل الحاوية بعد تعديل الملف. الملف `openmaic.yml` مدرج في `.dockerignore`، فلا يُضمَّن أبدًا في صورة تُبنى من المستودع: اربطه وقت التشغيل بدلًا من ذلك. عند عدم وجود `openmaic.yml` ما زال `server-providers.yml` القديم يُقرأ من `/app/server-providers.yml`.

داخل حاوية Docker يشير `localhost` إلى الحاوية نفسها. إذا كان Ollama أو Lemonade أو VoxCPM أو ComfyUI يعمل على المضيف، فاستخدم `host.docker.internal`، مثل `http://host.docker.internal:11434/v1` أو `http://host.docker.internal:8188`. وعادةً ما يتطلب Docker على Linux أيضًا إضافة `extra_hosts: ["host.docker.internal:host-gateway"]` إلى خدمة `openmaic`. المزودون المعلنون في `openmaic.yml` (أو عبر المتغيرات القديمة) يديرهم الخادم، لذا يمكن أن تكون عناوينهم على المضيف أو على شبكة خاصة دون `ALLOW_LOCAL_NETWORKS`. لا يهم هذا المتغير إلا للعناوين التي يكتبها المستخدم: عناوين URL الأساسية للمحادثة المضافة في **الإعدادات ← خدمات النماذج**، وحقول الطلب المهملة.

## الاستضافة الذاتية على جهاز افتراضي

يحتاج المضيف إلى Node.js `22.19.0` أو أحدث، وpnpm `10.28.0`. قم بالبناء والتشغيل باستخدام `pnpm`:

```bash
pnpm install
pnpm build
DATABASE_URL=postgres://user:password@db-host:5432/openmaic pnpm start      # يستمع على المنفذ 3000 افتراضياً
```

ضع nginx أو Caddy أمام التطبيق لإنهاء TLS. تُحفظ الدروس وبيانات التشغيل والوسائط المولّدة في PostgreSQL، لذا يمكن لعدة نسخ مشاركة قاعدة بيانات واحدة.

## التخزين الدائم على الخادم (PostgreSQL)

يحفظ OpenMAIC الدروس وسجل المحادثات وتقدم المتعلمين والوسائط المولّدة في PostgreSQL، لذلك **`DATABASE_URL` إلزامي**: بدونه يطبع الخادم `[boot] Invalid server configuration; the server will not start: DATABASE_URL is not set. ...` مع طريقة الإصلاح ويخرج برمز `1`. واجهة برمجة التطبيقات للتخزين الدائم مضمنة في OpenMAIC ولا تحتاج إلى خدمة تخزين منفصلة.

يبدأ `docker compose up` قاعدة PostgreSQL بجانب التطبيق ويضبط له `DATABASE_URL`. للتطوير المحلي، يبدأ `pnpm db:up` قاعدة بيانات تطوير منفصلة من تعريف الخدمة نفسه (مشروع Compose ومجلد بيانات خاصان، `openmaic-dev-db`، مشتركة بين كل النسخ على هذا الجهاز، دون المساس بقاعدة بيانات الحزمة) على `127.0.0.1` (المنفذ `OPENMAIC_DB_PORT`، افتراضياً `5432`)، ويوقفها `pnpm db:down`. ثم اضبط الاتصال في `.env.local`:

```bash
DATABASE_URL=postgres://openmaic:openmaic-dev@127.0.0.1:5432/openmaic
```

لا توجد بيانات اعتماد منفصلة للتخزين الدائم: يُنسب كل طلب إلى المالك الذي تحدده آلية تحديد المالك (افتراضياً ملف تعريف ارتباط مجهول لكل متصفح)، وتُقسَّم جلسات وقت التشغيل والوسائط حسب هذا المالك. الهوية الافتراضية تعزل المتصفحات لكنها لا تصادق أحداً، لذا ينبغي للنشر الذي يخدم مستخدمين حقيقيين تسجيل طرق مصادقة للمالك مبنية على حساباته الخاصة. تمت إزالة `PERSISTENCE_DEV_TOKEN` و`NEXT_PUBLIC_PERSISTENCE_TOKEN` من الإصدارات السابقة ويتم تجاهلهما، ولم تعد جلسات وقت التشغيل المخزنة بمفتاح المتعلم القديم الذي أنشأه المتصفح قابلة للوصول. إذا كان `PERSISTENCE_DEV_TOKEN` هو بوابة الوصول الوحيدة لديك، فاحمِ النشر باستخدام `ACCESS_CODE` أو بوابة، أو سجّل طرق مصادقة للمالك، قبل الترقية.

يتم حفظ بيانات PostgreSQL في مجلد `openmaic-postgres`. يتم تعيين كلمة مرور `PERSISTENCE_POSTGRES_PASSWORD` فقط عند التهيئة الأولى لقاعدة البيانات، ولا يتم تعديلها تلقائياً عند تغيير متغير البيئة لاحقاً.

ما لم يُضبط `OPENMAIC_SECRET_KEY`، تحتوي وحدة التخزين `openmaic-data` أيضًا على `instance-secret.key`، وهو سر المثيل المولَّد الذي يشفّر مفاتيح المزودين المحفوظة في إعدادات النماذج. انسخه احتياطيًا مع قاعدة البيانات: بدونه يجب إدخال المفاتيح المحفوظة من جديد. عند تشغيل عدة نسخ، أو من دون وحدة تخزين دائمة، أو على نظام ملفات للقراءة فقط، اضبط `OPENMAIC_SECRET_KEY` بدلًا من ذلك (القيمة نفسها في كل النسخ)؛ راجع [الأسرار و OPENMAIC_SECRET_KEY](./configuration.mdx#الأسرار-و-openmaic_secret_key).

كانت الإصدارات السابقة قادرة على حفظ الدروس في المتصفح (IndexedDB). أُزيل هذا الوضع، ويتم تجاهل متغير البناء `NEXT_PUBLIC_PERSISTENCE`. تنتقل الدروس المحفوظة بهذه الطريقة إلى الخادم تلقائيًا عندما يفتح ذلك المتصفح التطبيق المُحدَّث لأول مرة: ينسخها مستورد أحادي الاتجاه (مع المحادثات وتقدّم التعلّم والمجلدات والوسائط) إلى المالك الذي يحدده الخادم لذلك المتصفح، ويترك البيانات الأصلية في المتصفح دون تغيير. يجري الاستيراد مرة واحدة لكل متصفح: يربط الخادم المتصفح بأول مالك يفتح التطبيق المُحدَّث فيه، وينقل الضمّ هذا الربط إلى الحساب (مالك مجهول دُمج في حساب عند تسجيل الدخول)، ويرفض الخادم طلبات المستورد لأي مالك آخر. ولا يُستورد شيء لأي مالك آخر يستخدم المتصفح نفسه لاحقًا. لا يتطلب ذلك أي إجراء ولا تظهر أي واجهة، وتُسجَّل المشكلات في وحدة تحكم المتصفح بالبادئة `[legacy-browser-import]`.

## اختياري: تصدير فيديو MP4

تقوم ميزة "تصدير الفيديو" أولاً بإنشاء مشروع Hyperframes مستقل في المتصفح، ثم يستخدم خدمة `render-service` المستقلة Chromium وFFmpeg لتصيير MP4. هذه الخدمة اختيارية ولا تؤثر على إنشاء الدروس العادي.

لتفعيل ملف التعريف `video-export`:

```bash
docker compose --profile video-export up --build
```

يتيح Compose لـ OpenMAIC الاتصال بخدمة التصيير عبر `RENDER_SERVICE_URL`. إذا لم يتم تفعيل هذا الملف التعريفي أو كانت خدمة التصيير غير متاحة، يتحول التصدير إلى تنزيل مشروع ZIP للتصيير المحلي عبر CLI. تستخدم خدمة التصيير شبكة معزولة وتتطلب قدرة `NET_ADMIN` عند التشغيل؛ لمزيد من القيود وطرق النشر المستقلة، راجع [`render-service/README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/main/render-service/README.md).
