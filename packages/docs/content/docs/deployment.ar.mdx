OpenMAIC تطبيق Next.js يحتاج إلى عملية Node.js تعمل باستمرار وإلى PostgreSQL. يجري توليد المقررات على الخادم: يُحفظ كل توليد في قاعدة البيانات وينفّذه عامل داخل عملية الخادم، فيستمر بعد مغادرة المتصفح للصفحة، وإذا توقفت العملية تتسلّمه عملية أخرى (أو العملية نفسها بعد إعادة التشغيل) من آخر خطوة مكتملة. هناك طريقتان مدعومتان للنشر:

- **Docker Compose** (موصى به): التطبيق وPostgreSQL في حاويتين.
- **صورة Docker أو `pnpm start`** مع قاعدة PostgreSQL تديرها بنفسك.

بدءًا من 1.2.0 لم تعد المنصات بلا خادم (serverless) مثل Vercel مدعومة: الدالة التي تنتهي بانتهاء الطلب لا يمكنها تنفيذ توليد. راجع قسم «Vercel (حتى 1.1.x)» أدناه.

## Docker

يحتوي المستودع على `Dockerfile` مناسب للإنتاج. يستخدم داخل الصورة Node.js 22، قم بالبناء والتشغيل:

```bash
docker build -t openmaic .

docker run --env-file .env.local -e DATABASE_URL=postgres://user:password@db-host:5432/openmaic -v openmaic-data:/app/data -p 3000:3000 openmaic
```

يوصى باستخدام تكوين Docker Compose الموجود في المستودع:

```bash
cp .env.example .env.local
# عدّل .env.local (المفاتيح وخيارات الخادم)، ثم:
docker compose up --build
```

يبدأ نشر Compose الافتراضي حاويتين: تطبيق OpenMAIC وPostgreSQL، ويضبط `DATABASE_URL` بينهما، ويربط مجلدي البيانات `openmaic-data` و`openmaic-postgres`. يمكن تكوين مزودين ووظائف أخرى حسب الحاجة، راجع [شرح الإعدادات](./configuration.mdx).

تُضبط النماذج بإحدى طريقتين. في التثبيت الشخصي، شغّل الحزمة وافتح التطبيق واربط خدمة نماذج في إعدادات النماذج؛ تُحفظ الإعدادات في قاعدة البيانات. وفي النشر الذي تديره بالملفات، انسخ `openmaic.example.yml` إلى `openmaic.yml`، وأبقِ المفاتيح في `.env.local`، واربط الملف (انظر أدناه). راجع [الإعدادات](./configuration.mdx#النماذج-والمزودون).

تنشئ الصورة مجلد البيانات في وحدة التخزين بملكية مستخدم التشغيل، لذا تحفظ وحدات التخزين الجديدة الدروس وسجلات الاستخدام مباشرة. قد تكون وحدة التخزين التي أنشأتها صورة أقدم مملوكة لـ root، ما يجعل كل حفظ على الخادم يفشل بـ `EACCES` بينما يواصل التطبيق العمل كالمعتاد (لا تصل الدروس إلى القرص دون أن يلاحظ أحد؛ ويظهر في السجل `Failed to record usage ... EACCES: permission denied`). أصلح وحدة التخزين هذه مرة واحدة، ثم أعد تشغيل التطبيق:

```bash
docker exec -u root <container> chown -R 1001:1001 /app/data
```

تُحقن مفاتيح التكوين `NEXT_PUBLIC_*` أثناء بناء Docker، ولا يمكن الاعتماد فقط على `.env.local` وقت التشغيل. على سبيل المثال، لتمكين تصدير الفيديو واستيراد PPTX التجريبي:

```bash
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true \
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true \
docker compose --profile video-export up --build
```

يمكن تمرير مفاتيح وظائف العميل الأخرى بنفس الطريقة. إذا استخدمت `docker build`، فاستخدم `--build-arg` المقابلة.

لاستخدام `openmaic.yml` اربطه في مجلد عمل التطبيق، أو في أي مكان آخر مع ضبط `OPENMAIC_CONFIG` على مساره:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

لا تربط مسارًا غير موجود على المضيف: سينشئ Docker مجلدًا مكانه ويرفض الخادم البدء. مع `docker run` أضف `-v "$PWD/openmaic.yml:/app/openmaic.yml:ro"`. أعد تشغيل الحاوية بعد تعديل الملف. الملف `openmaic.yml` مدرج في `.dockerignore`، فلا يُضمَّن أبدًا في صورة تُبنى من المستودع: اربطه وقت التشغيل بدلًا من ذلك. عند عدم وجود `openmaic.yml` ما زال `server-providers.yml` القديم يُقرأ من `/app/server-providers.yml`.

داخل حاوية Docker يشير `localhost` إلى الحاوية نفسها. إذا كان Ollama أو Lemonade أو VoxCPM أو ComfyUI يعمل على المضيف، فاستخدم `host.docker.internal`، مثل `http://host.docker.internal:11434/v1` أو `http://host.docker.internal:8188`. وعادةً ما يتطلب Docker على Linux أيضًا إضافة `extra_hosts: ["host.docker.internal:host-gateway"]` إلى خدمة `openmaic`. المزودون المعلنون في `openmaic.yml` (أو عبر المتغيرات القديمة) يديرهم الخادم، لذا يمكن أن تكون عناوينهم على المضيف أو على شبكة خاصة دون `ALLOW_LOCAL_NETWORKS`. لا يهم هذا المتغير إلا للعناوين التي يكتبها المستخدم: عناوين URL الأساسية للمحادثة المضافة في **الإعدادات ← خدمات النماذج**، وحقول الطلب المهملة.

## الاستضافة الذاتية على جهاز افتراضي

يحتاج المضيف إلى Node.js `22.19.0` أو أحدث، وpnpm `10.28.0`. قم بالبناء والتشغيل باستخدام `pnpm`:

```bash
pnpm install
pnpm build
DATABASE_URL=postgres://user:password@db-host:5432/openmaic pnpm start      # يستمع على المنفذ 3000 افتراضياً
```

شغّل التطبيق تحت مدير عمليات (systemd أو pm2 أو حاوية) يبقيه قيد التشغيل ويعيد تشغيله، وضع nginx أو Caddy أمام التطبيق لإنهاء TLS. تُحفظ المقررات ووسائطها المولّدة في PostgreSQL (أو S3)، لذا يمكن لعدة نسخ مشاركة قاعدة بيانات واحدة، بشرط أن تتشارك أيضًا مجلد البيانات والقيمة نفسها لـ `OPENMAIC_SECRET_KEY` (انظر أدناه).

يشغّل `pnpm start` الأمر `next start`، الذي يحذّر من أنه لا يعمل مع الإعداد `output: standalone`. هذا التحذير غير ضار: يقدّم `next start` البناء كاملًا من `.next`. أما صورة Docker فتشغّل الخادم المستقل (`node server.js`)، لكن هذا الخادم يغيّر مجلد العمل إلى مجلده الخاص، لذا استمر على الجهاز الافتراضي في استخدام `pnpm start`، الذي يقرأ `data/` و`openmaic.yml` من المجلد الذي يبدأ فيه.

## الإعدادات المطلوبة

| الإعداد | Docker Compose | صورة Docker أو `pnpm start` |
| --- | --- | --- |
| `DATABASE_URL` | مضبوط على PostgreSQL المرفقة | مطلوب؛ بدونه يخرج الخادم عند البدء |
| وضع الهوية | مستخدم واحد (`OWNER_SINGLE_USER=true` في `docker-compose.defaults.env`) | إن لم يُضبط، يكون كل متصفح مالكًا مجهولًا مستقلًا |
| `OPENMAIC_SECRET_KEY` | اختياري: يُحفظ السر المولَّد في وحدة التخزين `openmaic-data` | مطلوب لعدة نسخ، أو عند عدم وجود مجلد `data/` دائم |
| مجلد البيانات | وحدة التخزين `openmaic-data` على `/app/data` | مجلد `data/` دائم في مجلد العمل، تتشاركه كل النسخ |
| النماذج | `openmaic.yml` أو **الإعدادات ← النماذج** | كذلك |

**وضع الهوية** يحدد مالك المقرر. إن لم يُضبط، يكون كل متصفح مالكًا مجهولًا مستقلًا، ويرى متصفح آخر مكتبة فارغة. للتثبيت الشخصي اضبط `OWNER_SINGLE_USER=true`، ولفريق واحد يتشارك مكتبة واحدة اضبط `PERSISTENCE_SHARED_OWNER_ID` مع `ACCESS_CODE`، وللحسابات الحقيقية سجّل طرق مصادقة المالكين. راجع [Owner identity](./hosting.mdx#owner-identity) و`.env.example`.

في الوضع المجهول يحمل ملف تعريف الارتباط الخاص بالمالك العلامة `Secure` في بيئة الإنتاج، وكذلك ملف تعريف الارتباط الخاص بـ `ACCESS_CODE`. لا تحفظ المتصفحات ملف تعريف ارتباط `Secure` إلا عبر HTTPS أو على `http://localhost` (ولا يحفظه Safari حتى هناك)، لذا يجب على النشر الذي يُقدَّم عبر HTTP العادي ضبط `COOKIE_SECURE=0` (القيمة `0` تمامًا): وإلا يصبح كل طلب مالكًا جديدًا، وتفشل عمليات الكتابة بـ `403`، ويُطلب رمز الوصول مرة أخرى. بدون TLS تنتقل ملفات تعريف الارتباط نصًا واضحًا، فلا تفعل ذلك إلا على شبكة موثوقة.

يشفّر **`OPENMAIC_SECRET_KEY`** مفاتيح المزودين المحفوظة في إعدادات النماذج. بدونه تنشئ كل نسخة سرّها الخاص في `data/instance-secret.key`، فلا تستطيع النسخ التي تتشارك قاعدة البيانات قراءة المفاتيح التي حفظتها نسخة أخرى. احفظه مع نسخ قاعدة البيانات الاحتياطية؛ راجع [الأسرار و OPENMAIC_SECRET_KEY](./configuration.mdx#الأسرار-و-openmaic_secret_key).

تحتاج **عدة نسخ** تتشارك قاعدة بيانات أيضًا إلى مجلد بيانات دائم مشترك واحد (`data/` في مجلد العمل، و`/app/data` في الصورة؛ مثل وحدة التخزين نفسها أو نظام ملفات شبكي على كل نسخة). تُحفظ مستندات المقررات ووسائطها المولّدة في PostgreSQL (أو في S3 مع `ASSET_S3_BUCKET`)، لكن كل عملية تحتفظ بهذه الملفات في مجلد بياناتها: ملفات المواد المرفوعة ونتائج استخراجها، والسرد ووسائط المواد للمقررات التي يحررها الوكيل (`data/classrooms` أو `OPENMAIC_CLASSROOMS_DIR`)، وسجلات الاستخدام (`data/usage`)، والسر المولَّد للنسخة. عملية التوليد التي تتسلّمها نسخة أخرى تقرأ المواد المرفوعة من هناك.

## عمليات التوليد

تشغّل كل عملية خادم عاملًا للتوليد، ولا يعتمد ذلك على `OPENMAIC_AGENT_RUNTIME_ENABLED`. تضبطه هذه المتغيرات (أعداد صحيحة موجبة):

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `OPENMAIC_MAX_ACTIVE_RUNS_PER_OWNER` | `2` | عدد عمليات التوليد التي يمكن لمالك واحد أن يجريها في وقت واحد. لا تُحتسب عملية تنتظر تأكيد المخطط أو متوقفة عند خطوة فاشلة. عند تجاوز الحد يُرجع البدء أو تأكيد المخطط أو إعادة المحاولة `429 ACTIVE_RUN_LIMIT`. |
| `OPENMAIC_MAX_WAITING_RUNS_PER_OWNER` | `10` | عدد عمليات التوليد التي يمكن أن تنتظر تأكيد المخطط لمالك واحد في وقت واحد. |
| `OPENMAIC_GENERATION_RUN_MAX_CONCURRENT` | `4` | عدد عمليات التوليد التي تنفّذها عملية خادم واحدة في وقت واحد. |
| `OPENMAIC_GENERATION_RUN_STREAMS_PER_OWNER` | `16` | عدد تدفقات أحداث التوليد التي يمكن لمالك واحد إبقاؤها مفتوحة على عملية واحدة. |
| `OPENMAIC_GENERATION_RUN_RETENTION_HOURS` | `24` | عدد الساعات التي تحتفظ فيها عملية توليد منتهية بسجل أحداثها الكامل قبل ضغطه. |

تتشارك عمليات التوليد إعدادات التأجير مع بيئة تشغيل الوكيل (`OPENMAIC_AGENT_RUNTIME_SCAN_INTERVAL_MS` و`_HEARTBEAT_MS` و`_LEASE_TTL_MS` و`_MAX_ATTEMPTS`؛ راجع `.env.example`). عند إيقاف الخادم تُركن عمليات التوليد الجارية فيه، وتتابعها نسخة أخرى أو النسخة نفسها عند بدئها من جديد.

## التخزين الدائم على الخادم (PostgreSQL)

يحفظ OpenMAIC الدروس وسجل المحادثات وتقدم المتعلمين والوسائط المولّدة في PostgreSQL، لذلك **`DATABASE_URL` إلزامي**: بدونه يطبع الخادم `[boot] Invalid server configuration; the server will not start: DATABASE_URL is not set. ...` مع طريقة الإصلاح ويخرج برمز `1`. واجهة برمجة التطبيقات للتخزين الدائم مضمنة في OpenMAIC ولا تحتاج إلى خدمة تخزين منفصلة.

يبدأ `docker compose up` قاعدة PostgreSQL بجانب التطبيق ويضبط له `DATABASE_URL`. للتطوير المحلي، يبدأ `pnpm db:up` قاعدة بيانات تطوير منفصلة من تعريف الخدمة نفسه (مشروع Compose ومجلد بيانات خاصان، `openmaic-dev-db`، مشتركة بين كل النسخ على هذا الجهاز، دون المساس بقاعدة بيانات الحزمة) على `127.0.0.1` (المنفذ `OPENMAIC_DB_PORT`، افتراضياً `5432`)، ويوقفها `pnpm db:down`. ثم اضبط الاتصال في `.env.local`:

```bash
DATABASE_URL=postgres://openmaic:openmaic-dev@127.0.0.1:5432/openmaic
```

لا توجد بيانات اعتماد منفصلة للتخزين الدائم: يُنسب كل طلب إلى المالك الذي تحدده آلية تحديد المالك (افتراضياً ملف تعريف ارتباط مجهول لكل متصفح)، وتُقسَّم جلسات وقت التشغيل والوسائط حسب هذا المالك. الهوية الافتراضية تعزل المتصفحات لكنها لا تصادق أحداً، لذا ينبغي للنشر الذي يخدم مستخدمين حقيقيين تسجيل طرق مصادقة للمالك مبنية على حساباته الخاصة. تمت إزالة `PERSISTENCE_DEV_TOKEN` و`NEXT_PUBLIC_PERSISTENCE_TOKEN` من الإصدارات السابقة ويتم تجاهلهما، ولم تعد جلسات وقت التشغيل المخزنة بمفتاح المتعلم القديم الذي أنشأه المتصفح قابلة للوصول. إذا كان `PERSISTENCE_DEV_TOKEN` هو بوابة الوصول الوحيدة لديك، فاحمِ النشر باستخدام `ACCESS_CODE` أو بوابة، أو سجّل طرق مصادقة للمالك، قبل الترقية.

يتم حفظ بيانات PostgreSQL في مجلد `openmaic-postgres`. يتم تعيين كلمة مرور `PERSISTENCE_POSTGRES_PASSWORD` فقط عند التهيئة الأولى لقاعدة البيانات، ولا يتم تعديلها تلقائياً عند تغيير متغير البيئة لاحقاً.

ما لم يُضبط `OPENMAIC_SECRET_KEY`، تحتوي وحدة التخزين `openmaic-data` أيضًا على `instance-secret.key`، وهو سر المثيل المولَّد الذي يشفّر مفاتيح المزودين المحفوظة في إعدادات النماذج. انسخه احتياطيًا مع قاعدة البيانات: بدونه يجب إدخال المفاتيح المحفوظة من جديد. عند تشغيل عدة نسخ، أو من دون وحدة تخزين دائمة، أو على نظام ملفات للقراءة فقط، اضبط `OPENMAIC_SECRET_KEY` بدلًا من ذلك (القيمة نفسها في كل النسخ)؛ راجع [الأسرار و OPENMAIC_SECRET_KEY](./configuration.mdx#الأسرار-و-openmaic_secret_key).

كانت الإصدارات السابقة قادرة على حفظ الدروس في المتصفح (IndexedDB). أُزيل هذا الوضع، ويتم تجاهل متغير البناء `NEXT_PUBLIC_PERSISTENCE`. تنتقل الدروس المحفوظة بهذه الطريقة إلى الخادم تلقائيًا عندما يفتح ذلك المتصفح التطبيق المُحدَّث لأول مرة: ينسخها مستورد أحادي الاتجاه (مع المحادثات وتقدّم التعلّم والمجلدات والوسائط) إلى المالك الذي يحدده الخادم لذلك المتصفح، ويترك البيانات الأصلية في المتصفح دون تغيير. يجري الاستيراد مرة واحدة لكل متصفح: يربط الخادم المتصفح بأول مالك يفتح التطبيق المُحدَّث فيه، وينقل الضمّ هذا الربط إلى الحساب (مالك مجهول دُمج في حساب عند تسجيل الدخول)، ويرفض الخادم طلبات المستورد لأي مالك آخر. ولا يُستورد شيء لأي مالك آخر يستخدم المتصفح نفسه لاحقًا. لا يتطلب ذلك أي إجراء ولا تظهر أي واجهة، وتُسجَّل المشكلات في وحدة تحكم المتصفح بالبادئة `[legacy-browser-import]`.

## الترقية من 1.1.x

| النشر | ما يجب فعله |
| --- | --- |
| `docker compose` | اسحب الإصدار الجديد وشغّل `docker compose up --build`. انقل إعدادات النماذج إلى `openmaic.yml` أو **الإعدادات ← النماذج** (تبقى متغيرات المزودين صالحة ما دام لا يوجد `openmaic.yml`)، وأعد كتابة `MODEL_ROUTES` على شكل خانات: يرفض الخادم البدء إذا ضُبط دون `openmaic.yml`. افتح التطبيق مرة واحدة في كل متصفح يحتوي على مقررات محلية لاستيرادها. إذا كان `.env.local` يضبط `PERSISTENCE_SHARED_OWNER_ID` فاضبط أيضًا `OWNER_SINGLE_USER=false`: يبدأ Compose الآن في وضع المستخدم الواحد. لا تُدمج مقررات المالكين المجهولين من نشر سابق على الخادم في المستخدم الواحد تلقائيًا؛ استعدها عبر `POST /api/identity/claim` من كل متصفح أنشأها (فتح المتصفح يستورد فقط ما احتفظ به محليًا). |
| `pnpm start` مع PostgreSQL خاصة بك | أوقف الخادم، واجلب الإصدار الجديد، وشغّل `pnpm install` و`pnpm build`، ثم أعد التشغيل بـ `pnpm start` في مجلد العمل نفسه ليحتفظ بـ `data/`. اضبط `DATABASE_URL` ووضع الهوية، و`OPENMAIC_SECRET_KEY` عندما تتشارك عدة نسخ قاعدة البيانات؛ وتحتاج النسخ المتعددة أيضًا إلى مجلد بيانات مشترك واحد (راجع [الإعدادات المطلوبة](#الإعدادات-المطلوبة)). إعدادات النماذج و`MODEL_ROUTES` ومقررات المتصفح كما في الصف السابق. |
| Vercel | ابقَ على 1.1.x، أو انتقل إلى مضيف يعمل باستمرار بقاعدة البيانات نفسها (انظر أدناه). |
| Skill / API | اتبع مهارة `openmaic` المحدّثة: ارفع المواد وأرسل الطلب واستعلم عن الحالة بصفة المالك نفسه. |

قبل التشغيل الأول للإصدار 1.2.0:

- **احتفظ بمجلد البيانات.** شغّل 1.2.0 مع مجلد `data/` نفسه في مجلد العمل (أو `OPENMAIC_CLASSROOMS_DIR` نفسه)، ومع وحدة التخزين `openmaic-data` نفسها في Compose. الفصول التي حفظها 1.1.x ملفاتٍ في `data/classrooms` تُستورد إلى قاعدة البيانات مرة واحدة في الخلفية بعد التشغيل؛ والخادم الذي يبدأ دون هذا المجلد لا يجد ما يستورده.
- **اضبط وضع الهوية أولًا.** يمنح الاستيراد تلك الفصول للمالك المضبوط عند ذلك التشغيل: المستخدم الواحد (`OWNER_SINGLE_USER=true`) أو مالك الفريق المشترك (`PERSISTENCE_SHARED_OWNER_ID`)، وإلا (الوضع المجهول) فالمالك المخصص `system:legacy-classrooms`، وعندها تُفتح للقراءة فقط من روابطها القديمة ولا تظهر في أي مكتبة. يُستورد كل فصل مرة واحدة فقط، لذا تبقى الفصول المستوردة في الوضع المجهول لدى `system:legacy-classrooms` حتى لو ضبطت وضع هوية لاحقًا.

تُستورد بيانات المتصفح (المقررات وإعدادات النماذج والوكلاء المخصصون) مرة واحدة عندما يفتح كل متصفح التطبيق المحدّث لأول مرة. راجع [الإعدادات](./configuration.mdx#الانتقال-من-الإعدادات-القديمة) لنقل إعدادات النماذج، و[CHANGELOG](https://github.com/THU-MAIC/OpenMAIC/blob/main/CHANGELOG.md) للقائمة الكاملة للتغييرات الكاسرة.

## Vercel (حتى 1.1.x)

النشر بلا خادم مدعوم حتى OpenMAIC 1.1.x، وزر Deploy في [README المستودع](https://github.com/THU-MAIC/OpenMAIC#vercel-deployment-up-to-11x) ينشر الفرع `release/1.1.x`. يمكن نقل مثل هذا النشر لاحقًا إلى مضيف يعمل باستمرار دون فقدان البيانات: وجّه `DATABASE_URL` في المضيف الجديد إلى قاعدة البيانات التي كان يستخدمها (إن وُجدت)، وقدّمه على العنوان نفسه؛ فالمتصفحات تحفظ بياناتها لكل موقع، وتُستورد مقررات الزوار عندما يفتح كل متصفح التطبيق المحدّث لأول مرة.

## اختياري: تصدير فيديو MP4

تقوم ميزة "تصدير الفيديو" أولاً بإنشاء مشروع Hyperframes مستقل في المتصفح، ثم يستخدم خدمة `render-service` المستقلة Chromium وFFmpeg لتصيير MP4. هذه الخدمة اختيارية ولا تؤثر على إنشاء الدروس العادي.

لتفعيل ملف التعريف `video-export`:

```bash
docker compose --profile video-export up --build
```

يتيح Compose لـ OpenMAIC الاتصال بخدمة التصيير عبر `RENDER_SERVICE_URL`. إذا لم يتم تفعيل هذا الملف التعريفي أو كانت خدمة التصيير غير متاحة، يتحول التصدير إلى تنزيل مشروع ZIP للتصيير المحلي عبر CLI. تستخدم خدمة التصيير شبكة معزولة وتتطلب قدرة `NET_ADMIN` عند التشغيل؛ لمزيد من القيود وطرق النشر المستقلة، راجع [`render-service/README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/main/render-service/README.md).
