OpenMAIC — приложение Next.js, которому нужны постоянно работающий процесс Node.js и PostgreSQL. Генерация курсов выполняется на сервере: каждая генерация хранится в базе данных и выполняется воркером внутри серверного процесса. Она продолжается, когда браузер уходит со страницы, а если процесс завершился, её подхватывает другой процесс (или тот же после перезапуска) с последнего завершённого шага. Поддерживаются два варианта развертывания:

- **Docker Compose** (рекомендуется): приложение и PostgreSQL в двух контейнерах.
- **Образ Docker или `pnpm start`** с собственной базой PostgreSQL.

Начиная с 1.2.0 serverless-платформы, такие как Vercel, не поддерживаются: функция, которая завершается вместе с запросом, не может выполнить генерацию. См. раздел «Vercel (до 1.1.x)» ниже.

## Docker

В репозитории есть production-ready `Dockerfile`. В образе используется Node.js 22. Соберите и запустите:

```bash
docker build -t openmaic .

docker run --env-file .env.local -e DATABASE_URL=postgres://user:password@db-host:5432/openmaic -v openmaic-data:/app/data -p 3000:3000 openmaic
```

Рекомендуется использовать Docker Compose из репозитория:

```bash
cp .env.example .env.local
# Отредактируйте .env.local (ключи и серверные опции), затем:
docker compose up --build
```

По умолчанию Compose запускает два контейнера, OpenMAIC и PostgreSQL, настраивает между ними `DATABASE_URL` и монтирует volumes `openmaic-data` и `openmaic-postgres`. Другие провайдеры и функции настраиваются по необходимости, подробности в [Конфигурации](./configuration.mdx).

Модели настраиваются одним из двух способов. Для личной установки запустите стек, откройте приложение и подключите сервис моделей в настройках моделей; конфигурация сохраняется в базе данных. Для развёртывания, которым вы управляете файлами, скопируйте `openmaic.example.yml` в `openmaic.yml`, храните ключи в `.env.local` и смонтируйте файл (см. ниже). Подробнее в [Конфигурации](./configuration.mdx#модели-и-провайдеры).

Образ создаёт каталог данных в томе от имени пользователя, под которым работает приложение, поэтому новые тома сразу сохраняют занятия и записи об использовании. Том, созданный старым образом, может принадлежать root: тогда каждое сохранение на сервере завершается ошибкой `EACCES`, хотя приложение продолжает работать (занятия незаметно не попадают на диск; в журнале видно `Failed to record usage ... EACCES: permission denied`). Исправьте такой том один раз и перезапустите приложение:

```bash
docker exec -u root <container> chown -R 1001:1001 /app/data
```

Флаги `NEXT_PUBLIC_*` внедряются во время сборки Docker, их нельзя просто указать в `.env.local` при запуске. Например, чтобы включить экспорт видео и экспериментальный импорт PPTX:

```bash
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true \
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true \
docker compose --profile video-export up --build
```

Другие клиентские флаги можно передавать аналогично. При использовании `docker build` применяйте соответствующие `--build-arg`.

Чтобы использовать `openmaic.yml`, смонтируйте его в рабочий каталог приложения или в любое другое место, указав путь в `OPENMAIC_CONFIG`:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

Не монтируйте путь, которого нет на хосте: Docker создаст на его месте каталог, и сервер откажется запускаться. Для `docker run` добавьте `-v "$PWD/openmaic.yml:/app/openmaic.yml:ro"`. После изменения файла перезапустите контейнер. `openmaic.yml` указан в `.dockerignore`, поэтому никогда не попадает в образ, собранный из репозитория: монтируйте его при запуске. Если `openmaic.yml` нет, устаревший `server-providers.yml` по-прежнему читается из `/app/server-providers.yml`.

Внутри Docker-контейнера `localhost` указывает на сам контейнер. Если Ollama, Lemonade, VoxCPM или ComfyUI запущены на хосте, используйте `host.docker.internal`, например `http://host.docker.internal:11434/v1` или `http://host.docker.internal:8188`. В Linux Docker обычно также нужно добавить `extra_hosts: ["host.docker.internal:host-gateway"]` сервису `openmaic`. Провайдеры, объявленные в `openmaic.yml` (или через устаревшие переменные), управляются сервером, поэтому их адреса могут находиться на хосте или в частной сети без `ALLOW_LOCAL_NETWORKS`. Эта переменная важна только для адресов, которые вводит пользователь: базовых URL чата, добавленных в **Настройки → Сервисы моделей**, и устаревших полей запроса.

## Самостоятельный хостинг на виртуальной машине

Требуется Node.js версии не ниже `22.19.0` и pnpm `10.28.0`. Соберите и запустите через `pnpm`:

```bash
pnpm install
pnpm build
DATABASE_URL=postgres://user:password@db-host:5432/openmaic pnpm start      # по умолчанию слушает порт 3000
```

Запускайте приложение под менеджером процессов (systemd, pm2, контейнер), который держит его запущенным и перезапускает, и поставьте nginx или Caddy для TLS termination перед приложением. Курсы и сгенерированные медиа курсов хранятся в PostgreSQL (или S3), поэтому несколько экземпляров могут использовать одну базу, если у них также общий каталог данных и одинаковый `OPENMAIC_SECRET_KEY` (см. ниже).

`pnpm start` запускает `next start`, который предупреждает, что не работает с настройкой `output: standalone`. Это предупреждение безвредно: `next start` полностью обслуживает сборку из `.next`. Образ Docker вместо этого запускает standalone-сервер (`node server.js`), но этот сервер меняет рабочий каталог на собственную папку, поэтому на виртуальной машине используйте `pnpm start`: он читает `data/` и `openmaic.yml` из каталога, в котором запущен.

## Обязательная конфигурация

| Параметр | Docker Compose | Образ Docker или `pnpm start` |
| --- | --- | --- |
| `DATABASE_URL` | указывает на встроенный PostgreSQL | обязателен; без него сервер завершается при запуске |
| Режим идентификации | один пользователь (`OWNER_SINGLE_USER=true` в `docker-compose.defaults.env`) | если не задан, каждый браузер — отдельный анонимный владелец |
| `OPENMAIC_SECRET_KEY` | необязателен: созданный секрет хранится в томе `openmaic-data` | обязателен для нескольких экземпляров или без постоянного каталога `data/` |
| Каталог данных | том `openmaic-data`, смонтированный в `/app/data` | постоянный каталог `data/` в рабочем каталоге, общий для всех экземпляров |
| Модели | `openmaic.yml` или **Настройки → Модели** | так же |

**Режим идентификации** определяет, кому принадлежит курс. Если он не задан, каждый браузер — отдельный анонимный владелец, и в другом браузере библиотека пуста. Для личной установки задайте `OWNER_SINGLE_USER=true`, для одной команды с общей библиотекой — `PERSISTENCE_SHARED_OWNER_ID` вместе с `ACCESS_CODE`, а для настоящих учётных записей зарегистрируйте методы аутентификации владельцев. Подробнее — в разделе [Owner identity](./hosting.mdx#owner-identity) и в `.env.example`.

В анонимном режиме cookie владельца в production помечается `Secure`, как и cookie `ACCESS_CODE`. Браузеры сохраняют `Secure` cookie только по HTTPS или на `http://localhost` (Safari — даже не там), поэтому развёртывание, доступное по обычному HTTP, должно задать `COOKIE_SECURE=0` (ровно `0`): иначе каждый запрос становится новым владельцем, записи завершаются ошибкой `403`, а код доступа запрашивается снова. Без TLS cookie передаются открытым текстом, поэтому делайте так только в доверенной сети.

**`OPENMAIC_SECRET_KEY`** шифрует ключи провайдеров, сохранённые в настройках моделей. Без него каждый экземпляр создаёт собственный секрет в `data/instance-secret.key`, и экземпляры с общей базой не могут прочитать ключи, сохранённые друг другом. Храните его вместе с резервными копиями базы; см. [Секреты и OPENMAIC_SECRET_KEY](./configuration.mdx#секреты-и-openmaic_secret_key).

**Нескольким экземплярам** с общей базой нужен и один общий постоянный каталог данных (`data/` в рабочем каталоге, `/app/data` в образе; например, один и тот же том или сетевая файловая система на каждом экземпляре). Документы курсов и сгенерированные медиа курсов хранятся в PostgreSQL (или в S3 при `ASSET_S3_BUCKET`), но каждый процесс держит в своём каталоге данных эти файлы: загруженные материалы и результаты их извлечения, озвучку и медиа материалов курсов, которые редактирует агент (`data/classrooms` или `OPENMAIC_CLASSROOMS_DIR`), записи об использовании (`data/usage`) и созданный секрет экземпляра. Генерация, которую подхватил другой экземпляр, читает загруженные материалы оттуда.

## Генерации

В каждом серверном процессе работает воркер генерации; он не зависит от `OPENMAIC_AGENT_RUNTIME_ENABLED`. Его настраивают эти переменные (положительные целые числа):

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `OPENMAIC_MAX_ACTIVE_RUNS_PER_OWNER` | `2` | Сколько генераций один владелец может вести одновременно. Генерации, ожидающие подтверждения плана или приостановленные на неудавшемся шаге, не учитываются. При превышении запуск, подтверждение плана или повтор возвращают `429 ACTIVE_RUN_LIMIT`. |
| `OPENMAIC_MAX_WAITING_RUNS_PER_OWNER` | `10` | Сколько генераций одного владельца могут одновременно ждать подтверждения плана. |
| `OPENMAIC_GENERATION_RUN_MAX_CONCURRENT` | `4` | Сколько генераций один процесс выполняет одновременно. |
| `OPENMAIC_GENERATION_RUN_STREAMS_PER_OWNER` | `16` | Сколько потоков событий генераций один владелец может держать открытыми на одном процессе. |
| `OPENMAIC_GENERATION_RUN_RETENTION_HOURS` | `24` | Сколько часов завершённая генерация хранит полный журнал событий, после чего он сжимается. |

Генерации используют параметры аренды среды выполнения агентов (`OPENMAIC_AGENT_RUNTIME_SCAN_INTERVAL_MS`, `_HEARTBEAT_MS`, `_LEASE_TTL_MS`, `_MAX_ATTEMPTS`; см. `.env.example`). При остановке или перезапуске сервера, в том числе при поэтапном обновлении, его генерации продолжает другой экземпляр или тот же после запуска — с последнего завершённого шага: прогресс останавливается примерно на время аренды (по умолчанию 10 секунд), а шаг, который выполнялся, генерируется заново. Генерация, прерванная `OPENMAIC_AGENT_RUNTIME_MAX_ATTEMPTS` раз подряд (по умолчанию 5) без завершения шага, приостанавливается на этом шаге с возможностью повтора; увеличьте значение, если поэтапные обновления многих экземпляров достигают его.

## Серверная персистентность (PostgreSQL)

OpenMAIC хранит курсы, историю чатов, прогресс учащихся и сгенерированные медиа в PostgreSQL, поэтому **`DATABASE_URL` обязателен**: без него сервер выводит `[boot] Invalid server configuration; the server will not start: DATABASE_URL is not set. ...` с подсказкой и завершается с кодом `1`. HTTP API персистентности встроено в OpenMAIC, отдельный сервис не требуется.

`docker compose up` запускает PostgreSQL рядом с приложением и задаёт для него `DATABASE_URL`. Для локальной разработки `pnpm db:up` запускает по тому же описанию сервиса отдельную базу для разработки (свой проект Compose и volume `openmaic-dev-db`, общая для всех копий репозитория на этой машине; база стека не затрагивается) на `127.0.0.1` (порт `OPENMAIC_DB_PORT`, по умолчанию `5432`), а `pnpm db:down` останавливает его. Затем укажите подключение в `.env.local`:

```bash
DATABASE_URL=postgres://openmaic:openmaic-dev@127.0.0.1:5432/openmaic
```

Отдельных учётных данных для хранилища нет: каждый запрос относится к владельцу, которого определяет разрешение владельца (по умолчанию анонимный cookie на каждый браузер), и сессии времени выполнения и медиа разделены по этому владельцу. Идентичность по умолчанию изолирует браузеры, но никого не аутентифицирует, поэтому развёртыванию с реальными пользователями следует зарегистрировать методы аутентификации владельца на основе собственных учётных записей. `PERSISTENCE_DEV_TOKEN` / `NEXT_PUBLIC_PERSISTENCE_TOKEN` из прежних версий удалены и игнорируются; сессии времени выполнения, сохранённые под прежним ключом ученика, созданным браузером, больше недоступны. Если `PERSISTENCE_DEV_TOKEN` был единственной защитой доступа, перед обновлением закройте развёртывание через `ACCESS_CODE` или шлюз либо зарегистрируйте методы аутентификации владельца.

Данные PostgreSQL хранятся в volume `openmaic-postgres`. Пароль `PERSISTENCE_POSTGRES_PASSWORD` задаётся только при первой инициализации базы, последующие изменения переменной не меняют пароль существующего пользователя.

Если `OPENMAIC_SECRET_KEY` не задан, том `openmaic-data` также хранит `instance-secret.key` — сгенерированный секрет экземпляра, которым шифруются ключи провайдеров из настроек моделей. Делайте его резервную копию вместе с базой данных: без него сохранённые ключи придётся ввести заново. Если работает несколько реплик, нет постоянного тома или файловая система доступна только для чтения, задайте вместо этого `OPENMAIC_SECRET_KEY` (одно значение на всех репликах); см. [Секреты и OPENMAIC_SECRET_KEY](./configuration.mdx#секреты-и-openmaic_secret_key).

Прежние версии могли хранить курсы в браузере (IndexedDB). Этот режим удалён, а переменная сборки `NEXT_PUBLIC_PERSISTENCE` игнорируется. Курсы, сохранённые так в браузере, автоматически переносятся на сервер, когда этот браузер впервые открывает обновлённое приложение: односторонний импортёр копирует их (вместе с чатами, прогрессом обучения, папками и медиа) владельцу, которого сервер определяет для этого браузера, и не изменяет исходные данные в браузере. Импорт выполняется один раз на браузер: сервер привязывает браузер к первому владельцу, открывшему обновлённое приложение, а присоединение переносит привязку в учётную запись (анонимный владелец, объединённый с учётной записью при входе). Запросы импортёра от имени любого другого владельца сервер отклоняет. Любой другой владелец, позже работающий в том же браузере, ничего не получает. Никаких действий не требуется, интерфейс не показывается; проблемы записываются в консоль браузера с префиксом `[legacy-browser-import]`.

## Обновление с 1.1.x

| Развертывание | Что сделать |
| --- | --- |
| `docker compose` | Получите новую версию и запустите `docker compose up --build`. Перенесите настройки моделей в `openmaic.yml` или **Настройки → Модели** (пока нет `openmaic.yml`, переменные провайдеров продолжают работать) и перепишите `MODEL_ROUTES` в виде слотов: сервер с `MODEL_ROUTES`, но без `openmaic.yml`, не запускается. Откройте приложение один раз в каждом браузере, где есть локальные курсы, чтобы они импортировались. Если в `.env.local` задан `PERSISTENCE_SHARED_OWNER_ID`, задайте и `OWNER_SINGLE_USER=false`: Compose теперь запускается в однопользовательском режиме. Курсы анонимных владельцев из прежнего серверного развертывания не объединяются с единственным пользователем автоматически; заберите их через `POST /api/identity/claim` из каждого браузера, в котором они созданы (при открытии браузера импортируется только то, что он хранил локально). |
| `pnpm start` с собственным PostgreSQL | Остановите сервер, получите новую версию, выполните `pnpm install` и `pnpm build` и снова запустите `pnpm start` в том же рабочем каталоге, чтобы сохранить `data/`. Задайте `DATABASE_URL`, режим идентификации и `OPENMAIC_SECRET_KEY`, если базу используют несколько экземпляров; нескольким экземплярам нужен и один общий каталог данных (см. [Обязательная конфигурация](#обязательная-конфигурация)). Настройки моделей, `MODEL_ROUTES` и курсы браузеров — как в строке выше. |
| Vercel | Оставайтесь на 1.1.x или перейдите на постоянно работающий хост с той же базой данных (см. ниже). |
| Skill / API | Следуйте обновлённому skill `openmaic`: загружайте материалы, отправляйте запрос и опрашивайте статус от имени одного владельца. |

Перед первым запуском 1.2.0:

- **Сохраните каталог данных.** Запускайте 1.2.0 с тем же `data/` в рабочем каталоге (или с тем же `OPENMAIC_CLASSROOMS_DIR`), а в Compose — с тем же томом `openmaic-data`. Классы, которые 1.1.x сохранила файлами в `data/classrooms`, один раз импортируются в базу в фоне после запуска; серверу, запущенному без этого каталога, импортировать нечего.
- **Сначала задайте режим идентификации.** Импорт отдаёт эти классы владельцу, настроенному при этом запуске: единственному пользователю (`OWNER_SINGLE_USER=true`) или общему владельцу команды (`PERSISTENCE_SHARED_OWNER_ID`), а иначе (анонимный режим) — отдельному владельцу `system:legacy-classrooms`; тогда они открываются по старым ссылкам только для чтения и не появляются ни в одной библиотеке. Каждый класс импортируется только один раз, поэтому классы, импортированные в анонимном режиме, остаются у `system:legacy-classrooms`, даже если позже задать режим идентификации.

Данные браузера (курсы, настройки моделей, пользовательские агенты) импортируются один раз, когда браузер впервые открывает обновлённое приложение. Перенос настроек моделей описан в [Конфигурации](./configuration.mdx#миграция-со-старой-конфигурации), полный список несовместимых изменений — в [CHANGELOG](https://github.com/THU-MAIC/OpenMAIC/blob/main/CHANGELOG.md).

## Vercel (до 1.1.x)

Serverless-развертывание поддерживается до OpenMAIC 1.1.x; кнопка Deploy в [README репозитория](https://github.com/THU-MAIC/OpenMAIC#vercel-deployment-up-to-11x) разворачивает ветку `release/1.1.x`. Такое развертывание позже можно перенести на постоянно работающий хост без потери данных: укажите в `DATABASE_URL` нового хоста прежнюю базу данных (если она использовалась) и обслуживайте его по тому же адресу — браузеры хранят данные для каждого сайта отдельно, и курсы посетителей импортируются, когда каждый браузер впервые открывает обновлённое приложение.

## Опционально: экспорт MP4 видео

Функция «Экспорт видео» сначала создаёт в браузере автономный проект Hyperframes, затем отдельный `render-service` с Chromium и FFmpeg рендерит MP4. Этот сервис необязателен и не влияет на обычное создание курсов.

Включите профиль `video-export`:

```bash
docker compose --profile video-export up --build
```

Compose передаёт OpenMAIC URL рендер-сервиса через `RENDER_SERVICE_URL`. Если профиль не включён или сервис недоступен, экспорт возвращается к скачиванию ZIP проекта для локального рендеринга через CLI. Рендер-сервис работает в изолированной сети и требует capability `NET_ADMIN` при запуске; подробности и отдельные варианты развертывания — в [`render-service/README.md`](https://github.com/THU-MAIC/OpenMAIC/blob/main/render-service/README.md).
