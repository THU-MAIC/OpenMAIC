لدى OpenMAIC ثلاثة مصادر للإعدادات، ولكل منها مهمة واحدة:

| المصدر | من يكتبه | ما يحتويه | متى يسري |
| --- | --- | --- | --- |
| `openmaic.yml` | المشغّل | المزودون والتعيينات الافتراضية للخادم والخانات المقفلة، وما إذا كان المستخدمون يستطيعون إضافة مفاتيحهم | عند بدء التشغيل (أعد التشغيل للتطبيق) |
| إعدادات النماذج في تطبيق الويب | مستخدمو مساحة العمل | مزودوهم الخاصون، وتعيينات كل خانة لا يقفلها `openmaic.yml`، وتُحفظ في قاعدة البيانات | فورًا |
| متغيرات البيئة (`.env.local`، أو Secret الحاوية) | المشغّل | الأسرار التي يشير إليها `openmaic.yml`، وكل خيارات الخادم الأخرى | عند بدء التشغيل |

كل متغيرات البيئة اختيارية باستثناء `DATABASE_URL` (راجع [النشر](./deployment.mdx)). تجد جميع المتغيرات في [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/main/.env.example)، ونقطة بداية لإعدادات النماذج في [`openmaic.example.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/main/openmaic.example.yml)، ومعرّفات الإعدادات المسبقة والنماذج في [النماذج المدعومة](./supported-models.mdx).

في الإصدارات السابقة كانت النماذج تُضبط فقط عبر متغيرات بيئة المزودين و`server-providers.yml` و`DEFAULT_MODEL` و`MODEL_ROUTES`. ما زالت هذه الطرق تعمل حاليًا، باستثناء `MODEL_ROUTES`، لكنها مهملة؛ راجع [الانتقال من الإعدادات القديمة](#الانتقال-من-الإعدادات-القديمة).

## النماذج والمزودون

### المفاهيم

- **المزود (provider)**: حساب يستطيع الخادم استدعاءه، مثل مفتاح OpenAI أو Token Plan من MiniMax أو خادم متوافق مع OpenAI تستضيفه بنفسك. لكل مزود معرّف تختاره أنت، و**إعداد مسبق (preset)** يحدد المورّد والقدرات التي يغطيها.
- **الخانة (slot)**: موضع في المنتج يستخدم الذكاء الاصطناعي، مثل مخطط المقرر أو محتوى الشرائح أو تحويل النص إلى كلام أو البحث على الويب. تشكّل الخانات شجرة لكل قدرة، والخانة التي ليس لها تعيين تتبع الخانة الأم.
- **التعيين (assignment)**: المزود والنموذج اللذان تستخدمهما الخانة (`provider:model`)، مع معاملات استدعاء ونموذج احتياطي اختياريًا، أو `null` لإيقاف الخانة.

تكون القدرة متاحة فقط عندما تُحل خانتها إلى تعيين. لا توجد مفاتيح تشغيل وإيقاف منفصلة.

### openmaic.yml

يقرأ الخادم `openmaic.yml` من المجلد الذي يبدأ فيه (جذر المستودع؛ `/app` في صورة Docker). لاستخدام مسار آخر اضبط `OPENMAIC_CONFIG`؛ يُحل المسار النسبي انطلاقًا من المجلد نفسه، ويجب عندها أن يكون الملف موجودًا. بدون الملف يستخدم الخادم إعدادات الويب، و[المتغيرات القديمة](#الانتقال-من-الإعدادات-القديمة) ما دامت مضبوطة.

يُقرأ الملف مرة واحدة عند بدء التشغيل: أعد تشغيل الخادم بعد تعديله. يُتحقق من الملف كاملًا قبل بدء الخادم. أي `${VAR}` غير مضبوط، أو إعداد مسبق أو خانة غير معروفين، أو إشارة إلى مزود غير مُعلن، أو مزود لا يقدم قدرة الخانة، يوقف الخادم، وتُعرض كل مشكلة مع موضعها:

```text
[boot] Invalid server configuration; the server will not start: Invalid model configuration in /app/openmaic.yml:
  - providers.openai.apiKey: environment variable OPENAI_API_KEY is not set
  - slots.course.outlines: unknown slot
```

لا تكتب الأسرار في الملف نفسه: أشر إليها بـ `${VAR}` واضبط المتغير في البيئة. القيم الآتية من المتغيرات لا تُطبع أبدًا في هذه الرسائل.

### مثال كامل

```yaml title="openmaic.yml"
providers:
  # <معرّف المزود>: أحرف صغيرة وأرقام وشرطات
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}      # يُقرأ من البيئة عند بدء التشغيل
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  openai-image:                    # المفتاح نفسه لتوليد الصور
    preset: openai-image
    apiKey: ${OPENAI_API_KEY}
  minimax:                         # Token Plan: محادثة وصور وفيديو وTTS وبحث
    preset: minimax
    apiKey: ${MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}
  local:                           # أي خادم متوافق مع OpenAI
    preset: openai-compatible
    baseUrl: http://ollama:11434/v1
    models: [qwen3:8b]

slots:
  llm: openai:gpt-5.5              # الافتراضي لكل خانات المحادثة أدناه
  course.outline:
    model: anthropic:claude-sonnet-4-6
    fallback: openai:gpt-5.4-mini  # يُجرَّب مرة واحدة عند فشل قابل لإعادة المحاولة
  course.content.slide:
    model: minimax:MiniMax-M3
    thinking: { enabled: false }
    fallback: minimax:MiniMax-M2.7
  classroom: local:qwen3:8b        # قد يحتوي معرّف النموذج على نقطتين
  agent:
    model: openai:gpt-5.5          # يحتاج إلى استدعاء الأدوات
    api: openai-completions
  tts: minimax:speech-2.8-turbo
  image: openai-image:gpt-image-2
  webSearch: tavily                # المزود وحده: نموذجه الافتراضي
  video: null                      # موقوف افتراضيًا؛ يمكن للمستخدمين تشغيله

lock: [tts]                        # ثابت للجميع مع شجرته الفرعية
allowUserKeys: false               # يختار المستخدمون من بين هؤلاء المزودين ولا يضيفون غيرهم
```

مع هذا الملف تكون الخانات المكتوبة تحت `slots` قيمًا افتراضية للخادم: يمكن للمستخدمين تغيير كل منها في إعدادات النماذج، باستثناء `tts` الذي يثبّته `lock` للجميع. خانة المحادثة غير المذكورة، مثل `course.agents`، تتبع أصلها (`llm`)؛ وجذر القدرة غير المذكور، مثل `asr` أو `document`، يبقى غير مُهيأ حتى يعيّنه مستخدم. ومع `allowUserKeys: false` يختار المستخدمون فقط من بين المزودين المعلنين هنا.

### المزودون

كل إدخال تحت `providers` يعلن مزودًا واحدًا. المفتاح هو معرّفه الذي تستخدمه الخانات للإشارة إليه: من 1 إلى 63 حرفًا من الأحرف الصغيرة والأرقام والشرطات، يبدأ بحرف أو رقم.

| الحقل | إلزامي | المعنى |
| --- | --- | --- |
| `preset` | نعم | الإعداد المسبق المدمج الذي يستخدمه هذا المزود. راجع [النماذج المدعومة ← الإعدادات المسبقة](./supported-models.mdx#الإعدادات-المسبقة). |
| `apiKey` | عادةً | مفتاح API. تحذفه الخدمات التي لا تحتاج إلى مفتاح (الخوادم المحلية، Brave، SearXNG، unpdf). |
| `baseUrl` | لبعض الإعدادات المسبقة | عنوان يُستدعى بدلًا من عنوان الإعداد المسبق. إلزامي لـ `openai-compatible` و`azure` و`searxng` و`mineru`. |
| `models` | لا | معرّفات نماذج المحادثة التي يقدمها هذا المزود كما تعرضها إعدادات النماذج. بالنسبة إلى `openai-compatible` فهي القائمة الوحيدة في الإعدادات. لا تقيّد ما يمكن كتابته في `slots`. |
| `proxy` | لا | عنوان وكيل HTTP لطلبات هذا المزود. |
| `credentials` | لبعض الإعدادات المسبقة | أزواج مفاتيح للخدمات التي لا تستخدم مفتاحًا واحدًا. يستخدم AliDocMind الحقلين `accessKeyId` و`accessKeySecret`. |
| `options` | لا | إعدادات غير سرية خاصة بالمزود، مثل `backend` لـ `voxcpm-tts`. الأسماء أحرف وأرقام و`_` و`-`؛ والقيم سلاسل نصية أو أرقام أو قيم منطقية (بلا خرائط أو قوائم متداخلة)، ويعمل `${VAR}`. تعرض إعدادات النماذج الخيارات، لذا لا تضع فيها مفتاحًا أبدًا. للنشر فقط: لا تستطيع إعدادات النماذج ضبطها. |

تغطي معظم الإعدادات المسبقة قدرة واحدة وفق السجلات المدمجة: الإعداد `openai` للمحادثة فقط، أما صور OpenAI وتحويل النص إلى كلام والتفريغ الصوتي فهي الإعدادات `openai-image` و`openai-tts` و`openai-whisper`. أعلن مزودًا واحدًا لكل قدرة، وأشر إلى `${VAR}` نفسه عندما يغطي مفتاح واحد عدة قدرات. **إعدادات Token Plan المسبقة** (`minimax` و`tokendance` و`volcengine-ark` و`kimi-coding-plan`) تغطي عدة قدرات بمفتاح واحد، كل منها على عنوان الخطة الخاص. يستبدل `baseUrl` على المزود العنوان لكل القدرات التي يغطيها، لذا لا تضع `baseUrl` لـ Token Plan إلا إذا انتقلت كل قدراته معه.

يوقّع Amazon Bedrock (`preset: bedrock`) الطلبات بسلسلة بيانات اعتماد AWS على الخادم (البيئة أو profile أو role)، ويقرأ المنطقة من `BEDROCK_REGION` أو `AWS_REGION` أو `AWS_DEFAULT_REGION`؛ و`apiKey` رمز bearer اختياري.

### الخانات

| الخانة | القدرة | الأم | ما تتحكم فيه |
| --- | --- | --- | --- |
| `llm` | chat | — | نموذج المحادثة الافتراضي: كل استدعاء محادثة لا تغطيه خانة أدناه |
| `course.research` | chat | `llm` | إعادة صياغة استعلام البحث على الويب أثناء البحث للمقرر |
| `course.outline` | chat | `llm` | مخططات المشاهد |
| `course.agents` | chat | `llm` | ملفات تعريف وكلاء المعلم وزملاء الصف |
| `course.content` | chat | `llm` | محتوى المشاهد لأنواع المشاهد التي ليس لها خانة خاصة |
| `course.content.slide` | chat | `course.content` | مشاهد الشرائح |
| `course.content.quiz` | chat | `course.content` | مشاهد الاختبارات |
| `course.content.interactive` | chat | `course.content` | المشاهد التفاعلية |
| `course.content.pbl` | chat | `course.content` | مشاهد التعلم القائم على المشاريع (PBL) |
| `course.actions` | chat | `llm` | إجراءات المشاهد (ما يقوله الوكلاء ويفعلونه في كل مشهد) |
| `classroom` | chat | `llm` | محادثة الصف وتصحيح الاختبارات وبيئة تشغيل PBL |
| `agent` | chat | `llm` | وكيل Pro workbench. **يتطلب استدعاء الأدوات.** ويقبل أيضًا `api` و`contextWindow` |
| `agent.title` | chat | `agent` | عناوين جلسات Pro. تُضبط في `openmaic.yml` فقط ولا تظهر في إعدادات النماذج |
| `tts` | tts | — | تحويل النص إلى كلام |
| `asr` | asr | — | التعرف على الكلام (الإدخال الصوتي وتفريغ الصوت والفيديو) |
| `image` | image | — | توليد الصور |
| `video` | video | — | توليد الفيديو |
| `webSearch` | webSearch | — | البحث على الويب |
| `document` | document | — | خدمة تحليل المستندات (MinerU وMinerU Cloud وAliDocMind). لا يحتاج استخراج نص PDF المدمج إلى خدمة |

كيف تُحل الخانة:

- يبدأ الحل من خانة الاستدعاء ويصعد نحو جذر القدرة، وأول تعيين يُعثر عليه هو الذي يُستخدم. لذلك يكون تعيين الخانة الأم هو الافتراضي لشجرتها الفرعية كلها، وتغيير الأم يغيّر كل خانة فرعية ليس لها تعيين خاص.
- داخل شجرة فرعية مقفلة (الخانة أو أحد أسلافها مذكور في `lock`، أو `lock: all`) لا يُعتد إلا بـ `openmaic.yml`: يصعد البحث حتى الخانة المقفلة، وأول تعيين يكتبه الملف هو الذي يُستخدم. وفي كل مكان آخر تُستشار في كل خانة أولًا تعيينات مساحة العمل نفسها، ثم القيمة الافتراضية التي يكتبها `openmaic.yml` هناك. لذلك تبقى القيمة الافتراضية المكتوبة على خانة فرعية سارية عندما تضبط مساحة العمل الخانة الأصل؛ ولاستبدالها تضبط مساحة العمل الخانة الفرعية نفسها.
- `null` يوقف الصعود: الخانة وكل الخانات تحتها التي ليس لها تعيين خاص تكون موقوفة.
- إذا وصل الحل إلى الجذر دون تعيين، تبقى القدرة غير مُعدة. تفشل الاستدعاءات بخطأ يذكر اسم الخانة، ولا يوجد رجوع إلى أي مورّد.
- المتطلبات تخص الخانة التي تعلنها، وتُفحص على النموذج الذي تُحل إليه الخانة، سواء كان معيّنًا لها أو موروثًا. تتطلب `agent` استدعاء الأدوات؛ وإذا قال الكتالوج المدمج إن نموذجها لا يدعمه، يرفض الوكيل العمل بدل أن يتدبر أمره. النموذج غير الموجود في الكتالوج مسموح به. لا متطلبات لـ `agent.title`، لذا يمكن أن يستخدم نموذجًا أصغر.

### التعيينات

للتعيين أربعة أشكال:

```yaml
slots:
  llm: openai:gpt-5.5            # مزود:نموذج
  webSearch: tavily              # المزود وحده: نموذجه الافتراضي
  course.outline:                # كائن مع معاملات
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
    thinking: { effort: low }
  video: null                    # موقوف
```

يقبل شكل الكائن الحقول التالية:

| الحقل | المعنى |
| --- | --- |
| `model` | إلزامي. `مزود:نموذج`، أو `مزود` وحده خارج خانات المحادثة. |
| `fallback` | نموذج لإعادة المحاولة مرة واحدة، بالشكل نفسه. لخانات النماذج اللغوية فقط؛ راجع [النماذج الاحتياطية](#النماذج-الاحتياطية). |
| `thinking` | معاملات الاستدلال لنماذج المحادثة: `enabled` (true/false)، و`mode` (`default` و`disabled` و`enabled` و`auto`)، و`effort` (`none` و`minimal` و`low` و`medium` و`high` و`xhigh` و`max`)، و`level` (`minimal` و`low` و`medium` و`high`)، و`budgetTokens`، و`excludeReasoningOutput`. يطبّق محوّل كل مزود ما تدعمه واجهته. |
| `api` | لـ `agent` فقط: لهجة النقل، `openai-completions` (الافتراضية) أو `openai-responses`. |
| `contextWindow` | لـ `agent` فقط: حجم نافذة السياق المفترض عند الضغط، عندما يجب أن يكون أقل من قيمة الكتالوج. |

يجب ألا تضبط خانة `agent` القيمة `thinking.effort`: فالنقل الذي يستدعي الأدوات لا يستطيع الجمع بين شدة الاستدلال وأدوات الدوال.

### الإشارة إلى المزود وحده

الإشارة بدون `:model` تعني النموذج الافتراضي للمزود: النموذج الذي توصي به Token Plan لتلك القدرة، وإلا فالنموذج الافتراضي في السجل المدمج. معظم خدمات البحث والمستندات لا تتيح اختيار نموذج، لذا فالشكل المعتاد هو `webSearch: tavily` أو `document: mineru-cloud`. خانات المحادثة تسمّي نموذجًا دائمًا؛ و`llm: openai` يُرفض عند بدء التشغيل.

### النماذج الاحتياطية

تنطبق النماذج الاحتياطية على خانات النماذج اللغوية فقط: `llm` وكل الخانات تحته. يُرفض `fallback` في خانة `tts` أو `asr` أو `image` أو `video` أو `webSearch` أو `document`، عند بدء التشغيل في `openmaic.yml` وعند الحفظ في إعدادات النماذج.

يُجرَّب `fallback` الخاص بالخانة مرة واحدة عندما يفشل استدعاء النموذج الأساسي، بعد محاولاته الخاصة، بفشل قابل لإعادة المحاولة: خطأ عابر من SDK، أو انتهاء المهلة، أو خطأ شبكة، أو نفاد الحصة (429)، أو نقص السعة (503)، أو مخرجات فارغة. رفض المحتوى لأسباب السلامة وأخطاء 4xx الأخرى لا تؤدي إلى الرجوع الاحتياطي. ينطبق الرجوع الاحتياطي على الاستدعاءات العادية والمتدفقة معًا، ويستخدم معاملات `thinking` الخاصة بالخانة.

النموذج الاحتياطي جزء من التعيين ويُورث معه: `course.content.slide` بلا تعيين خاص تستخدم نموذج `course.content` ونموذجه الاحتياطي. الخانة ذات المتطلبات لا تعيد المحاولة على نموذج احتياطي لا يلبيها.

### إيقاف قدرة

اكتب `null` في خانتها. `video: null` يوقف توليد الفيديو افتراضيًا، ويظل بإمكان المستخدمين تشغيله في إعدادات النماذج؛ أضف `lock: [video]` لإبقائه موقوفًا للجميع. و`course.content.pbl: null` يوقف توليد مشاهد PBL بينما يواصل باقي `course.content` العمل. يفشل استدعاء الخانة الموقوفة فورًا، وتجيب مسارات الوسائط بـ `403` بدل اختيار مورّد آخر.

### القيم الافتراضية والأقفال وإعدادات النماذج

ما يكتبه `openmaic.yml` تحت `slots` هو **القيمة الافتراضية** للخادم: يمكن للمستخدمين تغييرها في إعدادات النماذج، حيث تقول البطاقة **افتراضي الخادم**، ويلغي **إعادة التعيين إلى افتراضي الخادم** تغييرهم. وما يذكره تحت `lock` **يثبّته المسؤول** للجميع مع شجرته الفرعية كاملة:

```yaml
lock: [llm, video]   # هذه الخانات وكل الخانات تحتها
# أو
lock: all            # كل الخانات
```

- يجب أن تكون كل خانة يذكرها `lock` مكتوبة تحت `slots` (و`null` يُحتسب: `video: null` مع `lock: [video]` يبقي الفيديو موقوفًا للجميع). الخانة المجهولة، أو الخانة المقفلة التي لا يكتبها `slots`، توقف الخادم عند بدء التشغيل مع ذكر موضعها (`lock.1: ...`).
- الخانة المقفلة تثبّت أبناءها أيضًا: مع `lock: [llm]` لا يستطيع أي مستخدم ضبط `course.outline` أو أي خانة أخرى لنموذج اللغة، وتُحل كلها من `openmaic.yml` وحده.
- `lock: all` يثبّت كل الخانات، مكتوبة أو لا؛ ويصبح جذر القدرة الذي لا يكتبه `slots` غير مُهيأ للجميع.
- تجتمع `null` والقيمة الافتراضية والقفل كما هو متوقع: `video: null` وحدها موقوفة حتى يشغّلها مستخدم؛ ومع `lock: [video]` تبقى موقوفة.

تأخذ الإعدادات أحد ثلاثة أشكال، بحسب الإعداد:

| الشكل | متى | ما يُعرض |
| --- | --- | --- |
| **اضبطها بنفسك** | `allowUserKeys` مفعّل (الافتراضي) | Token Plan وخدمات النماذج وإعدادات نماذج الدورة |
| **اختر نموذجًا** | `allowUserKeys: false` | إعدادات نماذج الدورة فقط، مع الاختيار من بين المزودين الذين يعلنهم `openmaic.yml` |
| **مُهيأ من قِبل المسؤول** | كل الخانات مقفلة (`lock: all`) | ملخّص للقراءة فقط يبيّن النموذج الذي يستخدمه كل جزء (أو أنه موقوف أو غير مُهيأ) |

قاعدة واحدة تحكم كل عنصر تحكم: لا يُعرض إلا إذا كان استخدامه يمكن أن يغيّر شيئًا. لا يظهر تبويب في خدمات النماذج، ولا إضافة خدمة فيه، إلا ما دامت لقدرته خانة يستطيع المستخدم ضبطها؛ ولا يظهر Token Plan إلا ما دامت خطة ما قادرة على ملء خانة غير مقفلة، ولا يمس ربط الخطة أي خانة مقفلة. البطاقة المقفلة في إعدادات نماذج الدورة سطر واحد للقراءة فقط عليه **ثبّته المسؤول**. ويكون منتقي النماذج في شريط الأدوات الرئيسي للقراءة فقط ما دامت `llm` مقفلة.

تقرأ إعدادات النماذج في تطبيق الويب الشجرة نفسها وتعدّلها لمساحة العمل الحالية:

- **Token Plan**: يضيف ربط خطة مزودها بالمفتاح ويملأ الخانات التي توصي بها الخطة ولم تُعيّن بعد. يزيل فك الربط المزود، وتعود الخانات التي كانت تستخدمه إلى اتباع خاناتها الأم.
- **خدمات النماذج**: تبويب لكل قدرة (نماذج اللغة، الصور، الفيديو، تحويل النص إلى كلام، التعرف على الكلام، تحليل المستندات، البحث على الويب) يسرد خدماتها. يُعرض مزودو `openmaic.yml` للقراءة فقط ودون أي معلومات عن مفاتيحهم. الخدمة التي تعدّها مساحة العمل تصبح مزودًا لها: مفتاحها للكتابة فقط ولا يظهر إلا كقناع مثل `…abcd`، والعنوان المخصص متاح لنماذج اللغة فقط (تستخدم Azure Speech نقطة النهاية الرسمية لمنطقتها، مثل `https://<region>.tts.speech.microsoft.com`)، والخدمات المستضافة ذاتيًا وأزواج المفاتيح تُعدّ في `openmaic.yml`. تتحقق أزرار الاختبار من المزود المحفوظ على الخادم.
- **إعدادات نماذج الدورة**: النموذج الرئيسي هو خانة `llm`، ولكل مرحلة في المسار خانتها (اتباع النموذج الرئيسي يعني أنه لا تعيين خاصًا بالمرحلة)؛ وتضبط مفاتيح الصور والفيديو والكلام والبحث والتفريغ خانتها على `null`. الخانة المقفلة سطر واحد للقراءة فقط، والخانة التي على قيمة الخادم الافتراضية تعرض **إعادة التعيين إلى افتراضي الخادم** بعد أن يغيّرها المستخدم.

تُستورد إعدادات المزودين التي حفظها المتصفح في الإصدارات السابقة (المزودون بمفاتيحهم وعناوينهم الأساسية، والنموذج المختار، والاشتراك في Token Plan، واختيار كل قدرة) إلى مساحة العمل مرة واحدة. لا يستبدل الاستيراد أي إعداد موجود في مساحة العمل ولا أي خانة يقفلها `openmaic.yml`، ويتخطى العناصر التي يرفضها `allowUserKeys: false` أو التحقق. بعد استجابة 2xx، لا يُحذف من المتصفح إلا ما أصبحت مساحة العمل تحتفظ به: كل عنصر تخطاه الخادم (عنوان مخصص لخدمة وسائط، أو إعداد مسبق لا يحق لمساحة العمل استخدامه، أو معرّف مزود يعلنه النشر، ...) يبقى في هذا المتصفح مع مفتاحه، ولا يُرسل مرة أخرى، ويُعرض مع السبب في الإعدادات ← خدمات النماذج (مع تنبيه لمرة واحدة) حتى يُعاد إعداده أو يُتجاهل. يُستورد مزود Azure Speech مع نقطة النهاية الرسمية لمنطقته. بعد 400 يُرفض الاقتراح كله: لا يُرسل مرة أخرى، وتبقى عناصره مع مفاتيحها في هذا المتصفح وتُعرض مع العناصر التي تم تخطيها. ويُحذف الاقتراح غير المقروء؛ ولا يبقى في المتصفح لمحاولة لاحقة إلا عند 401 أو 404 أو 409 أو 5xx أو خطأ في الشبكة. يصبح الإدخال الصوتي الذي أُوقف صراحةً `asr: null`، وتصبح السرد أو الصور أو الفيديو التي أُوقفت مع وجود مزود صالح لها `tts: null` أو `image: null` أو `video: null` (وتبقى الخانة التي يقفلها `openmaic.yml` كما هي). يجب إعداد ما يلي يدويًا من جديد: نماذج المراحل (في إعدادات نماذج الدورة، أو `slots` في `openmaic.yml`)، وإعدادات الاستدلال (`thinking` على الخانة)، ومزودو الكلام والتفريغ المخصصون وزوج مفاتيح AliDocMind (في `openmaic.yml`؛ تبقى في المتصفح وتُعرض مع العناصر المتخطاة)، وخلفية VoxCPM (`options.backend`)، ومصادر بحث Baidu الفرعية (تُطبّق القيم الافتراضية للخادم). لا يُنقل إيقاف البحث (كان يوقف بحث الدورة فقط، بينما واصلت المحادثة والوكيل البحث)، ولا المفتاح المتوقف بحكم القيمة الافتراضية فقط: كل قدرة تعمل الآن متى حُلت خانتها.

مساحة العمل هي المالك (owner) بمعنى [توثيق التخزين الدائم](./deployment.mdx): في إعداد Docker Compose الافتراضي (وضع المستخدم الواحد) توجد مساحة عمل واحدة، وفي النشر متعدد المستخدمين يكون لكل حساب مسجّل مساحة عمله.

### allowUserKeys

```yaml
allowUserKeys: false
```

يحدد `allowUserKeys` (الافتراضي `true`) ما إذا كان بإمكان المستخدمين إضافة مزودين ومفاتيح وخطط Token Plan خاصة بهم. مع `false` يختار المستخدمون فقط من بين المزودين الذين يعلنهم `openmaic.yml`، وللخانات غير المقفلة فقط: لا يُعرض Token Plan ولا إضافة الخدمات، ولا تُستخدم بعد ذلك المزودات التي أضافتها مساحات العمل من قبل. ويتم حينئذ تجاهل الطلبات التي لا تزال تسمّي نموذجها أو مفتاحها أو عنوانها (ترويسات `x-model` و`x-api-key` و`x-base-url` المهملة، وحقول المزود في مسارات الوسائط)، ويُرفض شكل الترويسات في أزرار اختبار المزودين. والنشر متعدد المستخدمين الذي يتحمّل كل الاستخدام يضبطه عادةً ويقفل الخانات التي يريد تثبيتها.

### الأسرار و OPENMAIC_SECRET_KEY

- المفاتيح في `openmaic.yml` تأتي من البيئة عبر `${VAR}`. لا تُخزن في قاعدة البيانات ولا تُرسل إلى المتصفح أبدًا.
- المفاتيح التي تدخلها مساحة العمل في إعدادات النماذج تُخزن في قاعدة البيانات مشفرة بـ AES-256-GCM تحت سر المثيل `OPENMAIC_SECRET_KEY`.
- عندما لا يكون `OPENMAIC_SECRET_KEY` مضبوطًا، ينشئ الخادم سرًا عشوائيًا عند أول استخدام في `data/instance-secret.key` (داخل وحدة التخزين `openmaic-data` مع Docker Compose) ويستخدمه بعد ذلك.

احفظ السر مع نسخ قاعدة البيانات الاحتياطية: المفاتيح المحفوظة تحت سر مفقود أو متغير لا يمكن قراءتها ويجب إدخالها من جديد (تشير إليها إعدادات النماذج). اضبط `OPENMAIC_SECRET_KEY` صراحةً عندما تتشارك عدة مثيلات قاعدة البيانات نفسها، أو عندما لا يكون للخادم مجلد بيانات دائم (مثل حاوية بلا وحدة تخزين للبيانات)؛ أي سلسلة نصية تصلح، مثل مخرجات `openssl rand -base64 32`.

من دونه، يعني مجلد البيانات الذي لا يبقى بعد إعادة التشغيل (حاوية بلا وحدة تخزين، أو قرص مؤقت) سرًا جديدًا عند كل تشغيل، وتنشئ كل نسخة من النسخ المتعددة سرها الخاص؛ وفي مجلد عمل للقراءة فقط لا يمكن إنشاء سر ويفشل حفظ المفاتيح في إعدادات النماذج. عند بدء التشغيل يسجّل الخادم تحذيرًا عندما لا يكون `OPENMAIC_SECRET_KEY` مضبوطًا ومجلد البيانات غير قابل للكتابة، وعندما تحتوي قاعدة البيانات على مفاتيح مختومة بسر غير السر الحالي (مثلًا لفقدان `data/instance-secret.key`)؛ ويواصل التشغيل مع ذلك.

```bash
OPENMAIC_SECRET_KEY=...        # سر المثيل للمفاتيح المحفوظة في إعدادات النماذج
OPENMAIC_CONFIG=/etc/openmaic/openmaic.yml   # اختياري: مسار آخر لـ openmaic.yml
```

### ما يمكن لمساحات العمل إضافته

يمكن أن يكون مزودو `openmaic.yml` أي شيء يقبله المخطط. أما المزودون الذين تضيفهم مساحة العمل في إعدادات النماذج فهم أكثر تقييدًا، لأن عنوانهم ومفتاحهم يكتبهما مستخدم تطبيق الويب:

- لا يُعرض Amazon Bedrock: فهو سيوقّع ببيانات اعتماد AWS الخاصة بالخادم.
- لا `proxy` ولا أزواج مفاتيح (`credentials`): الإعدادات المسبقة التي تستخدم زوج مفاتيح، مثل AliDocMind، متاحة للنشر فقط.
- يُسمح بـ `baseUrl` مخصص فقط للإعدادات المسبقة التي تقدم المحادثة، والمزود الذي يملكه يخدم خانات المحادثة فقط. يجب ألا يحتوي العنوان على بيانات اعتماد أو سلسلة استعلام أو جزء (fragment)، ويجب أن يُحل إلى عنوان عام ما لم يضبط الخادم `ALLOW_LOCAL_NETWORKS=true`. الطلبات إليه لا تتبع عمليات إعادة التوجيه.
- يجب على خوادم النماذج المحلية (Ollama وLemonade) تسمية عنوانها الخاص بدل `localhost` الافتراضي في الإعداد المسبق.
- خدمات الوسائط والبحث والمستندات المستضافة ذاتيًا (VoxCPM2 وFunASR وكلام وصور Lemonade وComfyUI وSearXNG وMinerU المستضاف ذاتيًا) تعمل على شبكة الخادم نفسه ومتاحة للنشر فقط.
- لا يُعرض المزودون الذين أوقفهم المشغّل بمتغير `<CAP>_<VENDOR>_ENABLED=false` القديم.
- لا يمكن لمساحة العمل إعلان معرّف مزود أعلنه `openmaic.yml` بالفعل.

إذا أراد النشر أن يصل المستخدمون إلى خدمات داخلية، فليعلن هؤلاء المزودين في `openmaic.yml`.

### عملاء API وحقول الطلب المهملة

لم تعد طلبات التوليد بحاجة إلى حمل مفاتيح أو اختيارات نماذج: استدعاءات API التي تعمل بلا متصفح، مثل `/api/generate-classroom`، تُحل عبر الخانات نفسها التي يستخدمها تطبيق الويب، لمساحة عمل المستدعي.

ترويسات الطلب القديمة `x-model` و`x-api-key` و`x-base-url` و`x-provider-type` و`x-model-routes` و`x-image-provider` و`x-image-model` و`x-video-provider` و`x-video-model`، وحقول جسم الطلب المقابلة في مسارات الكلام والبحث والمستندات، مهملة. لا يُعمل بها إلا ما دامت الخانة التي تؤثر فيها بلا تعيين، أو، على خادم لا يزال مُهيأً بالمتغيرات القديمة، بقيمة افتراضية محوَّلة منها فقط (فقد كان `DEFAULT_MODEL` دائمًا أدنى من النموذج الذي يسميه الطلب)؛ وتغلب القيمة الافتراضية في `openmaic.yml` واختيار مساحة العمل نفسها والخانة المقفلة، والخانة المضبوطة على `null` ترفض الطلب أيًا كان ما يسميه. ومع `allowUserKeys: false` يتم تجاهلها كليًا. يسجّل الخادم تحذيرًا في أول مرة يستخدمها طلب. ستُزال بعد إصدارين فرعيين من صدور إعدادات النماذج الموصوفة أعلاه.

### الانتقال من الإعدادات القديمة

عندما لا يوجد `openmaic.yml`، يحوّل الخادم الإعدادات القديمة عند بدء التشغيل ويسجّل إشعار إهمال، وإشعارًا لكل إدخال تعذّر نقله:

| الإعداد القديم | يصبح |
| --- | --- |
| متغيرات المزودين (`OPENAI_API_KEY` و`TTS_MINIMAX_API_KEY` و…) و`server-providers.yml` | مزودي النشر (للقراءة فقط في إعدادات النماذج). معرّف المزود هو معرّف الإعداد المسبق، وهو معرّف المزود القديم باستثناء بحث MiniMax على الويب (`minimax-search`) وبحث Doubao على الويب (`doubao-search`) وصور Lemonade (`lemonade-image`) |
| `<PREFIX>_MODELS` | `models` الخاصة بالمزود |
| `DEFAULT_MODEL` | تعيين `llm` كقيمة افتراضية يمكن لمساحة العمل تجاوزها (غير مقفلة). تبقى خانة `agent` موقوفة كما كانت |
| `MODEL_FALLBACK` | النموذج الاحتياطي لـ `DEFAULT_MODEL`. بدون `DEFAULT_MODEL` يُسقط مع إشعار |
| أول مزود مُعد للـ TTS والـ ASR والصور والفيديو والمستندات، والبحث على الويب بترتيب الأولوية القديم | التعيين الافتراضي لتلك القدرة (يختار `DEFAULT_IMAGE_PROVIDER` مزود الصور) |
| `MODEL_ROUTES` | **لا يُحوَّل.** يرفض الخادم البدء (انظر أدناه) |
| `<CAP>_<VENDOR>_ENABLED=false` | ما زال ساريًا: يبقى المزود موقوفًا أيًا كان من يعيّنه |

عند وجود `openmaic.yml` تُتجاهل متغيرات المزودين و`server-providers.yml` و`DEFAULT_MODEL` و`MODEL_FALLBACK` و`MODEL_ROUTES` في حل النماذج، مع إشعار. ما زال `<CAP>_<VENDOR>_ENABLED=false` ساريًا؛ لإيقاف قدرة اضبط خانتها على `null` بدلًا من ذلك.

**متغيرات البيئة.** قبل:

```bash
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DEFAULT_MODEL=openai:gpt-5.5
MODEL_FALLBACK=anthropic:claude-sonnet-4-6
TTS_MINIMAX_API_KEY=...
TAVILY_API_KEY=tvly-...
```

بعد (تبقى المفاتيح في البيئة):

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  minimax-tts:
    preset: minimax-tts
    apiKey: ${TTS_MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}

slots:
  llm:
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
  tts: minimax-tts
  webSearch: tavily
```

احذف بعد ذلك `DEFAULT_MODEL` و`MODEL_FALLBACK`. يمكن إبقاء متغيرات المزودين مصدرًا لإشارات `${VAR}`. يصبح `<PREFIX>_BASE_URL` قيمة `baseUrl` للمزود (`OPENAI_BASE_URL` ← `baseUrl` تحت `openai`؛ اكتب العنوان، أو `${OPENAI_BASE_URL}` ما دام المتغير مضبوطًا)، ويصبح `<PREFIX>_MODELS` قائمة `models` الخاصة به. ومثل `DEFAULT_MODEL` المحوَّل، فإن `llm` المكتوب هنا قيمة افتراضية للخادم يمكن لمساحات العمل تغييرها؛ أضف `lock: [llm]` لتثبيته للجميع. وعلى خلاف التحويل، أصبحت `agent` تتبع `llm`: اكتب `agent: null` لإبقاء وكيل Pro موقوفًا.

**server-providers.yml.** قبل:

```yaml title="server-providers.yml"
providers:
  azure:
    apiKey: ...
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
pdf:
  alidocmind:
    accessKeyId: ...
    accessKeySecret: ...
web-search:
  searxng:
    baseUrl: http://searxng:8080
```

بعد:

```yaml title="openmaic.yml"
providers:
  azure:
    preset: azure
    apiKey: ${AZURE_OPENAI_API_KEY}
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
  alidocmind:
    preset: alidocmind
    credentials:
      accessKeyId: ${ALIDOCMIND_ACCESS_KEY_ID}
      accessKeySecret: ${ALIDOCMIND_ACCESS_KEY_SECRET}
  searxng:
    preset: searxng
    baseUrl: http://searxng:8080

slots:
  llm: azure:my-deployment
  document: alidocmind
  webSearch: searxng
```

يصبح كل قسم من `server-providers.yml` مزودين بالإعداد المسبق المطابق (`providers` ← إعدادات المحادثة، و`tts` و`asr` و`pdf` ← المستندات، و`image` و`video` و`web-search`)، وينتقل `accessKeyId`/`accessKeySecret` إلى `credentials`.

**MODEL_ROUTES.** الخادم الذي يضبط `MODEL_ROUTES` دون `openmaic.yml` لا يبدأ:

```text
MODEL_ROUTES does not carry over to the model configuration: write the per-stage models as slots in openmaic.yml (or the file named by OPENMAIC_CONFIG) and remove MODEL_ROUTES
```

لا تتطابق المسارات حسب المرحلة مع الخانات واحدًا لواحد، لذا لا تُحوَّل. أعد كتابة كل مسار كالخانة التي تنتمي إليها مرحلته:

| مرحلة `MODEL_ROUTES` | الخانة |
| --- | --- |
| `web-search-query-rewrite` | `course.research` |
| `scene-outlines-stream` | `course.outline` |
| `agent-profiles` | `course.agents` |
| `scene-content` | `course.content` |
| `scene-content:slide` و`:quiz` و`:interactive` و`:pbl` | `course.content.slide` و`.quiz` و`.interactive` و`.pbl` |
| `scene-actions` | `course.actions` |
| `chat-adapter` و`quiz-grade` و`pbl-v2-runtime` ومتغيراته `:instructor` و`:open-task` و`:evaluate` و`:simulator` | `classroom` |
| `generate-classroom` | `llm` |
| `maic-agent-driver` | `agent` |
| `conversation-title` | `agent.title` |
| `pbl-chat` و`maic-agent` | لا شيء: أُزيلت هذه المراحل. احذفها |

عندما تتشارك عدة مراحل خانة واحدة، أعطِ الخانة النموذج الواحد الذي يجب أن تستخدمه. ينتقل `thinking` الخاص بالمسار إلى `thinking` الخانة، وينتقل `api` و`contextWindow` من مسار `maic-agent-driver` إلى خانة `agent`. قبل:

```bash
DEFAULT_MODEL=openai:gpt-5.5
MODEL_ROUTES='{"scene-outlines-stream":"anthropic:claude-sonnet-4-6","scene-content:slide":{"model":"openai:gpt-5.4","thinking":{"effort":"low"}},"maic-agent-driver":{"model":"openai:gpt-5.5","api":"openai-completions"}}'
```

بعد:

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}

slots:
  llm: openai:gpt-5.5
  course.outline: anthropic:claude-sonnet-4-6
  course.content.slide:
    model: openai:gpt-5.4
    thinking: { effort: low }
  agent:
    model: openai:gpt-5.5
    api: openai-completions
```

بمجرد وجود `openmaic.yml` لا تضبط متغيرات المزودين وحدها أي شيء: مزود تحويل النص إلى كلام أو الصور أو المستندات أو البحث على الويب الذي لم يكن له سوى متغيراته (`TTS_MINIMAX_API_KEY` و`IMAGE_SEEDREAM_API_KEY` و`PDF_MINERU_BASE_URL` و`TAVILY_API_KEY` …) لم يعد يُستخدم، ولا تحصل أي قدرة على مزود افتراضي. صرّح بكل مزود تستخدمه تحت `providers` وعيّن `tts` و`image` و`document` و`webSearch` (و`asr` و`video`) في `slots`، كما في مثال متغيرات البيئة أعلاه؛ وتبقى الخانة غير المعيّنة غير مُعدّة ما لم تعيّنها مساحة عمل في إعدادات النماذج.

ثم احذف `MODEL_ROUTES` و`DEFAULT_MODEL` و`MODEL_FALLBACK`.

**Docker.** اربط الملف بجوار التطبيق وأبقِ المفاتيح في `.env.local`:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

## ACCESS_CODE — كلمة مرور على مستوى الموقع

للنشر المشترك (عروض داخلية، صفوف)، يمكن تعيين رمز وصول ليطلب من الزوار إدخال كلمة مرور قبل رؤية التطبيق:

```bash
ACCESS_CODE=your-secret-code
```

استخدم قيمة عشوائية طويلة (16 حرفًا على الأقل) — فهذا الرمز هو السر الوحيد الذي يحمي النشر. بعد نجاح التحقق، يُحفظ رمز موقَّع في cookie من نوع HTTP-only لمدة 7 أيام، ويُفرض انتهاء صلاحيته من جهة الخادم، لذا يلزم إعادة إدخال الرمز بعد انتهائه. لا يُقيَّد معدل التحقق إلا عند ضبط `TRUST_PROXY_HEADERS=true` خلف وكيل عكسي موثوق يعيد كتابة `x-forwarded-for` / `x-real-ip`: لكل عميل 10 محاولات كل 60 ثانية، ونجاح التحقق يمسح عدّاد ذلك العميل. وبدون وكيل موثوق لا يستطيع التطبيق نسبة الطلب إلى عميل بعينه، لذا لا يوجد أي تقييد، وتكون الحماية في طول الرمز وعشوائيته. اتركه فارغًا لتعطيله.

## feature flags (مفاتيح الميزات)

تُعتبر القيم `true` أو `1` مفعلة، وما لم يُذكر خلاف ذلك تُعد أي قيمة أخرى معطلة. تُحقن متغيرات `NEXT_PUBLIC_*` في وقت البناء للعميل، ويجب إعادة البناء بعد تعديلها:

```bash
# محرر MAIC (وضع Pro)
NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true

# محادثة Pi مفعلة افتراضيًا؛ أزل التعليق عن السطر التالي للعودة إلى المسار القديم
# NEXT_PUBLIC_PI_CHAT_ENABLED=false

# مراجع مواد PPT والمشاهد التفاعلية أثناء تشغيل Pi (علامة وقت البناء؛ لا تؤثر في مراجع وضع التحرير)
NEXT_PUBLIC_COURSEWARE_REFERENCE_ENABLED=true

# محرك مهام التعليم المهني (مفتاح خادم)
OPENMAIC_ENABLE_VOCATIONAL=true

# عرض مفتاح تجربة التعليم المهني
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true

# عرض مدخل تصدير الفيديو
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true

# عرض مدخل استيراد PPTX التجريبي
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true
```

تعتمد محادثة Pi على دعم النموذج لاستدعاء الأدوات/الدوال. إذا كان النموذج أو الموفر المحدد لا يدعم استدعاء الأدوات، فاضبط `NEXT_PUBLIC_PI_CHAT_ENABLED=false` (أو `0`) وأعد البناء لاستخدام مسار المحادثة القديم.

في Docker Compose، يُحمَّل ملف `.env.local` عبر `env_file` وقت التشغيل، ولا يُستخدم لاستبدال متغيرات وسائط البناء. أعد البناء مع تحديد القيمة صراحةً كما في الأمر التالي؛ فتغيير بيئة التشغيل وحدها لا يغيّر مسار المحادثة الذي اختير عند بناء العميل والخادم.

```bash
NEXT_PUBLIC_PI_CHAT_ENABLED=false docker compose up -d --build openmaic
```

استيراد PPTX لا يزال تجريبيًا، والنتائج لم تُدمج بالكامل في تدفق بيانات الصف. جميع متغيرات `NEXT_PUBLIC_*` هي مفاتيح بناء؛ عند نشر Docker، يجب تمريرها كـ build args، لا يمكن فقط تعيينها في بيئة الحاوية.

## متغيرات بيئة المزودين القديمة

هذه المتغيرات و`server-providers.yml` هي إعدادات الإصدارات السابقة. ما زالت تعمل عند عدم وجود `openmaic.yml` (راجع [الانتقال من الإعدادات القديمة](#الانتقال-من-الإعدادات-القديمة))، لكنها مهملة وستُزال بعد إصدارين فرعيين من صدور إعدادات النماذج. مع `openmaic.yml` استخدمها فقط مصدرًا لإشارات `${VAR}`. يشرح قسم الانتقال `DEFAULT_MODEL` و`MODEL_FALLBACK`؛ ولم يعد `MODEL_ROUTES` يُقرأ.

### موفرو LLM

عادةً ما يستخدم موفرو السحابة ثلاثة متغيرات بيئة: مفتاح API، عنوان URL الأساسي، وقائمة النماذج. مفتاح API عادةً مطلوب، أما العنوان الأساسي وقائمة النماذج فاختياريان. Azure OpenAI يحتاج إلى تكوين نقطة نهاية المورد، بينما Ollama وLemonade لا يحتاجان إلى مفتاح API.

```bash
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=                # تجاوز اختياري للعنوان الأساسي
OPENAI_MODELS=                  # قائمة بيضاء اختيارية للنماذج (مفصولة بفواصل)
```

بادئات الموفرين المدعومة:

| البادئة             | الموفر                              |
| ------------------- | ---------------------------------- |
| `OPENAI_`           | OpenAI                             |
| `AZURE_OPENAI_`     | Azure OpenAI                       |
| `ANTHROPIC_`        | Anthropic                         |
| `GOOGLE_`           | Google Gemini                     |
| `DEEPSEEK_`         | DeepSeek                         |
| `QWEN_`             | Alibaba Qwen                     |
| `KIMI_`             | Moonshot Kimi                   |
| `MINIMAX_`          | MiniMax (يستخدم نقطة نهاية متوافقة مع Anthropic افتراضيًا) |
| `GLM_`              | Zhipu GLM                       |
| `SILICONFLOW_`      | SiliconFlow                     |
| `DOUBAO_`           | Doubao (ByteDance)              |
| `OPENROUTER_`       | OpenRouter                     |
| `GROK_`             | xAI Grok                       |
| `TENCENT_`          | Tencent Hunyuan                |
| `TENCENT_HUNYUAN_`  | Tencent Hunyuan (اسم بديل)    |
| `XIAOMI_`           | Xiaomi MiMo                   |
| `MIMO_`             | Xiaomi MiMo (اسم بديل)        |
| `OLLAMA_`           | Ollama (محلي)                 |
| `LEMONADE_`         | Lemonade (محلي)               |

يستخدم Azure OpenAI اسم النشر كمعرف للنموذج:

```bash
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_BASE_URL=https://YOUR-RESOURCE.openai.azure.com/openai
AZURE_OPENAI_MODELS=your-deployment-name
```

للاتصال بخدمة LLM أخرى متوافقة مع OpenAI، أعلن في `openmaic.yml` مزودًا من نوع `openai-compatible` مع `baseUrl` و`models` الخاصة به، أو أضفه عبر **إضافة مزود** ضمن **الإعدادات ← خدمات النماذج ← نماذج اللغة**.

### النماذج المحلية (Ollama و Lemonade)

لا تحتاج Ollama وLemonade إلى مفتاح API؛ يجب كتابة عنوان URL الأساسي للخدمة المحلية في إعدادات الخادم لتجاوز فحص SSRF:

```bash
OLLAMA_BASE_URL=http://localhost:11434/v1
# LEMONADE_BASE_URL=http://localhost:13305/v1
```

يمكن تحديد قائمة بيضاء للنماذج المتاحة باستخدام `OLLAMA_MODELS` أو `LEMONADE_MODELS`.

### موفرو TTS

يستخدم موفرو TTS على الخادم متغيرات `TTS_<PROVIDER>_API_KEY`، مع خيار `TTS_<PROVIDER>_BASE_URL` للتجاوز.

```bash
# Doubao TTS (Volcengine Seed-TTS، MP3 أصلي)
TTS_DOUBAO_API_KEY=appId:accessKey
TTS_DOUBAO_BASE_URL=       # تجاوز اختياري

# Qwen TTS
TTS_QWEN_API_KEY=
TTS_QWEN_BASE_URL=         # تجاوز اختياري

# أي نقطة نهاية متوافقة مع OpenAI TTS
TTS_OPENAI_API_KEY=
TTS_OPENAI_BASE_URL=

# VoxCPM2 (TTS ذاتي الاستضافة مع استنساخ الصوت، راجع صفحة VoxCPM2)
TTS_VOXCPM_BASE_URL=http://localhost:8000
```

بادئات TTS المدعومة تشمل `TTS_OPENAI_`، `TTS_AZURE_`، `TTS_GLM_`، `TTS_QWEN_`، `TTS_MINIMAX_`، `TTS_DOUBAO_`، `TTS_ELEVENLABS_`، `TTS_GOOGLE_`، `TTS_VOXCPM_` و `TTS_LEMONADE_`. TTS المحلي لـ Lemonade وVoxCPM2 لا يحتاجان إلى مفتاح API. TTS المدمج في المتصفح لا يحتاج إلى إعدادات خادم.

يمكن للمسؤولين تعطيل موفر TTS معين على الخادم باستخدام `TTS_<PROVIDER>_ENABLED=false`. لمزيد من التفاصيل عن VoxCPM2 (TTS ذاتي الاستضافة واستنساخ الصوت)، راجع الفصل الخاص بـ [VoxCPM2](./voxcpm.mdx).

لاستخدام عنوان TTS آخر متوافق مع OpenAI، أعلن في `openmaic.yml` مزودًا من نوع `openai-tts` بذلك `baseUrl` وعيّن له خانة `tts`. لا يمكن لمساحات العمل إضافة عناوين TTS مخصصة في إعدادات النماذج.

### ASR (تحويل الكلام إلى نص)

```bash
# OpenAI Whisper
ASR_OPENAI_API_KEY=
ASR_OPENAI_BASE_URL=       # تجاوز اختياري

# Qwen ASR
ASR_QWEN_API_KEY=
ASR_QWEN_BASE_URL=         # تجاوز اختياري

# Azure ASR
ASR_AZURE_API_KEY=
ASR_AZURE_BASE_URL=https://{region}.api.cognitive.microsoft.com

# FunASR (محلي، لا يحتاج إلى مفتاح)
ASR_FUNASR_BASE_URL=http://localhost:8000/v1

# Lemonade ASR (محلي، لا يحتاج إلى مفتاح)
ASR_LEMONADE_BASE_URL=http://localhost:13305/v1
```

شغّل خدمة FunASR المتوافقة مع OpenAI باستخدام `funasr-server --device cuda`. تستقبل ملفات WAV على `/v1/audio/transcriptions` وتدعم SenseVoiceSmall وParaformer وFun-ASR-Nano.

ASR المدمج في المتصفح لا يحتاج إلى إعدادات خادم.

لاستخدام عنوان ASR آخر متوافق مع OpenAI، أعلنه في `openmaic.yml` بالإعداد المسبق `openai-whisper` و`baseUrl` الخاص به، وعيّن له خانة `asr`. لا يمكن لمساحات العمل إضافة عناوين ASR مخصصة في إعدادات النماذج:

```yaml title="openmaic.yml"
providers:
  my-asr:
    preset: openai-whisper
    apiKey: ${MY_ASR_API_KEY}
    baseUrl: https://asr.example.com/v1

slots:
  asr: my-asr:whisper-1
```

### موفرو توليد الصور

يستخدم موفرو الصور متغيرات `IMAGE_<PROVIDER>_API_KEY`، مع خيار `IMAGE_<PROVIDER>_BASE_URL`. البادئات المدعومة تشمل:

`IMAGE_OPENAI_`، `IMAGE_SEEDREAM_`، `IMAGE_QWEN_IMAGE_`، `IMAGE_NANO_BANANA_`، `IMAGE_MINIMAX_`، `IMAGE_GROK_` و `IMAGE_LEMONADE_`.

Lemonade خدمة محلية ولا تحتاج إلى مفتاح API:

```bash
IMAGE_LEMONADE_BASE_URL=http://localhost:13305/v1
```

لا يحتاج ComfyUI Image إلى مفتاح API. يعمل على شبكتك الخاصة، لذا يضبطه النشر: أعلنه في `openmaic.yml` بعنوان خادم ComfyUI وعيّن له خانة `image`.

```yaml title="openmaic.yml"
providers:
  comfyui:
    preset: comfyui-image
    baseUrl: http://host.docker.internal:8188

slots:
  image: comfyui
```

ضع ملفات JSON لسير العمل المصدّرة بصيغة API في مجلد `public/` الخاص بـ OpenMAIC. يجب أن تطابق أسماء الملفات `comfyui-*.json` أو تحتوي على `workflow`؛ يكتشف OpenMAIC هذه الملفات تلقائيًا ويعرضها كسير عمل. مع Docker، أضف سير العمل قبل بناء الصورة أو اربط ملف سير عمل منفردًا في `/app/public/` داخل الحاوية. بما أن المزود مُعلن من النشر، فلا يحتاج خادم ComfyUI على المضيف أو على شبكة خاصة إلى `ALLOW_LOCAL_NETWORKS`.

### موفرو توليد الفيديو

يستخدم موفرو الفيديو متغيرات `VIDEO_<PROVIDER>_API_KEY`، مع خيار `VIDEO_<PROVIDER>_BASE_URL`. البادئات المدعومة تشمل:

`VIDEO_SEEDANCE_`، `VIDEO_KLING_`، `VIDEO_VEO_`، `VIDEO_SORA_`، `VIDEO_MINIMAX_`، `VIDEO_GROK_` و `VIDEO_HAPPYHORSE_`.

### تحليل المستندات والوسائط

تعتمد صيغ المواد التعليمية على المحلل المختار. حاليًا يدعم النصوص، PDF، مستندات Office، الصور، وبعض صيغ الصوت والفيديو؛ تختلف الصيغ المدعومة والقدرات حسب الموفر.

```bash
# MinerU ذاتي الاستضافة
PDF_MINERU_BASE_URL=http://localhost:8888

# MinerU backend اختياري ذاتي الاستضافة
PDF_MINERU_BACKEND=pipeline

# MinerU Cloud
PDF_MINERU_CLOUD_API_KEY=
PDF_MINERU_CLOUD_BASE_URL=https://mineru.net/api/v4

# AliDocMind (يستخدم AccessKey من Alibaba Cloud بدلاً من مفتاح API منفصل)
ALIDOCMIND_ACCESS_KEY_ID=
ALIDOCMIND_ACCESS_KEY_SECRET=
ALIDOCMIND_BASE_URL=       # تجاوز اختياري
```

`unpdf` مدمج في OpenMAIC ويستخدم لتحليل PDF الأساسي. لتحليل مستندات Office، الصور، أو المواد التي تحتاج إلى OCR، جداول، معادلات أو تحليل تخطيط، يجب اختيار موفر MinerU أو AliDocMind المتوافق.

يدعم AliDocMind تحليل PDF، DOCX، PPTX، XLSX، بالإضافة إلى PNG، JPG/JPEG، BMP، GIF. حاليًا، يدعم تحليل الوسائط الصوتية والفيديو فقط عبر AliDocMind: صيغ الفيديو MP4، MOV، AVI، MKV، WMV، وصيغ الصوت MP3، WAV، AAC؛ لا يدعم M4A.

### البحث عبر الإنترنت

اضبط موفري البحث Tavily، Exa، Bocha، Brave، Baidu، SearXNG أو MiniMax:

```bash
TAVILY_API_KEY=
TAVILY_BASE_URL=           # تجاوز اختياري

EXA_API_KEY=
EXA_BASE_URL=https://api.exa.ai  # تجاوز اختياري

BOCHA_API_KEY=
BOCHA_BASE_URL=            # تجاوز اختياري

BAIDU_API_KEY=
BAIDU_BASE_URL=https://qianfan.baidubce.com  # تجاوز اختياري

# SearXNG ذاتي الاستضافة، لا يحتاج إلى مفتاح API
SEARXNG_BASE_URL=

WEB_SEARCH_MINIMAX_API_KEY=
WEB_SEARCH_MINIMAX_BASE_URL=https://api.minimaxi.com  # تجاوز اختياري
```

لا يحتاج Brave وSearXNG إلى مفتاح API. لا يوجد مفتاح للبحث على الويب في كل عملية توليد: يعمل متى حُلت خانة `webSearch` لمساحة العمل، وإيقافه (`webSearch: null` في `openmaic.yml`، أو بمفتاح البحث في **الإعدادات ← إعدادات نماذج الدورة**) يؤثر في عمليات التوليد اللاحقة لتلك المساحة. يُقدَّم البحث على الويب في Grok عبر أداة البحث في Grok LLM، وليس مزود بحث مستقلًا.

### server-providers.yml

مهمل لصالح `openmaic.yml`. عند وجود الملفين معًا، يضبط `openmaic.yml` وحده النماذج.

بدلاً من متغيرات البيئة، يمكنك وضع إعدادات موفري الخادم المسجلين في الكود داخل ملف `server-providers.yml` في جذر المشروع. يُحمّل الملف عند بدء الخادم، والبنية تطابق تصنيفات متغيرات البيئة:

```yaml title="server-providers.yml"
providers:
  openai:
    apiKey: sk-...
    baseUrl: https://api.openai.com/v1
    models:
      - gpt-5.5
  anthropic:
    apiKey: sk-ant-...

tts:
  doubao-tts:
    apiKey: appId:accessKey

asr:
  openai-whisper:
    apiKey: sk-...

pdf:
  mineru:
```
