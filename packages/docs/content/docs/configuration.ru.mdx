У OpenMAIC три источника конфигурации, и у каждого одна задача:

| Источник | Кто пишет | Что содержит | Когда применяется |
| --- | --- | --- | --- |
| `openmaic.yml` | Администратор | Провайдеры, назначения слотов и политика для AI-моделей | При запуске (после изменения нужен перезапуск) |
| Настройки моделей в веб-приложении | Пользователи рабочего пространства | Провайдеры и назначения, которые `openmaic.yml` оставляет открытыми; хранятся в базе данных | Сразу |
| Переменные окружения (`.env.local`, секрет контейнера) | Администратор | Секреты, на которые ссылается `openmaic.yml`, и все остальные серверные опции | При запуске |

Все переменные окружения необязательны, кроме `DATABASE_URL` (см. [Развёртывание](./deployment.mdx)). Полный список — в [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/main/.env.example), заготовка конфигурации моделей — в [`openmaic.example.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/main/openmaic.example.yml), идентификаторы пресетов и моделей — в разделе [Поддерживаемые модели](./supported-models.mdx).

В прежних версиях модели настраивались только через переменные окружения провайдеров, `server-providers.yml`, `DEFAULT_MODEL` и `MODEL_ROUTES`. Кроме `MODEL_ROUTES`, всё это пока работает, но устарело; см. [Миграция со старой конфигурации](#миграция-со-старой-конфигурации).

## Модели и провайдеры

### Основные понятия

- **Провайдер (provider)** — учётная запись, к которой может обращаться сервер: ключ OpenAI, Token Plan MiniMax, собственный OpenAI-совместимый сервер и т. п. У каждого провайдера есть выбранный вами id и **пресет (preset)**, который определяет вендора и покрываемые возможности.
- **Слот (slot)** — место в продукте, где используется AI: план курса, содержимое слайдов, синтез речи, веб-поиск и т. д. Слоты образуют по одному дереву на каждую возможность; слот без назначения следует за родителем.
- **Назначение (assignment)** — какой провайдер и какая модель используются в слоте (`provider:model`), при необходимости с параметрами вызова и резервной моделью, или `null`, чтобы выключить слот.

Возможность доступна ровно тогда, когда её слот разрешается в назначение. Отдельных переключателей нет.

### openmaic.yml

Сервер читает `openmaic.yml` из каталога, в котором он запущен (корень репозитория; `/app` в Docker-образе). Чтобы использовать другой путь, задайте `OPENMAIC_CONFIG`; относительный путь разрешается от того же каталога, и файл в этом случае обязан существовать. Без файла сервер использует настройки веб-приложения и, пока они заданы, [устаревшие переменные](#миграция-со-старой-конфигурации).

Файл читается один раз при запуске: после изменения перезапустите сервер. Перед запуском файл проверяется целиком. Незаданная `${VAR}`, неизвестный пресет или слот, ссылка на необъявленного провайдера или провайдер без нужной слоту возможности останавливают сервер, и каждая проблема выводится с указанием места:

```text
[boot] Invalid server configuration; the server will not start: Invalid model configuration in /app/openmaic.yml:
  - providers.openai.apiKey: environment variable OPENAI_API_KEY is not set
  - slots.course.outlines: unknown slot
```

Не записывайте секреты в сам файл: ссылайтесь на них через `${VAR}` и задавайте переменную в окружении. Значения из переменных никогда не выводятся в этих сообщениях.

### Полный пример

```yaml title="openmaic.yml"
providers:
  # <id провайдера>: строчные буквы, цифры и дефисы
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}      # читается из окружения при запуске
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  openai-image:                    # тот же ключ для генерации изображений
    preset: openai-image
    apiKey: ${OPENAI_API_KEY}
  minimax:                         # Token Plan: чат, изображения, видео, TTS, поиск
    preset: minimax
    apiKey: ${MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}
  local:                           # любой OpenAI-совместимый сервер
    preset: openai-compatible
    baseUrl: http://ollama:11434/v1
    models: [qwen3:8b]

slots:
  llm: openai:gpt-5.5              # по умолчанию для всех чат-слотов ниже
  course.outline:
    model: anthropic:claude-sonnet-4-6
    fallback: openai:gpt-5.4-mini  # один повтор при сбое, допускающем повтор
  course.content.slide:
    model: minimax:MiniMax-M3
    thinking: { enabled: false }
    fallback: minimax:MiniMax-M2.7
  classroom: local:qwen3:8b        # id модели может содержать двоеточия
  agent:
    model: openai:gpt-5.5          # нужен вызов инструментов
    api: openai-completions
  tts: minimax:speech-2.8-turbo
  image: openai-image:gpt-image-2
  webSearch: tavily                # только провайдер: его модель по умолчанию
  video: null                      # выключено и заблокировано

policy:
  allowWorkspaceProviders: false   # пользователи не могут добавлять своих провайдеров
```

С этим файлом каждый перечисленный слот зафиксирован для всех пользователей. Не указанный в файле чат-слот, например `course.agents`, следует за родителем (`llm`); не указанный корень возможности, например `asr` или `document`, остаётся ненастроенным. Пользователи могут назначить и те и другие в настройках моделей, выбирая из объявленных провайдеров.

### Провайдеры

Каждая запись в `providers` объявляет одного провайдера. Ключ — его id, по которому на него ссылаются слоты: от 1 до 63 строчных букв, цифр и дефисов, первым символом должна быть буква или цифра.

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `preset` | Да | Встроенный пресет провайдера. См. [Поддерживаемые модели → Пресеты](./supported-models.mdx#пресеты). |
| `apiKey` | Обычно | API-ключ. Сервисы без ключа (локальные серверы, Brave, SearXNG, unpdf) его не указывают. |
| `baseUrl` | Для некоторых пресетов | Адрес вместо собственного адреса пресета. Обязателен для `openai-compatible`, `azure`, `searxng` и `mineru`. |
| `models` | Нет | Идентификаторы чат-моделей, которые предлагает этот провайдер; их показывают настройки моделей. Для `openai-compatible` это единственный список в настройках. Он не ограничивает, какие модели можно указать в `slots`. |
| `proxy` | Нет | URL HTTP-прокси для запросов этого провайдера. |
| `credentials` | Для некоторых пресетов | Пара ключей для сервисов, которые не используют один ключ. AliDocMind принимает `accessKeyId` и `accessKeySecret`. |
| `options` | Нет | Несекретные настройки, специфичные для провайдера, например `backend` для `voxcpm-tts`. Имена состоят из букв, цифр, `_` и `-`; значения — строки, числа или булевы значения (без вложенных словарей и списков), `${VAR}` поддерживается. Настройки моделей показывают options, поэтому никогда не храните в них ключи. Только для развёртывания: настройки моделей не могут их задавать. |

Большинство пресетов покрывают одну возможность и соответствуют встроенным реестрам: пресет `openai` — только чат, а изображения, синтез и распознавание речи OpenAI — это пресеты `openai-image`, `openai-tts` и `openai-whisper`. Объявляйте по одному провайдеру на возможность и ссылайтесь на одну и ту же `${VAR}`, если один ключ покрывает несколько возможностей. **Пресеты Token Plan** (`minimax`, `tokendance`, `volcengine-ark`, `kimi-coding-plan`) покрывают несколько возможностей одним ключом, каждую — по собственному адресу тарифа. `baseUrl` у провайдера заменяет адрес для всех возможностей, которые он покрывает, поэтому задавайте `baseUrl` для Token Plan, только если вместе с ним переезжают все его возможности.

Amazon Bedrock (`preset: bedrock`) подписывает запросы цепочкой учётных данных AWS на сервере (окружение, профиль или роль) и берёт регион из `BEDROCK_REGION`, `AWS_REGION` или `AWS_DEFAULT_REGION`; `apiKey` — необязательный bearer-токен.

### Слоты

| Слот | Возможность | Родитель | За что отвечает |
| --- | --- | --- | --- |
| `llm` | chat | — | Чат-модель по умолчанию: все чат-вызовы, не покрытые слотами ниже, включая шаги безбраузерного API `/api/generate-classroom` без собственного слота |
| `course.research` | chat | `llm` | Переформулирование запроса веб-поиска при исследовании курса |
| `course.outline` | chat | `llm` | Планы сцен |
| `course.agents` | chat | `llm` | Профили агентов — преподавателя и одноклассников |
| `course.content` | chat | `llm` | Содержимое сцен для типов без собственного слота |
| `course.content.slide` | chat | `course.content` | Сцены-слайды |
| `course.content.quiz` | chat | `course.content` | Сцены-тесты |
| `course.content.interactive` | chat | `course.content` | Интерактивные сцены |
| `course.content.pbl` | chat | `course.content` | Сцены проектного обучения (PBL) |
| `course.actions` | chat | `llm` | Действия сцен (что агенты говорят и делают в каждой сцене) |
| `classroom` | chat | `llm` | Чат на занятии, проверка тестов и среда выполнения PBL |
| `agent` | chat | `llm` | Агент Pro workbench. **Требует вызова инструментов.** Также принимает `api` и `contextWindow` |
| `agent.title` | chat | `agent` | Заголовки сессий Pro. Настраивается только в `openmaic.yml`; в настройках моделей не отображается |
| `tts` | tts | — | Синтез речи |
| `asr` | asr | — | Распознавание речи (голосовой ввод, расшифровка аудио и видео) |
| `image` | image | — | Генерация изображений |
| `video` | video | — | Генерация видео |
| `webSearch` | webSearch | — | Веб-поиск |
| `document` | document | — | Сервис разбора документов (MinerU, MinerU Cloud, AliDocMind). Встроенному извлечению текста из PDF сервис не нужен |

Как разрешается слот:

- Разрешение начинается со слота вызова и поднимается к корню возможности. Побеждает первое найденное назначение, поэтому назначение родителя служит значением по умолчанию для всего поддерева. Изменение родителя меняет всех потомков без собственного назначения.
- На каждом слоте `openmaic.yml` проверяется раньше настроек моделей рабочего пространства.
- `null` останавливает подъём: слот и все слоты под ним без собственного назначения выключены.
- Если до корня назначение не найдено, возможность не настроена. Вызовы завершаются ошибкой с именем слота; перехода к какому-либо вендору нет.
- Требования принадлежат объявившему их слоту и проверяются на модели, в которую он разрешается, — назначенной или унаследованной. `agent` требует вызова инструментов; если встроенный каталог говорит, что модель этого не умеет, агент отказывается работать, а не обходится как-нибудь. Модель, которой нет в каталоге, допускается. У `agent.title` требований нет, так что для него подойдёт модель поменьше.

### Назначения

У назначения четыре формы:

```yaml
slots:
  llm: openai:gpt-5.5            # провайдер:модель
  webSearch: tavily              # только провайдер: его модель по умолчанию
  course.outline:                # объект с параметрами
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
    thinking: { effort: low }
  video: null                    # выключено
```

Объектная форма принимает:

| Поле | Назначение |
| --- | --- |
| `model` | Обязательно. `провайдер:модель` или, вне чат-слотов, только `провайдер`. |
| `fallback` | Модель для одного повтора, в той же форме. Только для слотов языковых моделей; см. [Резервные модели](#резервные-модели). |
| `thinking` | Параметры рассуждения для чат-моделей: `enabled` (true/false), `mode` (`default`, `disabled`, `enabled`, `auto`), `effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`), `level` (`minimal`, `low`, `medium`, `high`), `budgetTokens`, `excludeReasoningOutput`. Адаптер каждого провайдера применяет то, что поддерживает его API. |
| `api` | Только `agent`: транспортный диалект, `openai-completions` (по умолчанию) или `openai-responses`. |
| `contextWindow` | Только `agent`: размер контекстного окна для сжатия, если он должен быть меньше значения из каталога. |

Слот `agent` не должен задавать `thinking.effort`: его транспорт с вызовом инструментов не может совмещать силу рассуждения с функциями-инструментами.

### Ссылки только на провайдера

Ссылка без `:model` означает модель провайдера по умолчанию: ту, что Token Plan рекомендует для этой возможности, иначе модель по умолчанию из встроенного реестра. У сервисов поиска и документов чаще всего нет выбора модели, поэтому обычная форма — `webSearch: tavily` или `document: mineru-cloud`. Чат-слоты всегда указывают модель; `llm: openai` отклоняется при запуске.

### Резервные модели

Резервные модели применяются только к слотам языковых моделей: `llm` и всем слотам под ним. `fallback` в слоте `tts`, `asr`, `image`, `video`, `webSearch` или `document` отклоняется — при запуске для `openmaic.yml` и при сохранении в настройках моделей.

`fallback` слота используется один раз, если вызов основной модели после её собственных повторов завершился сбоем, допускающим повтор: временная ошибка SDK, таймаут, сетевая ошибка, исчерпание квоты (429), нехватка мощности (503) или пустой ответ. Отказы по соображениям безопасности контента и другие ошибки 4xx к резервной модели не приводят. Резервная модель работает и для обычных, и для потоковых вызовов и использует параметры `thinking` слота.

Резервная модель — часть назначения и наследуется вместе с ним: `course.content.slide` без собственного назначения использует модель и резервную модель `course.content`. Слот с требованием не переходит на резервную модель, которая ему не соответствует.

### Как выключить возможность

Запишите `null` в её слот. `video: null` выключает генерацию видео для всех рабочих пространств и блокирует её в выключенном состоянии; `course.content.pbl: null` выключает генерацию сцен PBL, а остальная часть `course.content` продолжает работать. Вызов выключенного слота сразу завершается ошибкой, а медиа-маршруты отвечают `403`, не переключаясь на другого вендора.

### Блокировки и настройки моделей

Всё, что записано в `slots` файла `openmaic.yml`, **заблокировано**: настройки моделей помечают это как **Set by the server** (задано сервером) и не позволяют изменить. Блокируются только записанные слоты. Рабочее пространство может назначить модель потомку заблокированного слота и тем самым переопределить значение для его поддерева. Чтобы зафиксировать всё поддерево, запишите каждый его слот.

Настройки моделей в веб-приложении читают и изменяют то же дерево для текущего рабочего пространства:

- **Token Plan**: подключение тарифа добавляет его провайдера с ключом и заполняет ещё не назначенные слоты, которые тариф рекомендует. Отключение удаляет провайдера; слоты, которые его использовали, снова следуют родителям.
- **Сервисы моделей**: по вкладке на возможность (языковые модели, изображения, видео, синтез речи, распознавание речи, разбор документов, веб-поиск) со списком сервисов. Провайдеры из `openmaic.yml` показаны только для чтения и без сведений о ключах. Сервис, настроенный рабочим пространством, становится его провайдером: ключ только записывается и отображается лишь маской вида `…abcd`, собственный адрес возможен только для языковых моделей (Azure Speech использует официальный адрес своего региона, например `https://<region>.tts.speech.microsoft.com`), а самостоятельно размещённые сервисы и пары ключей настраиваются в `openmaic.yml`. Кнопки проверки проверяют сохранённого провайдера на сервере.
- **Настройка моделей курса**: основная модель — это слот `llm`, каждый этап конвейера — свой слот (следовать основной модели значит не иметь своего назначения); переключатели изображений, видео, речи, поиска и расшифровки ставят слот в `null`. Слоты из `openmaic.yml` показаны, но изменить их нельзя.

Настройки провайдеров, сохранённые браузером в прежних версиях (провайдеры с ключами и базовыми URL, выбранная модель, подключение Token Plan и выбор для каждой возможности), один раз импортируются в рабочее пространство. Импорт никогда не заменяет существующие настройки рабочего пространства и слоты, заблокированные `openmaic.yml`, и пропускает записи, отклонённые политикой или проверкой. После ответа 2xx из браузера удаляется только то, что теперь хранит рабочее пространство: каждая пропущенная сервером запись (собственный адрес медиасервиса, пресет, недоступный рабочему пространству, id провайдера, объявленный развёртыванием, ...) остаётся в этом браузере вместе с ключом, больше никуда не отправляется и показывается с причиной в разделе «Настройки → Сервисы моделей» (уведомление приходит один раз), пока её не настроят заново или не удалят. Провайдер Azure Speech с официальным адресом региона импортируется. После 400 предложение отклонено целиком: оно не отправляется повторно, а его записи вместе с ключами сохраняются в этом браузере и перечисляются вместе с пропущенными. Нечитаемое предложение удаляется; для повторной попытки оно остаётся в браузере только при 401, 404, 409, 5xx или сетевой ошибке. Явно выключенный голосовой ввод становится `asr: null`, а озвучка, изображения или видео, выключенные при настроенном рабочем провайдере, становятся `tts: null`, `image: null` или `video: null` (слот, заблокированный `openmaic.yml`, остаётся как есть). Заново вручную нужно настроить: модели по этапам (в настройке моделей курса или в `slots` файла `openmaic.yml`), параметры рассуждения (`thinking` у слота), собственных провайдеров синтеза и распознавания речи и пару ключей AliDocMind (в `openmaic.yml`; они остаются в браузере и показываются вместе с пропущенными записями), backend VoxCPM (`options.backend`) и подисточники поиска Baidu (действуют значения сервера по умолчанию). Выключенное исследование не переносится (оно лишь останавливало исследование для курса; чат и агент продолжали искать), как и переключатель, выключенный только по умолчанию: каждая возможность работает, когда её слот разрешается.

Рабочее пространство — это владелец (owner) в смысле [документации по хранению данных](./deployment.mdx): в стандартной конфигурации Docker Compose (однопользовательский режим) рабочее пространство одно, а в многопользовательском развёртывании у каждой учётной записи своё.

### Политика

```yaml
policy:
  allowWorkspaceProviders: false
```

`allowWorkspaceProviders` (по умолчанию `true`) определяет, могут ли рабочие пространства добавлять собственных провайдеров. При `false` пользователи выбирают только среди провайдеров, объявленных в `openmaic.yml`, и только для слотов, которые файл оставляет открытыми. Модель, ключ или адрес, которые запрос указывает сам (устаревшие заголовки `x-model`, `x-api-key`, `x-base-url` и поля провайдера в медиа-маршрутах), тогда игнорируются, а проверка провайдера через заголовки отклоняется. Многопользовательское развёртывание, которое оплачивает всё использование, обычно задаёт этот флаг и блокирует нужные слоты.

### Секреты и OPENMAIC_SECRET_KEY

- Ключи в `openmaic.yml` берутся из окружения через `${VAR}`. Они никогда не сохраняются в базе данных и не отправляются в браузер.
- Ключи, которые рабочее пространство вводит в настройках моделей, хранятся в базе данных, зашифрованные AES-256-GCM секретом экземпляра `OPENMAIC_SECRET_KEY`.
- Если `OPENMAIC_SECRET_KEY` не задан, сервер при первом использовании создаёт случайный секрет в `data/instance-secret.key` (в Docker Compose — внутри тома `openmaic-data`) и дальше использует его.

Храните секрет вместе с резервными копиями базы данных: ключи, сохранённые под утерянным или изменённым секретом, прочитать нельзя, их придётся ввести заново (настройки моделей их отмечают). Задайте `OPENMAIC_SECRET_KEY` явно, если базу данных разделяют несколько экземпляров, или на хостингах без постоянного каталога данных, таких как Vercel; подойдёт любая строка, например вывод `openssl rand -base64 32`.

Без него каталог данных, который не переживает перезапуск (контейнер без тома, временный диск), означает новый секрет при каждом запуске, а несколько реплик создают каждая свой; в рабочем каталоге только для чтения секрет создать нельзя, и сохранение ключа в настройках моделей завершается ошибкой. При запуске сервер предупреждает, если `OPENMAIC_SECRET_KEY` не задан и каталог данных недоступен для записи, а также если в базе данных есть ключи, зашифрованные другим секретом, чем текущий (например, потому что `data/instance-secret.key` потерян); запуск при этом продолжается.

```bash
OPENMAIC_SECRET_KEY=...        # секрет экземпляра для ключей из настроек моделей
OPENMAIC_CONFIG=/etc/openmaic/openmaic.yml   # необязательно: другой путь к openmaic.yml
```

### Что могут добавлять рабочие пространства

Провайдеры в `openmaic.yml` могут быть любыми, что допускает схема. Провайдеры, которых рабочее пространство добавляет в настройках моделей, ограничены сильнее, потому что их адрес и ключ вводит пользователь веб-приложения:

- Amazon Bedrock не предлагается: он подписывал бы запросы собственными учётными данными AWS сервера.
- Нельзя задать `proxy` и пары ключей (`credentials`): пресеты с аутентификацией парой ключей, такие как AliDocMind, доступны только развёртыванию.
- Собственный `baseUrl` разрешён только пресетам с чатом, и такой провайдер обслуживает только чат-слоты. URL не должен содержать учётных данных, строки запроса или фрагмента и должен разрешаться в публичный адрес, если на сервере не задано `ALLOW_LOCAL_NETWORKS=true`. Запросы к нему не следуют перенаправлениям.
- Локальные серверы моделей (Ollama, Lemonade) должны указывать собственный адрес, а не `localhost` по умолчанию из пресета.
- Собственные медиа-, поисковые и документные сервисы (VoxCPM2, FunASR, речь и изображения Lemonade, ComfyUI, SearXNG, собственный MinerU) работают в сети самого сервера и доступны только развёртыванию.
- Провайдеры, выключенные администратором через устаревшую переменную `<CAP>_<VENDOR>_ENABLED=false`, не предлагаются.
- Рабочее пространство не может объявить id провайдера, уже объявленный в `openmaic.yml`.

Чтобы дать пользователям доступ к внутренним сервисам, объявите этих провайдеров в `openmaic.yml`.

### API-клиенты и устаревшие поля запросов

Запросам на генерацию больше не нужно передавать ключи или выбор модели: безбраузерные вызовы API, например `/api/generate-classroom`, разрешаются через те же слоты, что и веб-приложение, для рабочего пространства вызывающего.

Старые заголовки `x-model`, `x-api-key`, `x-base-url`, `x-provider-type`, `x-model-routes`, `x-image-provider`, `x-image-model`, `x-video-provider` и `x-video-model`, а также соответствующие поля тела запроса у маршрутов речи, поиска и документов устарели. Они учитываются, только пока у затрагиваемого слота нет назначения ни в `openmaic.yml`, ни в рабочем пространстве; когда оно появляется, побеждает конфигурация, а слот со значением `null` отклоняет запрос, что бы в нём ни было указано. При `policy.allowWorkspaceProviders: false` они не учитываются вовсе. При первом таком запросе сервер пишет предупреждение в журнал. Их удалят через две минорные версии после выхода описанных выше настроек моделей.

### Миграция со старой конфигурации

Если `openmaic.yml` нет, сервер при запуске преобразует старую конфигурацию и пишет в журнал уведомление об устаревании, а также уведомление по каждой записи, которую не удалось перенести:

| Старая настройка | Становится |
| --- | --- |
| Переменные провайдеров (`OPENAI_API_KEY`, `TTS_MINIMAX_API_KEY`, …) и `server-providers.yml` | Провайдерами развёртывания (только для чтения в настройках моделей). Id провайдера — это id пресета, который совпадает со старым id провайдера, кроме веб-поиска MiniMax (`minimax-search`), веб-поиска Doubao (`doubao-search`) и изображений Lemonade (`lemonade-image`) |
| `<PREFIX>_MODELS` | `models` провайдера |
| `DEFAULT_MODEL` | Назначением `llm` в виде значения по умолчанию, которое рабочее пространство может переопределить (не блокируется). Слот `agent`, как и раньше, остаётся выключенным |
| `MODEL_FALLBACK` | Резервной моделью `DEFAULT_MODEL`. Без `DEFAULT_MODEL` отбрасывается с уведомлением |
| Первый настроенный провайдер TTS, ASR, изображений, видео и документов, а также веб-поиск в прежнем порядке приоритета | Назначением этой возможности по умолчанию (провайдера изображений выбирает `DEFAULT_IMAGE_PROVIDER`) |
| `MODEL_ROUTES` | **Не преобразуется.** Сервер отказывается запускаться (см. ниже) |
| `<CAP>_<VENDOR>_ENABLED=false` | По-прежнему действует: провайдер остаётся выключенным, кто бы его ни назначил |

Если `openmaic.yml` существует, переменные провайдеров, `server-providers.yml`, `DEFAULT_MODEL`, `MODEL_FALLBACK` и `MODEL_ROUTES` не участвуют в разрешении моделей, о чём выводится уведомление. `<CAP>_<VENDOR>_ENABLED=false` продолжает действовать; чтобы выключить возможность, лучше задайте её слоту `null`.

**Переменные окружения.** До:

```bash
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DEFAULT_MODEL=openai:gpt-5.5
MODEL_FALLBACK=anthropic:claude-sonnet-4-6
TTS_MINIMAX_API_KEY=...
TAVILY_API_KEY=tvly-...
```

После (ключи остаются в окружении):

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  minimax-tts:
    preset: minimax-tts
    apiKey: ${TTS_MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}

slots:
  llm:
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
  tts: minimax-tts
  webSearch: tavily
```

Затем удалите `DEFAULT_MODEL` и `MODEL_FALLBACK`. Переменные провайдеров можно оставить как источник ссылок `${VAR}`. В отличие от преобразованного `DEFAULT_MODEL`, записанный здесь `llm` заблокирован; чтобы рабочие пространства могли выбирать сами, не указывайте его в `slots`. И в отличие от преобразования, `agent` теперь следует за `llm`: чтобы агент Pro оставался выключенным, запишите `agent: null`.

**server-providers.yml.** До:

```yaml title="server-providers.yml"
providers:
  azure:
    apiKey: ...
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
pdf:
  alidocmind:
    accessKeyId: ...
    accessKeySecret: ...
web-search:
  searxng:
    baseUrl: http://searxng:8080
```

После:

```yaml title="openmaic.yml"
providers:
  azure:
    preset: azure
    apiKey: ${AZURE_OPENAI_API_KEY}
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
  alidocmind:
    preset: alidocmind
    credentials:
      accessKeyId: ${ALIDOCMIND_ACCESS_KEY_ID}
      accessKeySecret: ${ALIDOCMIND_ACCESS_KEY_SECRET}
  searxng:
    preset: searxng
    baseUrl: http://searxng:8080

slots:
  llm: azure:my-deployment
  document: alidocmind
  webSearch: searxng
```

Каждый раздел `server-providers.yml` превращается в провайдеров с соответствующим пресетом (`providers` → чат-пресеты, `tts`, `asr`, `pdf` → документы, `image`, `video`, `web-search`), а `accessKeyId`/`accessKeySecret` переходят в `credentials`.

**MODEL_ROUTES.** Сервер, в котором задан `MODEL_ROUTES` без `openmaic.yml`, не запускается:

```text
MODEL_ROUTES does not carry over to the model configuration: write the per-stage models as slots in openmaic.yml (or the file named by OPENMAIC_CONFIG) and remove MODEL_ROUTES
```

Маршруты по этапам не соответствуют слотам один к одному, поэтому не преобразуются. Перепишите каждый маршрут как слот, к которому относится его этап:

| Этап `MODEL_ROUTES` | Слот |
| --- | --- |
| `web-search-query-rewrite` | `course.research` |
| `scene-outlines-stream` | `course.outline` |
| `agent-profiles` | `course.agents` |
| `scene-content` | `course.content` |
| `scene-content:slide`, `:quiz`, `:interactive`, `:pbl` | `course.content.slide`, `.quiz`, `.interactive`, `.pbl` |
| `scene-actions` | `course.actions` |
| `chat-adapter`, `quiz-grade`, `pbl-v2-runtime` и его варианты `:instructor`, `:open-task`, `:evaluate`, `:simulator` | `classroom` |
| `generate-classroom` | `llm` |
| `maic-agent-driver` | `agent` |
| `conversation-title` | `agent.title` |

Если несколько этапов делят один слот, назначьте ему одну модель, которую они должны использовать. `thinking` маршрута переходит в `thinking` слота, а `api` и `contextWindow` маршрута `maic-agent-driver` — в слот `agent`. До:

```bash
DEFAULT_MODEL=openai:gpt-5.5
MODEL_ROUTES='{"scene-outlines-stream":"anthropic:claude-sonnet-4-6","scene-content:slide":{"model":"openai:gpt-5.4","thinking":{"effort":"low"}},"maic-agent-driver":{"model":"openai:gpt-5.5","api":"openai-completions"}}'
```

После:

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}

slots:
  llm: openai:gpt-5.5
  course.outline: anthropic:claude-sonnet-4-6
  course.content.slide:
    model: openai:gpt-5.4
    thinking: { effort: low }
  agent:
    model: openai:gpt-5.5
    api: openai-completions
```

Затем удалите `MODEL_ROUTES`, `DEFAULT_MODEL` и `MODEL_FALLBACK`.

**Docker.** Смонтируйте файл рядом с приложением, а ключи оставьте в `.env.local`:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

## ACCESS_CODE — пароль для всего сайта

Для общих деплоев (внутренние демо, классы) можно задать пароль, чтобы посетители вводили его перед входом:

```bash
ACCESS_CODE=your-secret-code
```

Используйте длинное случайное значение (не менее 16 символов) — этот код является единственным секретом, защищающим деплой. После успешной проверки в HTTP-only cookie сохраняется подписанный токен на 7 дней; срок действия проверяется на сервере, поэтому после истечения код нужно ввести снова. Частота проверок ограничивается только при `TRUST_PROXY_HEADERS=true` за доверенным обратным прокси, который перезаписывает `x-forwarded-for` / `x-real-ip`: по клиентам (10 попыток за 60 секунд), и успешная проверка сбрасывает счётчик этого клиента. Без доверенного прокси приложение не может отнести запрос к конкретному клиенту, поэтому ограничения нет — защита обеспечивается длиной и случайностью кода. Оставьте пустым для отключения.

## Feature flags

Значения `true` или `1` включают функцию; если не указано иное, остальные значения выключают её. Переменные `NEXT_PUBLIC_*` внедряются в клиент при сборке, для их изменения нужна пересборка:

```bash
# MAIC Editor (Pro режим)
NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true

# Pi runtime включён по умолчанию; раскомментируйте следующую строку для возврата к прежнему пути
# NEXT_PUBLIC_PI_CHAT_ENABLED=false

# Ссылки на материалы PPT и интерактивных сцен в режиме Pi (флаг времени сборки; режим редактирования не затрагивается)
NEXT_PUBLIC_COURSEWARE_REFERENCE_ENABLED=true

# Профессиональное образование (серверный флаг)
OPENMAIC_ENABLE_VOCATIONAL=true

# Отображение UI для тестов профессионального образования
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true

# Включение видеоэкспорта
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true

# Экспериментальный импорт PPTX
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true
```

Pi runtime требует поддержки вызова инструментов/функций моделью. Если выбранная модель или провайдер не поддерживает вызов инструментов, установите `NEXT_PUBLIC_PI_CHAT_ENABLED=false` (или `0`) и пересоберите приложение, чтобы использовать прежний путь чата.

В Docker Compose файл `.env.local` загружается через `env_file` во время выполнения и не используется для подстановки аргументов сборки. Пересоберите приложение с явным значением переменной, как показано ниже. Изменение только окружения запущенного контейнера не меняет путь чата, выбранный при сборке клиента и сервера.

```bash
NEXT_PUBLIC_PI_CHAT_ENABLED=false docker compose up -d --build openmaic
```

Импорт PPTX пока экспериментален, результаты парсинга не интегрированы полностью в поток данных классов. Все `NEXT_PUBLIC_*` — флаги сборки, в Docker их нужно передавать как build args, нельзя просто задавать в runtime env vars.

Дополнительные параметры сервера можно задать через env vars:

## Устаревшие переменные окружения провайдеров

Эти переменные и `server-providers.yml` — конфигурация прежних версий. Они продолжают работать без `openmaic.yml` (см. [Миграция со старой конфигурации](#миграция-со-старой-конфигурации)), но устарели и будут удалены через две минорные версии после выхода настроек моделей. С `openmaic.yml` используйте их только как источник ссылок `${VAR}`. `DEFAULT_MODEL` и `MODEL_FALLBACK` описаны в разделе о миграции; `MODEL_ROUTES` больше не читается.

### LLM провайдеры

Облачные провайдеры обычно используют три переменные: API key, base URL и список моделей. Обычно требуется только API key, base URL и список моделей — опциональны. Azure OpenAI требует указания endpoint ресурса, Ollama и Lemonade API key не требуют.

```bash
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=                # опциональное переопределение base URL
OPENAI_MODELS=                  # опциональный белый список моделей через запятую
```

| `GOOGLE_`           | Google Gemini                        |
| `DEEPSEEK_`         | DeepSeek                             |
| `QWEN_`             | Alibaba Qwen                        |
| `KIMI_`             | Moonshot Kimi                      |
| `MINIMAX_`          | MiniMax (по умолчанию Anthropic-совместимый endpoint) |
| `GLM_`              | Zhipu GLM                          |
| `SILICONFLOW_`      | SiliconFlow                        |
| `DOUBAO_`           | Doubao (ByteDance)                 |
| `OPENROUTER_`       | OpenRouter                        |
| `GROK_`             | xAI Grok                          |
| `TENCENT_`          | Tencent Hunyuan                   |

| `OLLAMA_`           | Ollama (локально)                 |
| `LEMONADE_`         | Lemonade (локально)               |

Azure OpenAI использует deployment name в качестве ID модели:

```bash
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_BASE_URL=https://YOUR-RESOURCE.openai.azure.com/openai
AZURE_OPENAI_MODELS=your-deployment-name
```

Чтобы подключить другой OpenAI-совместимый LLM-сервис, объявите в `openmaic.yml` провайдера `openai-compatible` с его `baseUrl` и `models` или добавьте его кнопкой **Добавить провайдера** в **Настройки → Сервисы моделей → Языковые модели**.

### Локальные модели (Ollama и Lemonade)

Ollama и Lemonade не требуют API key; base URL локального сервиса нужно указывать в конфигурации сервера, чтобы пройти проверку SSRF:

```bash
OLLAMA_BASE_URL=http://localhost:11434/v1
# LEMONADE_BASE_URL=http://localhost:13305/v1
```

Для ограничения доступных моделей можно использовать `OLLAMA_MODELS` или `LEMONADE_MODELS` с белым списком моделей.

### TTS провайдеры

Серверные TTS провайдеры используют `TTS_<PROVIDER>_API_KEY` и опциональный `TTS_<PROVIDER>_BASE_URL`.

```bash
# Doubao TTS (Volcengine Seed-TTS, нативный MP3)
TTS_DOUBAO_API_KEY=appId:accessKey
TTS_DOUBAO_BASE_URL=       # опциональное переопределение

# Qwen TTS
TTS_QWEN_API_KEY=
TTS_QWEN_BASE_URL=         # опциональное переопределение

# Любой OpenAI-совместимый TTS endpoint
TTS_OPENAI_API_KEY=
TTS_OPENAI_BASE_URL=

# VoxCPM2 (self-hosted TTS с клонированием голоса, см. отдельную страницу VoxCPM2)
TTS_VOXCPM_BASE_URL=http://localhost:8000
```

Поддерживаемые TTS префиксы: `TTS_OPENAI_`, `TTS_AZURE_`, `TTS_GLM_`, `TTS_QWEN_`, `TTS_MINIMAX_`, `TTS_DOUBAO_`, `TTS_ELEVENLABS_`, `TTS_GOOGLE_`, `TTS_VOXCPM_` и `TTS_LEMONADE_`. Локальные Lemonade TTS и VoxCPM2 не требуют API key. Встроенный в браузер TTS не требует серверной настройки.

Администратор может принудительно отключить TTS провайдер на сервере, установив `TTS_<PROVIDER>_ENABLED=false`. VoxCPM2 (self-hosted TTS + клонирование голоса) описан на отдельной странице [VoxCPM2](./voxcpm.mdx).

Чтобы использовать другой OpenAI-совместимый адрес TTS, объявите в `openmaic.yml` провайдера `openai-tts` с этим `baseUrl` и назначьте ему слот `tts`. Рабочие пространства не могут добавлять собственные адреса TTS в настройках моделей.

### ASR (распознавание речи)

```bash
# OpenAI Whisper
ASR_OPENAI_API_KEY=
ASR_OPENAI_BASE_URL=       # опциональное переопределение

# Qwen ASR
ASR_QWEN_API_KEY=
ASR_QWEN_BASE_URL=         # опциональное переопределение

# Azure ASR
ASR_AZURE_API_KEY=
ASR_AZURE_BASE_URL=https://{region}.api.cognitive.microsoft.com

# FunASR (локально, key не нужен)
ASR_FUNASR_BASE_URL=http://localhost:8000/v1

# Lemonade ASR (локально, key не нужен)
ASR_LEMONADE_BASE_URL=http://localhost:13305/v1
```

Запустите OpenAI-совместимый сервис командой `funasr-server --device cuda`. Он принимает WAV на `/v1/audio/transcriptions` и поддерживает SenseVoiceSmall, Paraformer и Fun-ASR-Nano.

Встроенный в браузер ASR не требует серверной настройки.

Чтобы использовать другой OpenAI-совместимый адрес ASR, объявите его в `openmaic.yml` с пресетом `openai-whisper` и его `baseUrl` и назначьте ему слот `asr`. Рабочие пространства не могут добавлять собственные адреса ASR в настройках моделей:

```yaml title="openmaic.yml"
providers:
  my-asr:
    preset: openai-whisper
    apiKey: ${MY_ASR_API_KEY}
    baseUrl: https://asr.example.com/v1

slots:
  asr: my-asr:whisper-1
```

### Провайдеры генерации изображений

Провайдеры изображений используют `IMAGE_<PROVIDER>_API_KEY` и опциональный `IMAGE_<PROVIDER>_BASE_URL`. Поддерживаемые префиксы:

`IMAGE_OPENAI_`, `IMAGE_SEEDREAM_`, `IMAGE_QWEN_IMAGE_`, `IMAGE_NANO_BANANA_`, `IMAGE_MINIMAX_`, `IMAGE_GROK_` и `IMAGE_LEMONADE_`.

Lemonade — локальный сервис, не требует ключа:

```bash
IMAGE_LEMONADE_BASE_URL=http://localhost:13305/v1
```

ComfyUI Image не требует API-ключа. Он работает в вашей собственной сети, поэтому настраивается развёртыванием: объявите его в `openmaic.yml` с адресом сервера ComfyUI и назначьте ему слот `image`.

```yaml title="openmaic.yml"
providers:
  comfyui:
    preset: comfyui-image
    baseUrl: http://host.docker.internal:8188

slots:
  image: comfyui
```

Поместите JSON рабочего процесса, экспортированный в формате API, в каталог `public/` OpenMAIC. Имена файлов должны соответствовать `comfyui-*.json` или содержать `workflow`; OpenMAIC автоматически находит эти файлы и предлагает их как рабочие процессы. В Docker добавьте рабочий процесс до сборки образа или смонтируйте отдельный файл в `/app/public/` контейнера. Поскольку провайдер объявлен развёртыванием, серверу ComfyUI на хосте или в частной сети не нужен `ALLOW_LOCAL_NETWORKS`.

### Провайдеры генерации видео

Видео провайдеры используют `VIDEO_<PROVIDER>_API_KEY` и опциональный `VIDEO_<PROVIDER>_BASE_URL`. Поддерживаемые префиксы:

`VIDEO_SEEDANCE_`, `VIDEO_KLING_`, `VIDEO_VEO_`, `VIDEO_SORA_`, `VIDEO_MINIMAX_`, `VIDEO_GROK_` и `VIDEO_HAPPYHORSE_`.

### Разбор документов и медиа

Формат материалов зависит от выбранного парсера. Поддерживаются текст, PDF, Office-документы, изображения и часть аудио/видео форматов; возможности зависят от провайдера.

```bash
# MinerU self-hosted
PDF_MINERU_BASE_URL=http://localhost:8888

# MinerU self-hosted опциональный backend
PDF_MINERU_BACKEND=pipeline

# MinerU Cloud
PDF_MINERU_CLOUD_API_KEY=
PDF_MINERU_CLOUD_BASE_URL=https://mineru.net/api/v4

# AliDocMind (использует AccessKey Alibaba Cloud, а не отдельный API key)
ALIDOCMIND_ACCESS_KEY_ID=
ALIDOCMIND_ACCESS_KEY_SECRET=
ALIDOCMIND_BASE_URL=       # опциональное переопределение
```

`unpdf` встроен в OpenMAIC и подходит для базового разбора PDF. Для Office-документов, изображений и материалов с OCR, таблицами, формулами или сложной версткой рекомендуется MinerU или AliDocMind.

AliDocMind поддерживает PDF, DOCX, PPTX, XLSX, а также PNG, JPG/JPEG, BMP, GIF. Текущая поддержка аудио/видео через AliDocMind: видео форматы MP4, MOV, AVI, MKV, WMV; аудио MP3, WAV, AAC. M4A не поддерживается.

### Поисковые провайдеры

Настройте Tavily, Exa, Bocha, Brave, Baidu, SearXNG или MiniMax:

```bash
TAVILY_API_KEY=
TAVILY_BASE_URL=           # опциональное переопределение

EXA_API_KEY=
EXA_BASE_URL=https://api.exa.ai  # опциональное переопределение

BOCHA_API_KEY=
BOCHA_BASE_URL=            # опциональное переопределение

BAIDU_API_KEY=
BAIDU_BASE_URL=https://qianfan.baidubce.com  # опциональное переопределение

# Self-hosted SearXNG, API key не нужен
SEARXNG_BASE_URL=

WEB_SEARCH_MINIMAX_API_KEY=
WEB_SEARCH_MINIMAX_BASE_URL=https://api.minimaxi.com  # опциональное переопределение
```

Brave и SearXNG не требуют API key. У веб-поиска нет переключателя для отдельной генерации: он выполняется, когда слот `webSearch` рабочего пространства разрешается, а его выключение (`webSearch: null` в `openmaic.yml` или переключателем поиска в **Настройки → Настройка моделей курса**) влияет на последующие генерации этого рабочего пространства. Grok использует поиск через инструменты Grok LLM, это не отдельный поисковый провайдер.

### server-providers.yml

Устарело, используйте `openmaic.yml`. Если есть оба файла, модели настраивает только `openmaic.yml`.

Кроме env vars, можно положить конфигурацию зарегистрированных провайдеров в `server-providers.yml` в корне проекта. Файл загружается при старте сервера, структура соответствует категориям env vars:

```yaml title="server-providers.yml"
providers:
  openai:
    apiKey: sk-...
    baseUrl: https://api.openai.com/v1
    models:
      - gpt-5.5
  anthropic:
    apiKey: sk-ant-...

tts:
  doubao-tts:
    apiKey: appId:accessKey

asr:
  openai-whisper:
    apiKey: sk-...

pdf:
  mineru:
    baseUrl: http://localhost:8888
  alidocmind:
    accessKeyId: your-access-key-id
    accessKeySecret: your-access-key-secret

image:
  seedream:
    apiKey: ...

video:
  seedance:
    apiKey: ...

web-search:
  tavily:
    apiKey: tvly-...
  exa:
    apiKey: ...
  searxng:
    baseUrl: http://localhost:8080
```

Переменные окружения по отдельным полям переопределяют соответствующие настройки в YAML. Ключи должны совпадать с зарегистрированными в коде ID провайдеров, например `openai`, `doubao-tts`, `openai-whisper`, `mineru`, `alidocmind`, `seedream`, `seedance`, `exa`, `tavily` или `searxng`. Неизвестные ID нельзя использовать для регистрации кастомных LLM провайдеров.
