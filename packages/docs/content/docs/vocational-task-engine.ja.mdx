---

職業訓練タスクエンジンは、業務上のタスクを中心に教材を生成します。学習者が行う作業、必要な工具、続行・停止の判断、完了の確認を扱い、説明スライド、対話型の手順練習、原理解説、タスクに沿ったチャレンジを組み合わせます。

この機能は実験段階で、既定では無効です。[クイックスタート](./getting-started.mdx)で OpenMAIC と LLM プロバイダーを設定した後、以下のフラグを有効にしてください。

## 適したタスク

作業順序、工具や設備、観察可能な状態、続行・停止・再確認・引き継ぎといった判断を含む具体的なタスクに適しています。設備点検、組立準備、整備前の安全確認などが例です。

大綱プロンプトは、最初にタスクを説明し、同じ業務フローに沿って練習とチャレンジを構成するよう求めます。プランナーは実践に適した内容か判断するよう指示されており、概念説明だけの依頼では通常のスライドや対話型ウィジェットを使う方針です。生成された大綱は確認してください。

## 機能を有効にする

OpenMAIC アプリケーションの `.env.local` に追加します。

```bash
OPENMAIC_ENABLE_VOCATIONAL=true
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true
```

| フラグ                                | 役割                                                   | 反映される時点                                               |
| ------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| `OPENMAIC_ENABLE_VOCATIONAL`          | サーバーで職業訓練の計画と手順練習の生成を許可します。 | 実行時。プロセスの環境変数を変更したらアプリを再起動します。 |
| `NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI` | ホーム画面に実験的なスイッチを表示します。             | ビルド時。本番環境では変更後に再ビルドします。               |

両方とも `true` または `1` を受け付け、未設定では無効です。ローカル設定の変更後は `pnpm dev` を再起動してください。本番環境では公開フラグを `pnpm build` より前に設定し、サーバーフラグをアプリの起動時に渡します。これは OpenMAIC アプリの設定であり、ドキュメントサーバーの設定ではありません。[設定](./configuration.mdx)も参照してください。

スイッチの表示だけではサーバー機能は有効になりません。サーバーフラグと、生成リクエストの `requirements.taskEngineMode` の両方が必要です。サーバーフラグが無効の場合、通常またはインタラクティブモードの生成経路に戻ります。

## 職業訓練レッスンを生成する

1. OpenMAIC のホーム画面を開き、利用するモデルを設定します。
2. **职教任务** と表示される実験的なスイッチをオンにします。
3. 作業内容、学習者の経験、工具、判断箇所、完了条件を説明します。関連教材があれば添付します。
4. 生成する前に **生成前に常にアウトラインを確認** をオンにします（大綱の生成中にその下に表示され、大綱の確認画面にもあります）。その後、大綱を生成して確認し、教室の生成に進みます。オフの場合、大綱ができるとサーバーがそのまま生成を続けます。

入力例：

```text
基本的な工場知識を持つ学習者向けに、電気自動車のバッテリー整備前の
安全確認を練習するレッスンを作成してください。最初にタスクを説明し、
保護具と工具の点検、点検結果の解釈、GO/STOP 判断、引き継ぎ確認を練習します。
作業手順と許容値には添付資料を使ってください。
誤った判断の結果を示し、各練習にリセット機能を用意してください。
```

有効な職業訓練コースは、サーバーが実際に採用したモードを保存し、コース一覧に **Vocational Mode** バッジを表示できます。後続のシーン生成と再試行にも保存済みモードを渡すため、サーバーフラグが有効な間は手順練習を利用できます。バッジは生成モードを示し、すべてのシーンが手順ウィジェットになることを保証するものではありません。

## 学習者が行う練習

`procedural-skill` ウィジェットは、既存の対話型シーンレンダラーで表示する HTML 練習として生成されます。プロンプトは操作可能なコントロール、タスクと工具の説明、順序付き手順、進捗、フィードバック、完了条件、リセットを求めます。少なくとも一つの操作で選択・測定・判断を扱い、誤った選択には作業の中断や再確認などの結果を示す方針です。

完了条件は練習の状態に応じて更新し、リセットでは手順、進捗、フィードバック、コントロールを初期状態に戻すよう指示されています。HTML はモデルが生成するため、使用前に動作を確認してください。軽量な手順練習であり、ウィジェット内の状態はプラットフォームに保存される評価記録や物理シミュレーションではありません。

## トラブルシューティング

| 症状                                       | 確認すること                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| スイッチが表示されない                     | アプリのビルド環境の `NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI` を確認し、本番では再ビルド、開発では再起動します。              |
| スイッチはあるが通常の内容になる           | サーバーの `OPENMAIC_ENABLE_VOCATIONAL` と、送信時にスイッチがオンだったかを確認します。                                   |
| 理論的なテーマで手順練習が生成されない     | 業務の操作や意味のある判断がないテーマでは手順ウィジェットを避けるよう指示されています。具体的なタスクを説明してください。 |
| 操作、リセット、フィードバックに問題がある | 生成されたシーンの HTML を確認し、該当する内容を再生成します。モードの有効化だけではモデルの正確な実装を保証できません。   |

## 実装メモ

[PR #685](https://github.com/THU-MAIC/OpenMAIC/pull/685) で追加された機能は、既存の生成と対話型レンダリング経路を使います。現在の `main` の主な構成は以下のとおりです。

| コンポーネント                                                                                                                                                                                                                        | 責務                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [機能フラグ](https://github.com/THU-MAIC/OpenMAIC/blob/main/lib/config/feature-flags.ts)                                                                                                                                              | `resolveVocationalActive` がリクエストの `taskEngineMode` とサーバーフラグを組み合わせます。表示用フラグは別です。                                                   |
| [大綱ルート](https://github.com/THU-MAIC/OpenMAIC/blob/main/app/api/generate/scene-outlines-stream/route.ts)と[タスクエンジンのプロンプト](https://github.com/THU-MAIC/OpenMAIC/tree/main/lib/prompts/templates/task-engine-outlines) | 職業訓練プランナーを選び、ストリームの完了イベントで実効モードを返します。                                                                                           |
| [シーン内容ルート](https://github.com/THU-MAIC/OpenMAIC/blob/main/app/api/generate/scene-content/route.ts)と[生成パッケージ](https://github.com/THU-MAIC/OpenMAIC/blob/main/packages/%40openmaic/generation/src/scene-generator.ts)   | サーバーの条件を再確認し、タスク項目を内容プロンプトに渡します。無効な手順大綱はフォールバックで図に変更でき、ウィジェット生成側も許可されない手順内容を拒否します。 |
| [プレビューモードのヘルパー](https://github.com/THU-MAIC/OpenMAIC/blob/main/app/generation-preview/vocational-mode.ts)と[シーン生成 Hook](https://github.com/THU-MAIC/OpenMAIC/blob/main/lib/hooks/use-scene-generator.ts)            | 実効モードを保存し、後続シーンと再試行にも渡します。[PR #716](https://github.com/THU-MAIC/OpenMAIC/pull/716) の修正を含みます。                                      |

手順大綱には `procedureType`（`repair`、`assembly`、`inspection`、`operation`、`custom`）、`task`、`tools`、`steps`、`successCriteria`、`errorConsequences` があります。[内容テンプレート](https://github.com/THU-MAIC/OpenMAIC/tree/main/packages/%40openmaic/generation/templates/procedural-skill-content)がこれらを練習ページに変換します。

教師アクションは既存のプラットフォームから iframe へのメッセージ `SET_WIDGET_STATE`、`HIGHLIGHT_ELEMENT`、`ANNOTATE_ELEMENT`、`REVEAL_ELEMENT` を再利用します。手順プロンプトは安定したステップセレクターと、学習者の操作および `SET_WIDGET_STATE` で共有する状態更新経路を求め、`completedSteps` にも対応する方針です。既存のシーンとアクションの契約を利用します。
