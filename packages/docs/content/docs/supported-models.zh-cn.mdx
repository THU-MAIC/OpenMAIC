本页列出开源版 OpenMAIC 内置的服务商和模型。在 [`openmaic.yml`](./configuration.mdx) 中，服务商通过 `preset` 指定其中之一；Web 端的模型设置提供同一份目录。具体可用性还取决于服务商账号、所在区域和服务端配置，服务商的 `models` 列表也可以缩小模型设置中提供的选项。

## 预设

预设是内置的服务商模板：哪家厂商、哪个端点，以及一个账号覆盖哪些能力。`openmaic.yml` 或模型设置中的每个服务商都要指定一个预设。

**单能力预设**使用下面各表中的 provider ID，每种能力一个：`openai` 是 OpenAI 对话，OpenAI 的图像、语音合成和语音识别分别是 `openai-image`、`openai-tts` 和 `openai-whisper`。有三个 ID 因为已被其他预设占用而与 registry ID 不同：MiniMax 联网搜索是 `minimax-search`，豆包联网搜索是 `doubao-search`，Lemonade 图像生成是 `lemonade-image`。

**Token Plan 预设**用一个 key 覆盖多种能力，每种能力使用该套餐自己的端点。在 **设置 → Token Plan** 中接入这类服务商时，还会为套餐推荐了模型且仍未分配的槽位填入模型。

| 预设 | 套餐 | 覆盖能力 |
| --- | --- | --- |
| `minimax` | MiniMax | 对话、图像、视频、TTS、联网搜索 |
| `tokendance` | TokenDance | 对话、图像、视频、TTS、联网搜索 |
| `volcengine-ark` | 火山方舟 Agent Plan | 对话、图像、视频、TTS、联网搜索 |
| `kimi-coding-plan` | Kimi 编程套餐 | 对话、联网搜索、网页抓取 |

在**设置 → Token Plan** 中连接 Kimi Coding Plan，会同时推荐对话、联网搜索和网页抓取，共用套餐密钥和 `https://api.kimi.com/coding/v1`。如果网页抓取仅使用隐式内置默认值，连接会直接分配 Kimi，不弹出冲突确认，即使选择保留当前配置也是如此。工作区的显式选择（包括 `null`）以及部署配置的非内置读取器或 `null` 仍按现有冲突选项处理。断开连接会移除套餐的分配，恢复服务端默认值（未配置读取器时为内置读取器），不会恢复此前工作区的显式选择。锁定的槽位保持不变，未声明网页抓取的套餐不会修改该槽位。

首次设置向导会将网页抓取保留为内置读取器；只有通过 Token Plan 设置页面连接套餐，才会应用套餐的抓取推荐配置。

`openai-compatible` 用于接入任意 OpenAI 兼容的对话服务：需要填写 `baseUrl`，模型设置中提供的就是它的 `models` 列表。

### DeepSeek 联网搜索与网页抓取

`deepseek` 预设在对话、联网搜索和托管 Markdown 提取之间共享 `DEEPSEEK_API_KEY` 和 API 基础地址。搜索使用 `POST /v1/tools/search`，最多返回 50 条结果，查询按 Unicode code point 截断到 128 个字符，优先使用 `summary`，为空时回退到 `snippet`。抓取使用 `POST /v1/tools/fetch`，读取 `content` 和非空的可选 `title`。

旧版配置需要设置 `WEB_SEARCH_DEEPSEEK_ENABLED=true`，或在 `server-providers.yml` 中显式添加 `web-search.deepseek`。仅配置对话凭据不会启用搜索或替换已有搜索默认项。`WEB_SEARCH_DEEPSEEK_ENABLED=false` 会强制禁用搜索。存在 `openmaic.yml` 时，旧版变量不能指定槽位，必须显式声明服务商并指定 `webSearch` 和/或 `webFetch`。

The default API base is `https://api.deepseek.com/v1`. On `api.deepseek.com`, every base path (including `/beta`) is normalized to `/v1` before appending `/tools/search` or `/tools/fetch`. Custom gateway bases preserve their configured path prefix; a bare root gets `/v1` first. Custom endpoints belong in deployment configuration, while client and workspace overrides remain restricted to official endpoints. The default fetch reader remains `builtin`. See [DeepSeek official pricing](https://api-docs.deepseek.com/zh-cn/quick_start/pricing) for current request charges. Failed requests and searches with no results are not billed.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### Kimi 联网搜索

`kimi` 预设（Moonshot Open Platform）和 `kimi-coding-plan` 预设都支持使用同一个 API key 和 Base URL 进行对话与联网搜索。将 `webSearch` 指向对话使用的同一服务商，无需额外的密钥或搜索模型。

Open Platform 的 `https://api.moonshot.cn/v1` 和 `https://api.moonshot.ai/v1` 使用 `/tools/search_pro`，搜索结果正文由页面片段拼接而成，没有正文时回退到摘要。编程套餐的 `https://api.kimi.com/coding/v1` 和 `https://api.kimi.ai/coding/v1` 使用 `/search` 并启用页面抓取，优先使用页面正文，其次使用摘要。每次请求最多返回 20 条结果。

在旧版配置中，仅配置对话密钥不会启用搜索。请设置 `WEB_SEARCH_KIMI_ENABLED=true`，或在 `server-providers.yml` 中显式添加 `web-search.kimi`。使用 `openmaic.yml` 时，需要显式指定 `webSearch` 槽位。首次运行向导仅为使用官方 Base URL 的账户推荐搜索。

端点按 Base URL 的路径选择：去掉末尾斜杠后，以 `/coding/v1` 结尾的路径使用 `/search`，其他路径使用 `/tools/search_pro`。在 `openmaic.yml` 中配置的自定义代理必须保留这一端点路径结构。

存在 `openmaic.yml` 时，必须声明 `providers.<id>: { preset: kimi }` 并指定 `slots.webSearch: <id>`；旧版环境变量 `WEB_SEARCH_KIMI_ENABLED` 无法为该槽位指定服务商。

## 网页抓取

`webFetch` 槽位默认使用无需密钥的 `builtin` 读取服务（Readability 和 Turndown；PDF 仍使用 `document`）。`kimi` 和 `kimi-coding-plan` 都复用对应服务商的密钥和 API 基础地址进行托管提取。Moonshot 开放平台使用 `/tools/fetch`，Coding Plan 使用 `/fetch`。`firecrawl` 使用单独的 Firecrawl 密钥（与 Firecrawl 联网搜索共用），调用 `/v2/scrape`。没有回退服务。可在模型服务或课程模型配置中选择读取服务，也可在 `openmaic.yml` 中指定 `slots.webFetch`。Kimi 的密钥与对话共享。所有读取服务都保留本地会话授权、公开地址检查和不可信结果边界。

DeepSeek 也通过 `deepseek` 预设提供托管 Markdown 提取，复用对话密钥和 API 基础地址。按上面的示例显式指定 `webFetch`，调用 `/v1/tools/fetch`，并保留部署配置中的网关地址。超时和仅对传输错误重试一次的行为与 Kimi 相同，不重试 HTTP 错误或无效响应。
