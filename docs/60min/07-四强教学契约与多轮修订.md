# 四强教学契约与多轮修订

> 对应代码：`lib/generation/long-form/{brief,revision}.ts`、`lib/server/generation/steps/long-form-revision.ts`
> 对应提示词：`lib/prompts/templates/long-form-critique/`、`lib/prompts/templates/long-form-revise/`

---

## 一、为什么是这四条

一条 60 分钟的课可以信息正确、结构完整、时长精准，同时**什么都没改变**。学习者看完，知道了很多，做不了任何判断。四条契约分别堵住四种"正确但无用"：

| 契约 | 堵住的失败 | 一句话检验 |
| --- | --- | --- |
| **逻辑推导性** | 结论被宣布，没有被推出 | 这一页的结论，是这一页哪一步逼出来的？ |
| **系统思维** | 知识点是清单，不是系统 | 删掉这一页，地图上会缺什么？ |
| **基础补强** | 课程从它从未建立的水平开始 | 这一模块假设学习者已经会什么，谁给的？ |
| **自主决策** | 一小时的接收，零次选择 | 这一小时里，学习者做过哪个决定？ |

四条都不是"讲得更好"的修辞，而是**可以在大纲文本上判定的结构属性**——这是它们能进审校环节的前提。

---

## 二、四条契约的落地形态

### A. 逻辑推导性

**页级要求**：`keyPoints` 是论证的步骤序列，不是关于主题的正确陈述列表。

- 如果某个要点陈述了结果（"速率因此饱和"），同一页更早的要点必须是逼出它的那一步。
- 第 N 页的最后一个要点，是第 N+1 页的起点。链条要可见。
- 第一个模块用一行给出全课主线：先建立什么、由它推出什么、最后能预测什么。

**反例**（真实形态）：`keyPoints: ["半衰期的定义", "一级动力学特征", "稳态浓度"]` —— 三个正确的小标题，零推导。

**可检验信号**：推导连词前后是否有实质内容；结论句前是否存在前提句；跨页首尾是否接得上。

### B. 系统思维

**课程级要求**：在第一个概念页之前建立系统——**构件、构件间关系、使系统成为系统的反馈、以及边界**（这个模型不覆盖什么）。

**页级要求**：每页 `description` 必须命名它构建的**节点或边**。命名不出来的页，是挂不上任何东西的页。

**为什么边界必须写**：不写边界，学习者会把这个模型用到它不成立的地方——这是长课最贵的错误，因为它要到真实场景里才暴露。

**反例**：一章讲完 20 个药，每个都讲适应证和不良反应，但从不说这些药作用在同一条通路的哪一段、谁和谁互相抵消。

### C. 基础补强

**模块级要求**：每个模块的首页声明它假设学习者已具备什么。标记 **P** 的模块额外带一页 `slide`，把该模块推导**真正依赖的那一个**前置知识预先建立。

**补丁的是前置知识，不是话题**。写"速率常数是什么"，不写"药动学复习"。话题复习会把已经会的人拖慢，把不会的人留在原地——因为他不知道自己缺的是哪一块。

**为什么只补"承重"的那一个**：长课的时间预算不允许补三个。选错了，模块整体听不懂；选对了，其余可以靠上下文带过。

### D. 自主决策

**模块级要求**：标记 **D** 的模块带一个**决策型** `quiz`——一个情境、两三个看起来都成立的选项、其中一个因为课程已建立的某个理由而正确。解析要给出每个错误选项的**后果**。

**关键**：错误选项必须有吸引力。答案是"显然错"的题不是决策，是伪装成题的陈述。答案是"上一页说过"的题也不是决策，是回忆。

**与检索点的关系**：模块本来就以检索页收尾时，**决策题就是那一页**，不额外加题。一小时里每个模块两道测验，课程会变成考试。

### 配额（由规划器计算，不由模型决定）

| 义务 | 判定规则 | 60 分钟课时 |
| --- | --- | --- |
| **P**（基础补丁） | 所有 `concept` 模块 | 模块 2、5 |
| **D**（决策点） | 每约 20 分钟 1 个，取最长的模块；模块 ≥8 分钟 | 模块 2、3、6 |

D 的数量被刻意压住：60 分钟 7 个模块，若每个都给决策点，加上 3 个检索点，测验页会占到 29 页里的 9 页。**一个以测验为主的一小时，不是教学。**

## 三、多轮修订

### 3.1 为什么一稿不行

一次生成只有一个方向。大纲从第一页写到最后一页，而它的问题恰恰在这个方向上不可见：

- 第 7 页宣布了结论——写的时候，作者知道自己刚在第 6 页做了什么，所以不觉得缺步骤。
- 模块 4 挂不上系统——写模块 4 时，系统已经写在 20 分钟前的上下文里。
- 没人补前置——写的时候，作者自己会，所以没想到有人不会。
- 没有决策点——写"讲清楚"的时候，不会想到"让他选"。

**这些缺陷对作者是透明的，对读者是致命的。** 所以必须换一个没有写过它的人来读。

### 3.2 循环

```
草稿（流式生成，一次）
  ↓
审校：五个维度打分 + 列出具体缺陷（带页码）
  ↓
全维 ≥4 或没有可执行的缺陷？ ──是──→ 交付
  ↓ 否
修复：只改被点名的页，保留 id、顺序、类型
  ↓
安全校验：页数漂移 ≤25%、id 不重复、类型合法？ ──否──→ 保留上一版，交付
  ↓ 是
回到审校（最多 2 轮）
```

### 3.3 停止条件

| 条件 | 动作 | 理由 |
| --- | --- | --- |
| 五个维度全部 ≥4 | 停止，交付 | 已经够了，再改是抛光 |
| 审校说 `pass` | 停止 | 审校者认为没问题，就尊重它 |
| 缺陷列表为空 | 停止 | **没有指令的修复者会重写整门课** |
| 轮次用完（2 轮） | 停止 | 收益在此之后急剧下降 |
| 审校输出无法解析 | 停止，保留草稿 | 在"什么都没说"的基础上修改，只会更糟 |
| 修复失败 / 不安全 | 停止，保留上一版 | 结构完好的浅课 > 没人审过的新课 |

**注意第 3 条**：这是最容易写错的地方。一个分数很低但没列出任何缺陷的审校，如果触发修复，修复者拿到的是空指令——它会自由发挥，把课程重写一遍。所以"低分"本身不是修改的理由，"低分且指出了具体位置"才是。

### 3.4 安全阀

修复者被要求"只改被点名的页"，但它经常不听。所以每次修复都要过一遍 `isSafeRevision`：

- 页数为 0 → 拒绝
- 页数漂移 > 25% → 拒绝（29 页变 40 页是重写，不是修复）
- id 重复或丢失 → 拒绝
- 出现未知场景类型 → 拒绝

被拒绝时保留上一版。**修复只允许把课改好，不允许把课改没。**

### 3.5 成本

| 场景 | 调用数 |
| --- | --- |
| 短课（非长课） | 1（大纲）+ 每页 3 次 |
| 长课，一次通过 | 1 + 1（审校） |
| 长课，两轮修订 | 1 + 2×2 = 5 |

对比：29 页长课的下游是 29 × 3 = 87 次调用。**在大纲上多花 4 次，换的是 87 次调用不建立在错误结构上。** 这是整个长课链路里性价比最高的一次投入。

### 3.6 时间预算

修订跑在大纲步骤内部，而大纲步骤有 300 秒的硬截止（`STEP_DEADLINES_MS.outline`）。**截止触发会连草稿一起中断**——那比不修订更糟。

所以：

- 长课的大纲预算额外加 240 秒（`STEP_DEADLINES_MS.outlineRevision`），不是从 300 秒里切。
- 循环拿到合并后的截止时刻，**每次调用前先算时间够不够**：审校需 45 秒，修复需 90 秒（它要重新输出整份大纲）。
- 不够就跳过该轮，直接交付当前版本。

流式生成跑了 280 秒的课，修订阶段只剩很少的时间——结果是"这次不修订"，而不是"这次课没了"。

### 3.7 为什么不是"生成两遍取好的"

生成两遍会得到两份不同的课，无法比较，也无法解释为什么选了一份。修订得到的是**同一门课的两版**——差异全部来自被点名的缺陷，可追溯、可回滚、可在日志里读。

## 四、实现位置

| 关注点 | 位置 |
| --- | --- |
| 契约的生成侧表述 | `long-form/brief.ts`（`The four contracts this course is judged on`） |
| 义务配额 | `long-form/plan.ts`（`decisionModules` / `patchModules`） |
| 审校提示词 | `lib/prompts/templates/long-form-critique/` |
| 修复提示词 | `lib/prompts/templates/long-form-revise/` |
| 审校解析与停止判定 | `long-form/revision.ts` |
| 循环与安全阀 | `lib/server/generation/steps/long-form-revision.ts` |
| 接入点 | `steps/outline.ts` 的 `generateOutlines` |

**没有 schema 变更**：四条契约全部落在既有字段上——`keyPoints`（推导）、`description`（系统节点）、`teachingObjective`（能力）、`quiz` 场景（决策）。新增字段会让 dsl、导出、编辑链路全部跟改，而收益并不来自字段，来自要求。

## 五、局限

1. **审校质量决定一切。** 如果审校者本身看不出"结论没有被推出"，循环只是把一个平庸的大纲改成一个更平庸的。当前用与生成同一个模型，没有独立的强模型。
2. **只在大纲层修订。** 讲稿层的"念页""宣告"仍然是一次成型。场景级修订成本是 29 页 × 2，暂未启用。
3. **契约无法自动验证。** 目前靠审校的语义判断；可计算的代理指标（推导连词密度、系统锚覆盖率）在 `04-评价体系.md` 里设计，尚未接入。
4. **两轮是经验值。** 没有做过收益曲线测量，2 轮可能不是最优点。
