# 长课评价体系

> 目标：让"这节 60 分钟的课好不好"从主观判断变成**可复现的分数 + 可定位的问题**。
> 对标依据见 `05-对标研究.md`；演绎规范见 `03-知识点演绎规范.md`。

---

## 一、设计原则

1. **每个维度都必须有代理指标**。纯主观维度（"讲得好不好"）无法迭代；只有能被脚本算出来的维度才能驱动自动改进。
2. **主观分与自动分并存，不互相替代**。自动分用于批量回归（每次改提示词跑一遍），主观分用于定标（确认自动分没有跑偏）。
3. **长课特有维度单列**。连贯性与记忆锚在短课里几乎不需要，在 60 分钟里是决定性的，不能藏在"结构"里。
4. **权重反映失效代价**。演绎质量权重最高（25%），因为它是长课唯一无法靠结构弥补的部分。

---

## 二、八维评分表

总分 100。每维 1-5 分，加权后折算。

### 维度 1 · 目标一致性（Alignment）· 15%

课程声称要教的东西，与实际讲的东西、与评估考的东西，三者是否一致。

| 分 | 锚点 |
| --- | --- |
| 5 | 每个模块有 2-4 条可检验的行为目标；每页可追溯到某条目标；每个检索点直接检验本模块目标动词 |
| 3 | 有模块目标，但部分页面与目标无关（凑页）；评估与目标动词不匹配 |
| 1 | 无模块目标，或目标是"了解/掌握"一类不可检验表述；评估与内容脱节 |

**代理指标**
- `模块目标覆盖率` = 有 `teachingObjective` 的模块数 / 模块总数
- `目标动词可检验率` = 目标中行为动词（derive/explain/apply/compare/diagnose…）占比
- `评估-目标动词匹配率` = quiz 题型与目标动词兼容的比例

---

### 维度 2 · 结构与节奏（Structure & Pacing）· 15%

时间花在该花的地方，模块边界清晰，没有头重脚轻。

| 分 | 锚点 |
| --- | --- |
| 5 | 总时长偏差 <10%；各模块时长与教学功能匹配（推导最长、整合最短）；每个 ≥10 分钟模块有检索点；模块边界有明显切换 |
| 3 | 总时长偏差 10-25%；模块时长与功能部分不匹配；检索点缺失 1 个 |
| 1 | 总时长偏差 >40%；模块边界不可感知；无检索点或全部集中在开头 |

**代理指标**
- `时长偏差` = \|Σ estimatedDuration − 目标秒数\| / 目标秒数
- `模块时长-功能匹配` = 各模块时长排名的逆序与功能权重排名的一致度（Kendall τ）
- `检索点密度` = check 页数 / 模块数（目标 ≥ 0.6）
- `页时长离散度` = 各页时长标准差 / 均值（目标 < 0.25）

---

### 维度 3 · 知识点演绎质量（Explanation Quality）· 25%

**权重最高。** 每一页是否真的在论证，而不是在宣告。

| 分 | 锚点 |
| --- | --- |
| 5 | 每页至少做三件事中的两件：给出必真的理由、跑一个具体案例、指出失效边界；抽象概念首次出现必有直觉铺垫；使用学习者可能的错误预测；页与页不重复 |
| 3 | 约半数页面有实质演绎，其余为宣告或复述；有直觉铺垫但流于类比，未说明类比在哪断裂 |
| 1 | 绝大多数页面是"定义 + 要点 + 小结"；出现"因此"但无推导过程；同一概念被反复重新定义 |

**代理指标**
- `论证标记率` = 含因果/推导连词（因为/因此/从而/why/because/therefore）且前后句有实质内容的段落 / 总段落
- `案例密度` = 含具体情境（数字、命名场景、病例、代码）的段落 / 总段落（目标 ≥ 0.3）
- `念页率` = 旁白与同页 `keyPoints` 的字符 n-gram 重叠率（目标 < 0.6）
- `宣告率` = 出现"因此/所以"但前一句不含论证的比例（目标 < 0.15）
- `定义复读` = 台账中同 term 在不同页被重新定义次数（目标 = 0）

---

### 维度 4 · 认知负荷与可理解性（Cognitive Load）· 15%

依据 Mayer 的分段 / 信号 / 冗余 / 一致性四原则（见 `05-对标研究.md` §3.4）。

| 分 | 锚点 |
| --- | --- |
| 5 | 每页只推进一个论证步骤；spotlight 先于对应讲解；旁白与画面互补而非复述；无装饰性素材 |
| 3 | 偶尔一页塞两个以上新概念；spotlight 时序错乱；部分旁白在念画面文字 |
| 1 | 单页新概念 >3 个；旁白与画面高度冗余；大量与学习无关的装饰 |

**代理指标**
- `单页新概念数` = 该页首次出现的术语数（目标 ≤ 2）
- `spotlight 前置率` = spotlight 出现在对应 text 之前的比例（目标 = 1.0）
- `冗余度` = 旁白与页面文字的重叠率（同维度 3 的念页率）
- `术语引入速率` = 新术语数 / 分钟（长课目标 ≤ 1.5，短课可更高）

---

### 维度 5 · 参与与注意力维持（Engagement）· 10%

60 分钟内是否有足够的注意力锚点。

| 分 | 锚点 |
| --- | --- |
| 5 | 每 12-15 分钟有一次明显切换（新媒介/新任务/新声音）；至少 2 次预测冲突；提问后有真实停顿；互动密度与长度匹配 |
| 3 | 有 1-2 次切换但间隔不均；提问即自答 |
| 1 | 全程同一形态（连续 slide）；无停顿；无互动 |

**代理指标**
- `切换间隔` = 相邻两次"媒介/任务切换"的分钟差（目标 12-15）
- `互动密度` = (quiz + interactive + discussion) / 模块数
- `停顿率` = 提问句后存在 TTS 停顿（标点/静音）的比例
- `形态同质率` = 连续同 role 页的最大长度（目标 ≤ 3）

---

### 维度 6 · 评估与反馈（Assessment）· 10%

| 分 | 锚点 |
| --- | --- |
| 5 | 每个模块末有检索点；题目考迁移而非复述；有错误反馈与解释；难度与模块目标匹配 |
| 3 | 有检索点但集中在部分模块；题目为原例改写；无反馈解释 |
| 1 | 仅课程末一个总结性测验，或完全没有 |

**代理指标**
- `检索点覆盖率` = 有 check 的模块 / 模块数（≥10 分钟的模块，目标 = 1.0）
- `迁移题比例` = 题干情境与课上原例不同的题目 / 总题数（目标 ≥ 0.6）
- `反馈完备率` = 带解释的题目 / 总题数

---

### 维度 7 · 长课连贯性与记忆锚（Continuity）· 5%

**短课不需要，长课必需。** 这是本体系区别于通用课程评价的地方。

| 分 | 锚点 |
| --- | --- |
| 5 | 开场埋的环在整合模块闭合；模块间有显式桥接；跨页引用准确（"前面建立的 X"）；无提前收尾；案例复用 ≤2 次 |
| 3 | 有桥接但不均匀；开场环闭合得含糊；偶有提前总结 |
| 1 | 各模块像独立短课拼接；开场环不闭合；同一案例贯穿全程；第 2 模块后即出现全课总结 |

**代理指标**
- `开环闭合率` = `integration` 模块中闭合的 `openLoops` / 总开环数（目标 = 1.0）
- `桥接完备率` = 模块首页含前序指代的比例（目标 ≥ 0.8）
- `提前收尾` = 非末模块出现全课总结词（"整节课/从头到尾/the whole course"）的次数（目标 = 0）
- `案例复用峰值` = 单一案例出现的页数（目标 ≤ 3）

---

### 维度 8 · 制作与呈现（Production）· 5%

| 分 | 锚点 |
| --- | --- |
| 5 | 旁白无公式/代码符号被 TTS 误读；无空页、无溢出；字幕与语音一致；音量一致 |
| 3 | 个别公式读音问题；个别页面排版拥挤 |
| 1 | 大量 LaTeX 进入旁白；页面溢出；音画不同步 |

**代理指标**
- `TTS 可读性违规率` = 旁白中含 LaTeX/代码符号的段落比例（目标 = 0，依据 `snippets/speech-tts-readability.md`）
- `排版溢出数` = 导出诊断中 overflow 类 diagnostic 数
- `音画时长偏差` = 旁白实际时长与页时长的偏差

---

## 三、总分与等级

| 等级 | 加权总分 | 含义 |
| --- | --- | --- |
| A | ≥ 4.2 | 达到国际公开课 + 名师内容的下限；可直接发布 |
| B | 3.5-4.2 | 结构合格、演绎平庸；可发布但需人工打磨 |
| C | 2.8-3.5 | 有明显结构性缺陷；需重新生成 |
| D | < 2.8 | 不构成一节长课 |

**加权公式**

```
总分 = 0.15×D1 + 0.15×D2 + 0.25×D3 + 0.15×D4 + 0.10×D5 + 0.10×D6 + 0.05×D7 + 0.05×D8
```

**一票否决项**（任一触发，直接判 D，不论总分）：
- 时长偏差 > 50%
- 维度 3 得分 = 1（全是宣告）
- 维度 7 的"提前收尾"次数 > 2
- TTS 可读性违规率 > 10%

## 四、自动化评测设计

### 4.1 目录结构（建议，对齐现有 `eval/` 约定）

```
eval/long-form/
  runner.ts            # 跑一批课程，产出报告
  metrics/
    alignment.ts       # D1
    pacing.ts          # D2
    explanation.ts     # D3
    load.ts            # D4
    engagement.ts      # D5
    assessment.ts      # D6
    continuity.ts      # D7
    production.ts      # D8
  judge-prompt.md      # 主观维度的 LLM 评审提示词
  scenarios/           # 测试课程集
    tcm-60min.json
    physics-60min.json
    programming-90min.json
  types.ts
  reporter.ts
```

与现有 `eval/orchestration`、`eval/outline-language` 保持同一形态：`scenarios/*.json` + `runner.ts` + `judge-prompt.md` + `reporter.ts`。

### 4.2 可纯计算的部分（不调模型）

D2（结构节奏）、D6（评估）、D7（连贯性的结构部分）**完全可以从数据结构算出**，不需要模型：

```ts
// D2 示例：时长偏差 + 检索点密度
const actualSeconds = scenes.reduce((acc, s) => acc + (s.estimatedDuration ?? 0), 0);
const targetSeconds = plan.minutes * 60;
const drift = Math.abs(actualSeconds - targetSeconds) / targetSeconds;

const checkDensity =
  plan.modules.filter((m) => m.durationMinutes >= CHECKPOINT_MODULE_MINUTES).length === 0
    ? 1
    : scenes.filter((s) => s.type === 'quiz').length /
      plan.modules.filter((m) => m.durationMinutes >= CHECKPOINT_MODULE_MINUTES).length;
```

这是整套体系里最便宜的部分，应该**先做**——它能在不增加任何模型成本的前提下抓住 60% 的失败案例（时长漂移、检索点缺失、页数失控）。

### 4.3 需要模型判断的部分

D3（演绎质量）、D4（认知负荷）、D7（连贯性的语义部分）需要 LLM 评审。建议做成**结构化打分 + 证据引用**，而不是给一个分数：

```json
{
  "dimension": "explanation",
  "score": 3,
  "evidence": [
    { "pageIndex": 7, "issue": "announce-without-derivation",
      "quote": "因此反应速率必然饱和。",
      "why": "前一句是数据描述，没有给出饱和的机制" },
    { "pageIndex": 12, "issue": "redundant-with-slide",
      "quote": "…", "why": "旁白是 keyPoints 的口语复述" }
  ]
}
```

**证据引用是关键**：只给分数的评审无法驱动修改，带页码和引文的评审可以直接转成重写任务。

### 4.4 人工定标流程

自动分上线前，必须做一次人工定标：

1. 取 10 节真实长课（覆盖不同学科、不同长度）
2. 3 名评审独立按八维打分（不看自动分）
3. 计算评审间一致性（Krippendorff's α，目标 ≥ 0.7）
4. 对齐自动分与人工分，偏差 > 1 分的维度重写指标
5. 固化锚点描述后，自动分才可用于批量回归

**跳过定标的自动评分体系不可信**——它只会稳定地测量自己。

## 五、与生成流程的闭环

评价体系的价值不在打分，在于**把分数变成修改动作**：

| 触发条件 | 自动动作 |
| --- | --- |
| 时长偏差 > 20% | 按实际页数重算预算，重写偏差最大的 3 页 |
| 单页字数偏差 > 40% | 重写该页 narration |
| 提前收尾 / 开场问候重复 | 重写该页首段或末段 |
| 检索点缺失 | 在模块末补一页 quiz |
| 念页率 > 60% | 重写该页，强制加入"为什么"与"具体案例" |
| 定义复读 | 改写后出现页，改为"前面建立的 X"式引用 |

这张表是下一阶段（v2）自动重试策略的输入。当前 `run/retry.ts` 只处理失败重试，不处理质量重写——这是质量闭环缺失的一环。
