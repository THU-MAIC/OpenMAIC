# 教学内容设计与知识点演绎规范

> 目的：把"讲得好"从形容词变成可执行、可检查的结构。
> 对应提示词：`templates/requirements-to-outlines/system.md`（长课分支）、`templates/slide-actions/system.md`（§4 长课演绎）

---

## 一、知识点必须回答的四个问题

任何一个知识点，讲透的标志是四个问题都有答案。少一个，学习者就在某个环节掉队，而且掉队后不会自己发现。

| 问题 | 学习者掉队时的表现 | 讲授责任 |
| --- | --- | --- |
| **为什么需要它** | "所以呢？这跟我有什么关系" | 在定义之前给出它要解决的困境 |
| **它到底是什么** | 能背定义，不能判断边界 | 给可操作的定义 + 一个反例 |
| **它怎么用** | 看得懂例题，做不出新题 | 完整示范 → 半成品 → 独立 |
| **什么时候会失效** | 过度泛化，把规律用错地方 | 明确边界条件与典型误用 |

四问不必四页。短页可以合并，但**一个模块内四问必须齐全**，且顺序不可颠倒（先"是什么"再"为什么"，是长课最典型的顺序错误——学习者没有动机接收一个他不知道为什么存在的定义）。

**提示词落地**：`requirements-to-outlines/system.md` 长课分支要求每页 `description` 写"学完能做什么/预测什么"，而不是主题标签；`keyPoints` 必须是带内容的论断，不能是小标题。

## 二、七种演绎模式

每种模式有明确的适用条件。选错模式的代价不是"讲得差"，而是"讲了但没讲进去"。

### 模式 1 · 直觉先行（Intuition First）

| | |
| --- | --- |
| **适用** | 抽象概念首次出现；学习者缺少可挂靠的经验 |
| **时长** | 2-4 分钟 |
| **结构** | 可感知的类比 → 类比在哪里成立 → 类比在哪里断裂 → 形式定义（此时定义已经是"命名一个已知的东西"） |
| **反例** | 直接给定义 + 三个性质。学习者记住了字，没有建立任何直觉，一遇到变形就崩 |
| **提示词落地** | 页 `role = open`，`keyPoints` 第一项必须是"类比/现象"，最后一项才是"定义" |

### 模式 2 · 预测冲突（Prediction-Error）

| | |
| --- | --- |
| **适用** | 学习者存在稳定的错误直觉（物理、概率、生理、经济尤其多） |
| **时长** | 2-3 分钟 |
| **结构** | 抛情境 → 让学习者先给出预测（停顿）→ 说出大多数人的预测 → 揭示真实结果 → 解释为什么直觉错了 |
| **反例** | 直接讲正确结论。学习者点头，然后继续用原来的直觉做题 |
| **关键** | 必须**先说出那个错误预测**，而不是只否定它。"很多人会认为是 X" 比 "不是 X" 有效得多 |
| **提示词落地** | `slide-actions/system.md` 长课分支："Use the learner's likely wrong answer. State the intuitive-but-wrong expectation, then show the collision with the evidence." |

### 模式 3 · 双重编码（Dual Coding）

| | |
| --- | --- |
| **适用** | 结构、流程、空间关系、数量关系 |
| **时长** | 1.5-3 分钟 |
| **结构** | 说到的每一个成分，画面上同时出现并高亮（spotlight）；语词与图形不是互相复述，而是互补——图给结构，话给因果 |
| **反例** | 页面上有图，但讲解在念图上的文字；或者图先出完，再开始讲 |
| **提示词落地** | spotlight 必须先于对应 text；一段话只聚焦一个元素；禁止"如图所示，我们可以看到……"式念图 |

### 模式 4 · 示范渐隐（Worked Example Fading）

| | |
| --- | --- |
| **适用** | 程序性知识：解题、推导、诊断、操作 |
| **时长** | 4-8 分钟，跨 2-3 页 |
| **结构** | 第 1 页：完整示范，每一步都说明"为什么走这一步"；第 2 页：同一类题，最后一步留白，让学习者补；第 3 页：只给起点和终点，中间自己走（可用 quiz 承接） |
| **反例** | 三个例题并排，难度相同。学习者看完三个仍然不会做第四个 |
| **关键** | 渐隐的是**步骤**，不是**难度**。难度保持不变，支撑逐步撤走 |
| **提示词落地** | 跨页模式，需在大纲阶段就规划：`keyPoints` 明确"完整示范/半成品/独立" |

### 模式 5 · 对比辨析（Contrastive Pairs）

| | |
| --- | --- |
| **适用** | 易混概念、分类边界、诊断鉴别 |
| **时长** | 2-4 分钟 |
| **结构** | 正例 → 反例（只差一个关键特征）→ 边界例（特征模糊，最考验理解）→ 提炼判别性特征 |
| **反例** | 只给正例 + 一句"注意区分"。学习者不知道要区分什么 |
| **关键** | 反例必须**只差一个特征**。差三个特征的反例，学习者会把差异归到错的地方 |
| **提示词落地** | `keyPoints` 写"两个案例 + 判别性特征"，而不是"概念 A 与概念 B 的区别" |

### 模式 6 · 苏格拉底追问（Guided Questioning）

| | |
| --- | --- |
| **适用** | 需要学习者自己得出结论，或需要暴露推理漏洞 |
| **时长** | 1.5-3 分钟 |
| **结构** | 问一个学习者能答的问题 → 基于答案再问 → 直到答案逼出结论 |
| **反例** | 自问自答："为什么呢？因为……"——这不是追问，是修辞 |
| **关键** | 长课里**提问后必须留停顿**（TTS 层面是标点与静音），且不能立刻自答 |
| **提示词落地** | 教师可以提开放反问，但**绝不能替学生回答**（`slide-actions/system.md` 已硬性禁止写学生台词）；需要学生真的回答时，用 `discussion` 动作收尾 |

### 模式 7 · 迁移挑战（Transfer Task）

| | |
| --- | --- |
| **适用** | 模块末、课程末；检验是否真的掌握 |
| **时长** | 2-4 分钟 |
| **结构** | 一个**表面不同、结构相同**的新情境 → 学习者自己判断该用哪个工具 → 揭晓 |
| **反例** | 换了个数字的原题。那是练习，不是迁移 |
| **提示词落地** | 模块末的 `check` 页；quiz 题干必须是新情境，不能是课上原例改写 |

## 三、单页讲解的五段骨架（长课版）

短课的一页可以是"引入—讲解—小结"。长课的一页 2-3 分钟，必须做更多工作，否则撑不满或注水。

| 段 | 占比 | 干什么 | 禁止 |
| --- | --- | --- | --- |
| ① 接续 | 10% | 一句话接住上一页留下的问题 | 问候、自我介绍、"上节课" |
| ② 主张 | 15% | 明确说出这一页要建立/推翻什么 | "今天我们来学习……" |
| ③ 展开 | 50% | 演绎主体：至少做三件事中的两件——给出必真的理由、跑一个具体案例、指出失效边界 | 罗列、复述页面上已有的文字 |
| ④ 收束 | 15% | 这一页的结论，一句话 | 提前做全课总结 |
| ⑤ 交棒 | 10% | 引出下一页的问题（模块末页改为"模块小结"） | 无过渡直接断掉 |

**这条骨架已经写进 `slide-actions/system.md` 的长课分支**，以"An hour-long lesson fails differently... nothing is *wrong*, everything is thin"开头，逐条对应。

### 长课的六个固定失败模式（反面清单）

| 失败模式 | 表现 | 检测信号 |
| --- | --- | --- |
| **念页** | 旁白 = 页面上文字的口语版 | 旁白与 `keyPoints` 的字符重叠率 > 60% |
| **宣告** | "因此 X 成立"，没有"因此"的推导过程 | 出现"因此/所以/可见"但前一句不含论证 |
| **同构** | 连续多页"定义—要点—小结" | 连续 3 页开场句式相似度 > 0.7 |
| **复读** | 同一概念被重新定义 2 次以上 | 台账 `definitions` 出现同 term 不同页 |
| **提前收尾** | 非末模块出现全课总结 | 第 2 模块后出现"整节课/从头到尾" |
| **案例复用** | 同一个例子贯穿 60 分钟 | 台账 `examples` 同一 name 出现 > 3 页 |

## 四、模块内的页间分工

一个模块的 6-8 页不是 6-8 个知识点，而是**一个论点的 6-8 步**。默认分工：

```
第 1 页  open     立问题：这个模块要回答什么，为什么上一模块回答不了
第 2 页  develop  给工具：定义 / 类比 / 关键区分
第 3-4 页 develop 推演：机制怎么运作（模式 3 或 4）
第 5 页  develop  反例：什么时候不成立（模式 5）
第 6 页  close    收束：这个模块建立了什么，留给下一模块什么
第 7 页  check    检索：一个迁移挑战（模式 7）
```

模块 ≥10 分钟时，最后一页是 `check`，倒数第二页是 `close`——这是 `plan.ts` 的 `rolesFor()` 直接产出的结构，不是建议。

## 五、学科模板（可配置层）

用户选择"通用 + 可配置学科模板"。学科差异体现在**四个旋钮**上，不体现在提示词分叉上（分叉会导致维护成本爆炸）。

| 旋钮 | 中医 / 医学 | 理工 / 工程 | 人文 / 社科 | 职业技能 |
| --- | --- | --- | --- | --- |
| **主导演绎模式** | 5 对比辨析 > 4 示范 > 1 直觉 | 3 双重编码 > 4 示范 > 2 预测冲突 | 2 预测冲突 > 6 追问 > 5 对比 | 4 示范渐隐 > 7 迁移 > 5 对比 |
| **页面类型偏好** | slide 为主 + 图（舌象/脉象/方剂结构） | slide + interactive（仿真）+ 公式 | slide 为主 + 少量时间轴/关系图 | slide + 操作步骤 + 检查表 |
| **术语策略** | 文言原文 + 白话对译并列，原文必须逐字给出 | 符号先定义后使用，符号表页 | 人名/年代/学派必须准确 | 工具名/型号/规范编号保留原文 |
| **评估形态** | 病案辨证（给症状选证型/方剂） | 计算 + 边界条件判断 | 论证评价（这段论证哪里弱） | 操作步骤排序 + 错误后果识别 |

中医模板的具体约定（作为首个验证学科）：

- **经典原文不可改写**。引用《伤寒论》条文必须给原文，再给白话，再给病机解释——三者顺序固定。
- **辨证必须走完整链条**：症状 → 病位 → 病性 → 病机 → 治法 → 方药 → 加减。少一环就是"背方剂"，不是"学中医"。
- **医案是最好的迁移载体**：模式 7 的迁移挑战用真实医案（隐去结论），比任何虚构情境都有效。
- **反例的价值高于正例**：同一症状不同证型的鉴别（模式 5）是中医教学的核心动作。
