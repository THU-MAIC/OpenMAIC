# 12 · MiMo 配音与两项提速实测

## 一、接口

小米 MiMo 的 TTS 走 **chat 协议**，不是 `/audio/speech`：

```
POST https://api.xiaomimimo.com/v1/chat/completions
api-key: $MIMO_API_KEY

{
  "model": "mimo-v2.5-tts",
  "messages": [
    { "role": "user",      "content": "<风格指令：语速、语气、术语读法>" },
    { "role": "assistant", "content": "<要念的文本>" }
  ],
  "audio": { "format": "mp3", "voice": "白桦" }
}
```

返回 JSON，音频在 `choices[0].message.audio.data`，base64。预置音色：`mimo_default` / 冰糖 / 茉莉 / 苏打 / 白桦 / Mia / Chloe / Milo / Dean。

**没有 `speed` 参数**，语速只能靠风格指令影响，实际节奏由模型决定 —— 这一点后面会咬人。

## 二、三个探针

| 输入 | 耗时 | 音频 | 语速 | 合成倍速 |
| --- | --- | --- | --- | --- |
| 396 字 | 8.4s | 101.9s | 233 字/分 | 12× |
| 792 字 | 8.1s | 169.1s | 281 字/分 | 21× |
| 1586 字 | 8.1s | 332.3s | 286 字/分 | 41× |
| 2968 字 | 8.1s | 238.7s | **746 字/分** | 29× |
| 5936 字 | 8.1s | 609.8s | **584 字/分** | 75× |

**8 秒是固定开销**：396 字和 1586 字都是 8.1 秒。所以"多切块"是纯浪费，块越大越划算 —— 直到 1600 字。

**超过 1600 字开始失真**：2968 字只出 238 秒音频。按 286 字/分算应该是 622 秒，实际 38%。**等于漏读了大半，而返回的仍然是合法 mp3** —— 这是最危险的一类失败：不报错，只是内容没了。所以分块上限定在 900 字，并且每块合成后用 ffprobe 校验时长。

## 三、并发

同一段 400 字，串行 8.4 秒一次：

| 并发 | 墙钟 | 加速 |
| --- | --- | --- |
| 4 路 | 21.4s | 1.58× |
| 8 路 | 30.3s | 2.22× |

线性打折，但仍有收益。取 8 路。

## 四、实测结果

18 页 / 15,537 字：

```
配音完成：63.4 分钟音频 / 墙钟 3.2 分钟（19.6× 实时）
实测语速 245 字/分钟
```

对比原来 StepFun 的 **22.3 分钟**，快 **7 倍**。

但代价是：MiMo 这个音色 245 字/分，StepFun 是 257。同样 15,537 字，**音频从 60.5 分钟变成 63.4 分钟**，成片 64.1 分钟。要正好 60 分钟，旁白应写 12,500 字而不是 15,537。

**同一段文本两次合成的长度也会差 2-3%**（61.7 → 63.4 分钟）。所以时长不能靠字数硬算，必须合成后测量，超差就补写或删减。

## 五、拼接：22 分钟 → 7.8 秒

原来拼接用 `libx264` 重编码整条视频，耗时 22 分钟。改成 `-c copy`：

```
分段合计 3678.103s
流拷贝   3678.126s
差       0.023s
耗时     7.4s
```

零漂移。现在的做法是**先试 `-c copy`，拼完用 ffprobe 比对分段合计，差超过 1 秒才回退重编码** —— 不再靠"我觉得可能会漂"来做决定。

## 六、这一轮的账

| 阶段 | 原来 | 现在 | 说明 |
| --- | --- | --- | --- |
| 正文生成 | 29.1 min | 29.1 min | 未重跑 |
| 配音 | 22.3 min | **3.2 min** | MiMo + 8 路并发 |
| 渲染 + 编码 | 28.0 min | **8.3 min** | 拼接改流拷贝 |
| **合计** | **79.7 min** | **40.6 min** | −49% |

正文那一项如果按模块并发重跑（7 模块 / 并发 4），预计 15 分钟左右，全程可到 **26 分钟**。

## 七、两个仍然存在的问题

1. **陈旧分段被静默复用**。第二次重建视频时 `existsSync(seg)` 让 18 段全部跳过，成片用的还是旧配音，而日志显示一切正常。改成比较音频与分段的修改时间。
2. **语速不可控**。没有 `speed` 参数，风格指令只能影响不能指定。要在固定时长里交付，只能"先合成再测量再补写"，不能"按字数算时长"。
