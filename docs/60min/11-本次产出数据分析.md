# 11 · 本次 60 分钟产出的数据分析

> 数据来源：`C:\tmp\course` 的 `plan.json`、`pages.json`、`durations.json`、`content.log`、18 段 MP4 的 ffprobe 结果、成片 ffprobe 结果。
> 所有数字都是实测，没有估算。

---

## 一、一句话结论

**时长控制成功了，但它成功的原因是两个误差互相抵消，不是设计对了。**
字数比目标少 2.4%，语速假设比实测高 3.0%，两者相乘刚好回到 60 分钟。这套参数再偏 5%，同一门课就会变成 57 或 63 分钟，而系统不会知道。

**生产耗时 79.7 分钟做 61.3 分钟的视频，1.33 倍实时。**其中 22 分钟花在一次可以避免的重编码上。

## 三、时长精度：误差分解

### 3.1 分层看

| 层 | 计划 | 实际 | 偏差 |
| --- | --- | --- | --- |
| 总时长 | 60:00 | 60:33 | **+0.9%** |
| 模块最大偏差 | 8.0 min（模块 4） | 8.4 min | +5.0% |
| 每页字数（均值） | 880 | 863 | **−2.4%** |
| 语速 | 假设 265 字/分 | 实测 257 字/分 | **−3.0%** |

### 3.2 关键发现：两个误差在抵消

```
时长 = 字数 ÷ 语速
计划：880 × 18 ÷ 265 = 59.8 分钟
实际：863 × 18 ÷ 257 = 60.5 分钟
```

字数少了 2.4%（让时长变短），语速也低了 3.0%（让时长变长）。两个误差方向相反、量级相近，相乘后几乎完全抵消。

**这不是校准做得好，这是巧合。**`speechRateFor()` 里那个 265 是从 51 个字的一次试音外推的，样本极小。真跑 15,537 字后实测 257——**偏差 3.0%**，而 3% 在 60 分钟上就是 1.8 分钟。

真正的修法是：**用实测语速回填，而不是继续用假设值**。这次跑完就有一个 15,537 字 / 3,632.9 秒的样本，比任何一次试音都准。

### 3.3 每页字数分布

| 指标 | 值 |
| --- | --- |
| 偏差均值 | −2.4% |
| 偏差范围 | **−17% ~ +4%** |
| 每页语速 | 243 ~ 264 字/分（极差 8.6%） |
| 每页时长 | 2:39 ~ 4:14，均值 3:22 |

**分布是单边的：18 页里 13 页低于目标，最高只超出 4%。**模型系统性少写，从不多写。

这直接推翻了我上一轮的判断。我当时说"模型比目标多写约 50%"——那是**一次要 3 页时**的观察（16k token 被推理吃光后的截断假象）。改成**一页一次调用**后，模型是轻微欠写的。

**推论：字数校验的上界从未触发过。**5 次重试全部是"低于下界"。上界 1.15 倍那条规则是死代码。

## 四、时间成本：79.7 分钟去哪了

| 阶段 | 起止 | 耗时 | 占比 |
| --- | --- | --- | --- |
| 课程设计 | 10:34:30 产出 | ~0.3 min | 0.4% |
| 正文生成 | 10:34:51 → 11:03:56 | **29.1 min** | 36% |
| 配音 | 11:03:56 → 11:26:14 | **22.3 min** | 28% |
| 渲染 + 编码 | 11:26:14 → 11:54:15 | **28.0 min** | 35% |

### 4.1 正文生成：并发的收益被前半段吃掉

| 段 | 页数 | 耗时 | 单页有效耗时 |
| --- | --- | --- | --- |
| 串行（p1–p5） | 5 | 10.3 min | **2.07 min** |
| 并发 3（p6–p18） | 13 | 11.4 min | **0.87 min** |

3 并发把单页成本压到 42%，效率 80%（理论 1/3）。但前 5 页是串行跑的，如果 18 页全程并发 3，正文阶段是 **15.7 分钟**而不是 29.1——**白花 13.4 分钟**。

### 4.2 编码：22 分钟花在一次不必要的重编码上

分段编码本身很快（fps12 + ultrafast，60 秒画面约 5.7 秒），18 段合计约 5.7 分钟。剩下 **22 分钟全在拼接**。

拼接命令用的是 `-c:v libx264 ... -crf 23`——**重编码整条 60 分钟视频**。而实测结果：

```
18 段时长合计  3678.1 秒
成片时长       3678.2 秒
差             0.1 秒
```

**零漂移。**`-c copy` 完全可行，几秒就能完成。当初选重编码的理由是"分段的时间戳偶尔会漂"，但这次没有漂——而我没有验证就付了 22 分钟。

正确做法是：先 `-c copy`，ffprobe 校验总时长，对不上再重编码。省下的 22 分钟占全程 28%。

### 4.3 可回收的三项

| 改动 | 省下 | 依据 |
| --- | --- | --- |
| 拼接改 `-c copy` + 校验兜底 | **22 min** | 实测漂移 0.1 秒 |
| 正文全程并发 3 | **13 min** | 后半段实测 0.87 min/页 |
| 配音与渲染重叠（音频一出来就渲染该页） | **~10 min** | 两阶段无依赖 |

合计：79.7 → **约 35 分钟**，从 1.33 倍实时降到 **0.57 倍**。

| # | 缺陷 | 量化 | 根因 |

## 七、我需要的节点

这次跑之所以只能靠 `content.log` 和 ffprobe 事后反推，是因为整条流水线**几乎没有埋点**。下面 12 个节点是让这条链可复现、可归因、可定价的最小集合。

| # | 节点 | 要回答的问题 | 现状 |
| --- | --- | --- | --- |
| N1 | 需求解析 | 时长 / 语言 / 学科解析成了什么 | ❌ 写死在脚本里 |
| N2 | 计划配平 | 模块分钟和 = 目标？页数 × 字数 = 总量？ | ✅ `plan.json` |
| N3 | 页级契约 | 每页有教学目标 / 交棒句 / 角色？ | ⚠️ 有 `role`，无 `teachingObjective` |
| N4 | 正文调用 | 每次调用的 token / 耗时 / 重试原因 | ❌ 只有 `console.log`，无 token |
| N5 | 字数配平 | 越界后怎么处理，放弃时告警 | ⚠️ 有校验，放弃时无告警 |
| N6 | 教学契约自检 | 推导 / 系统 / 基础 / 决策是否做到 | ❌ **完全没有** |
| N7 | 配音 | 分块数 / 失败 / 拼接 | ❌ 只有最终 mp3 |
| N8 | 语速校准 | 实测 vs 假设 | ✅ 可算（257 vs 265） |
| N9 | 版式溢出 | 文字是否截断 / 溢出 | ❌ 只能人眼看图 |
| N10 | 段时长漂移 | 段长 vs 音频长 | ⚠️ 事后可算，未自动 |
| N11 | 成片校验 | 总时长 / 音画同步 | ✅ ffprobe |
| N12 | 成本 | 调用数 / tokens / 金额 | ❌ **完全没有** |

**3 个有 · 3 个部分 · 6 个缺。**

### 缺口各自让我们失去了什么

**N6（教学契约自检）是最贵的缺口。**这一轮用户要的是"强逻辑推导、强系统思维、强基础补强、强自主决策"。这四条我在 PR 里写成了提示词约束，但**这次跑完全没有验证它们**——脚本是 `C:\tmp` 里的一次性代码，没走仓库的大纲链路，也没走审校/修复循环。视频"看起来"有推导感，但那是我的主观判断，不是测量。

**N12（成本）让我们无法定价。**47 次调用，我连一个 token 数都拿不出来。一门 60 分钟的课值多少钱，现在只能靠猜。

**N4（调用明细）让 p14 无法归因。**它报的是 `empty content`，但为什么空——推理吃光了？内容审核？超时？日志里没有 `finish_reason` 和 token 用量，只能猜。

**N9（版式溢出）把自动校验换成了人眼。**p9 的断句是我抽帧看图才发现的。18 页就要看 18 次图，200 页的课不可行。

## 八、与 PR #2125 的关系：这次跑验证了什么

必须说清楚，避免高估这次跑的价值。

| 能力 | 这次跑是否验证 |
| --- | --- |
| 时长预算内核（模块 → 页 → 字数 → 语速） | ✅ **验证了**，60 分计划 → 60.5 分实际 |
| 页密度（0.45 页/分钟） | ✅ 间接验证：18 页 / 60 分 = 0.3，但这是模型欠写倒推的，不是内核给的 |
| 正文质量（推导 / 系统 / 基础 / 决策） | ❌ **未验证**，无测量 |
| 审校 → 修复循环 | ❌ **完全没跑** |
| 确定性审计（`estimatedDuration`） | ❌ 未跑 |
| 课程记忆台账 | ❌ 未跑（并发 3 反而绕开了跨页上下文） |

**结论：这次跑证明的是"能产出 60 分钟成片，且时长可控"，没有证明"教学内容符合四强契约"。**PR 描述里写的"审校/修复循环未对真实模型跑过"，在这次跑之后**依然成立**。

| 优先级 | 事项 | 依据 | 收益 |
| --- | --- | --- | --- |

| P1 | 并发单元从"页"改成"模块" | 6 节缺陷 2/3 | 消除标题撞车与结构趋同 |
