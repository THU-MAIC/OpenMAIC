# 修订实验控制台

> 代码：`scripts/long-form/experiment-server.ts` + `experiment.html`
> 命令：`pnpm experiment:long-form` → 打开 `http://localhost:8787`

---

## 一、它解决什么问题

审校与修复这条链路，此前只有单元测试：提示词写好了、解析器测过了，**但没有任何模型读过它**。

这留下三个无法用代码回答的问题：

1. 6.4k 字符的审校提示词，模型会不会稳定返回合法 JSON？
2. 它能不能分辨"真人写的课"和"把教学抽干的同一门课"？
3. 修复提示词要的是补丁，模型会不会又交一整门课？

整套 90 次调用的流水线不适合用来回答这三个问题——太慢、太贵、失败时不知道坏在哪一环。所以做了一个只跑这四步的控制台。

**它复用生产环境的提示词和解析器**。实验通过，意味着上线的那个东西通过了，不是它的替身。

---

## 二、怎么跑

**Windows 最省事**：双击仓库根目录的 `start-long-form-experiment.cmd`，它会启动服务并自动打开浏览器。

命令行：

```bash
pnpm experiment:long-form
# → 长课修订实验控制台：http://localhost:8787
```

### 三个常见坑

1. **直接打开 HTML 文件不行。** 页面要用 `/api/run` 和 `/api/health`，静态打开没有后端，点按钮不会有任何反应。
   现在页面加载时会先请求 `/api/health`，连不上就顶一条红条告诉你「这个页面没有连上实验服务」，并把按钮置灰——不会再假装能跑。
2. **必须从 `http://localhost:8787` 打开**，不是 `file://`，也不是 IDE 的静态预览。
3. **端口占用**：`EXPERIMENT_PORT=8788 pnpm experiment:long-form`。
4. **出站地址走服务端 URL 守卫。** 页面在 loopback 上，但 loopback 不等于私有：任何打开的网页都能对本机发一个无预检的简单 POST，未经校验的 `Base URL` 就会把开发机变成跳板。所以 `/api/run` 和 `/api/probe` 的目标地址（以及每一次重定向）都过 `lib/server/ssrf-guard`。**自测用的本地 mock 端点要加 `ALLOW_LOCAL_NETWORKS=1`**，否则会明确报「端点被拒绝」。

页面上填三项：

| 字段 | 说明 |
| --- | --- |
| Base URL | 默认 `https://api.stepfun.com/step_plan/v1`，会自动补 `/chat/completions` |
| API Key | 自己填。只进本机进程内存，用于当次请求，不落盘、不打印、不回传 |
| Model | 默认 `step-5-preview` |

可选勾选「额外跑一次真实大纲生成」（+1 次调用，1-3 分钟）。

**为什么要有本地服务**：浏览器直连第三方 API 会被 CORS 挡住；本地服务把请求转出去，页面只跟 localhost 说话。

## 三、十一个检查点

| # | 检查点 | 通过条件 | 坏了说明什么 |
| --- | --- | --- | --- |
| C1 | 接口连通 | 返回非空文本 | 地址/密钥/模型名错 |
| C2 | 审校返回可解析 JSON | `parseCritique` 非空 | 提示词约束不够，或模型不守 JSON |
| C3 | 五维都有分数 | 5/5 维度有数值 | 打分维度没被理解 |
| C4 | 缺陷指向具体页码 | ≥1 条带 `pageIndex` | 审校在泛泛而谈，无法驱动修改 |
| C5 | 缺陷可执行 | 每条都有 `fix` | 同上，且修复会自由发挥 |
| C6a | 劣质稿被判需修改 | 未通过（有低分或缺陷） | 审校没有判别力 |
| C6b | **能区分真人稿与劣质稿** | 真人稿均分 > 劣质稿均分 | 最关键的一条：审校在瞎评 |
| C7 | 修复返回可解析补丁 | `parseRevisionPatch` 非空 | 补丁协议没被遵守 |
| C8 | 补丁可安全应用 | `applyRevisionPatch` 成功 | 页码越界/漂移超限 |
| C9 | 修复让算术缺陷变少 | 修复后缺陷数 < 修复前 | 修复没打中要害 |
| R1 | 真实大纲生成（可选） | 输出含 `outlines` | 大纲提示词链路断 |

### 实验素材

不是造的，是真的：

- **真人稿**：`eval/long-form/scenarios/ch18-analgesics.json`（28 页 / 61 分钟，真人讲过的那门镇痛药课），转成大纲后 `teachingObjective` 取 `purpose`、`keyPoints` 取讲稿提示、时长取分钟数。
- **劣质稿**：同一门课**抽干教学**——`keyPoints` 只剩标题、没有目标、每页 60 秒、全是 slide。这是契约存在的理由，也是审校必须能认出来的东西。

用同一门课做对照，C6b 才有意义：内容一样，教学没了。

## 四、自测结果（mock 模型）

我用一个本地 mock 端点把整条链路跑通，验证控制台本身没问题：

```
PASS  C1 接口连通
PASS  C2 审校返回可解析的 JSON
PASS  C3 五个维度都有分数 | derivation=1 systems=1 foundation=2 agency=1 structure=2
PASS  C4 缺陷指向具体页码 | 2 条缺陷，其中 1 条带页码
PASS  C5 每条缺陷都有可执行的修法 | 2/2 条带 fix
PASS  C6a 劣质稿被判为需要修改 | 均分 1.4，判定 revise
FAIL  C6b 能区分真人稿与劣质稿 | 真人稿均分 1.4 vs 劣质稿 1.4
PASS  C7 修复返回可解析的补丁 | 2 处修改 · 0 处新增 · 0 处删除
PASS  C8 补丁可以安全应用 | 28 页 → 28 页
PASS  C9 修复让算术缺陷变少 | 缺陷 64 → 62
PASS  R1 真实大纲生成
```

**C6b 的失败是正确的**：mock 对两份稿子返回同一份审校，所以它确实区分不了。这条检查点在 mock 下就该红——如果它也绿，说明检查点本身是假的。

真模型跑起来，这一条是整张表里信息量最大的。

## 五、它验证了什么，没验证什么

**验证了**：控制台链路（SSE 流、检查点判定、补丁应用、审计对比）、生产提示词能被渲染、生产解析器能处理返回。

**没验证**：模型对这些提示词的真实反应。mock 只能证明"机器没坏"，证明不了"模型能用"。

**也没验证**：完整流水线。这个控制台只跑审校与修复，不跑 29 页的逐页生成、TTS、渲染。

## 六、跑出失败怎么办

| 失败 | 大概率原因 | 改哪里 |
| --- | --- | --- |
| C1 空内容 | **推理模型把 `max_tokens` 全花在思考上**，`content` 为空而 `reasoning_content` 有值、`finish_reason: "length"` | 已修：探活用 512 token，并允许取 `reasoning_content` |
| C1 其他 | 地址/密钥/模型名错，或该端点不是 chat/completions 结构 | 点「接口诊断」看 `shape` 和 `bodyPreview` |
| C2 / C7 | 模型把 JSON 包在解释里 | 提示词已有"no prose, no code fence"；若仍失败，考虑改 `response_format` |
| C4 | 审校只给维度分不指页码 | 加强 `long-form-critique/system.md` 规则 3 |
| C6b | 审校看不出"抽干教学" | 这是真问题，需要更强的审校模型或更具体的锚点 |
| C8 | 补丁页码越界 | 提示词里 `pageIndex` 的定义要更明确 |
| C9 | 修复改了表面没改算术 | 缺陷描述里的 `fix` 不够具体，或模型没按补丁格式回 |

### 「接口诊断」按钮

在「开始实验」旁边。它只发一次最小请求，把原始响应的**结构**打出来：

```json
{
  "url": "https://api.stepfun.com/step_plan/v1/chat/completions",
  "status": 200,
  "shape": {
    "topLevelKeys": ["choices", "usage"],
    "choiceCount": 1,
    "finishReason": "length",
    "messageKeys": ["content", "reasoning_content"],
    "contentLength": 0,
    "reasoningLength": 6,
    "usage": { "prompt_tokens": 12, "completion_tokens": 32 }
  },
  "text": "让我想想……",
  "source": "reasoning_content"
}
```

`contentLength: 0` + `reasoningLength: 6` + `finishReason: "length"` 这三个数一起出现，就是"预算被推理吃光"的签名。换一个端点结构不同时，这里会直接显示出来，不用猜。

### token 上限的自动降级

审校和修复各用 16000 token。如果端点拒绝（400 且提到 `max_tokens` / `temperature`），会自动降到 4096、再降到 2048 并去掉 `temperature` 重试一次。401/404 这类错误不重试——少发 token 不会让它变好。
