# RJ-laixue 海外托管访问受阻 — 交接文档

> **接收方**：RJ 内部 IT 部门 + Codex（研发协作 AI）
> **发起方**：RJ 大学培训部门（RJ-laixue 产品方）
> **时间**：2026-07-27
> **目的**：完整复盘"福州/金山办公区无法访问 laixue.work"事件，邀请技术评估长期方案
> **版本**：v1.0

---

## TL;DR（一分钟看完）

- **现象**：2026-07-26 起，福州工区 + 金山办公区员工无法访问 https://www.laixue.work（ERR_CONNECTION_RESET）
- **诊断结论**：HTTP/S 业务在办公区出口侧对 Cloudflare 美国 IP 段（104.21.0.0/16 等）有网络层策略阻断
- **影响范围**：北京个人住宅可正常访问；公司办公区（福州/金山）受影响
- **短期方案**：换 DNS / 4G 热点 / 公司防火墙加白名单（立即可执行）
- **长期方案**：私有化部署（已立项，1-3 月规划中）。本次事件**加速**立项的必要性

## 1. 项目背景

### 1.1 RJ-laixue 是什么

锐捷大学培训部门**内部学习平台**，基于 OpenMAIC v0.3.1 上游二次开发。

- **域名**：https://www.laixue.work
- **当前托管**：Vercel 海外
- **数据存储**：Supabase（按 region）
- **上游**：OpenMAIC v0.3.1（已 fork 私有定制）
- **用户**：RJ 内部员工 + 培训学员（数十人使用）
- **业务场景**：新员工入职培训 / 销售赋能 / 知识沉淀

### 1.2 为什么用 Vercel（历史决定）

- 锐捷培训部门非研发主导，希望少运维
- Vercel 一键部署 + preview 环境 + Edge Functions 便利
- 上游 OpenMAIC 推荐 Vercel 部署

### 1.3 已知风险（立项中）

2026-07-24 Phase 0 收尾时已立项的 P0 风险：

| 风险 | 状态 | 紧迫度 |
|---|---|---|
| **私有化部署** | 立项但未启动 | P0（1-3 月） |
| **数据合规**（用户数据出境）| 与私有化同源 | P0 |
| **飞书 SSO** | 立项中 | P0 |
| **大模型私有化** | 立项中 | P0 |

**本次 GFW 事件** = 上述"P0 风险 1（私有化部署）"在生产环境的**首次显式触发**。

## 3. 技术诊断（IT 部门重点看）

### 3.1 关键证据链

| 测试 | 结果 | 含义 |
|---|---|---|
| DNS 解析 | www.laixue.work → 104.21.1.155 | ✅ 域名未污染，指向 Cloudflare 美国 IP |
| 培训部门用户（北京）浏览器 | 可访问 laixue.work | ✅ 北京个人住宅链路通 |
| 培训部门用户（北京）tracert | 14 跳完整到 104.21.1.155 | ✅ 路由可达，延迟合理 |
| 第三方 downforeveryoneorjustme.com | "It's just you. laixue.work is up." | ✅ 全球服务可达 |
| IT 同事（福州）tracert | 13 跳完整到 104.21.1.155 | ✅ 路由可达，延迟合理 |
| IT 同事（福州）ping | 4/4 收到，205-209ms | ✅ ICMP 通（说明链路物理层通）|
| **IT 同事（福州）HTTPS 业务** | **ERR_CONNECTION_RESET** | ❌ **TLS 业务被阻断** |
| 金山办公区同事 | 同样 ERR_CONNECTION_RESET | ❌ **多办公区复现** |
| IT 同事（福州）DNS | 192.168.5.28 + 172.30.44.20 | 内网代理 DNS（公司统一出口） |

### 3.2 诊断结论

**HTTP/S 业务在某些出口侧（公司办公区、移动部分网络）对 Cloudflare 美国 IP 段（104.21.0.0/16 等）有网络层策略阻断**。

⚠️ **无论具体是 GFW 主动干扰还是公司办公区防火墙策略，结果一致：办公区访问 Cloudflare 美国 IP 段不通**。

### 3.3 验证方法（IT 部门可执行）

**判断是 GFW 还是办公区防火墙**：

| 测试 | 期望（如果是 GFW）| 期望（如果是办公区防火墙）|
|---|---|---|
| 换 DNS（`223.5.5.5` / `1.1.1.1`）| 仍不通 | 可能通（如果防火墙是基于域名的）|
| 移动 4G 热点访问 | 通（个人出口通常不受 GFW 影响） | 通 |
| 海外代理（Clash/V2Ray）出口 | 通 | 通 |
| 金山办公区手机 4G 共享电脑 | 通 | 不一定通（金山内部网络）|
| 让 IT 检查金山办公区防火墙 / 代理规则 | — | 找到封锁 Cloudflare 段的规则 |

**关键判断点**：如果**移动 4G 热点能通 + 办公网不能通**——优先排查**办公区防火墙**（这是更可控的根因）。如果**4G 也不能通**——优先排查**国家网络层**（要靠代理或私有化解决）。

## 5. 中长期方案（1-3 月、6-12 月）

### 5.1 方案 A：国内 CDN 镜像（中期 1-3 月）

**核心思路**：保留 Vercel 主站，国内走 CDN 镜像（阿里云/腾讯云/华为云），按 IP 智能调度——海外 IP 回 Vercel，国内 IP 走国内 CDN。

| 维度 | 详情 |
|---|---|
| 部署方式 | Vercel → 国内 CDN edge 节点缓存静态资源 + API 反代 |
| 域名 | `laixue.work` 不在工信部白名单，**必须**走已备案的子域（公司域名）|
| 国内 CDN 选项 | 阿里云 CDN / 腾讯云 CDN / 华为云 CDN（按公司现有合作方）|
| 工程量 | 中（DNS 智能解析 + CDN 配置 + Vercel 反代验证）|
| 一次性成本 | 0 元（公司备案）+ CDN 接入 ~3-5 天 |
| 持续成本 | CDN 流量费（初期几千/月）|
| 效果 | 国内办公区/家庭/4G 都能秒开 |

**前置条件**：
- 公司有 ICP 备案的 .cn 域名（RJ 大概率有）
- 走公司主体备案（10-20 个工作日）
- 部署到国内云厂商

### 5.2 方案 B：双部署分流（中期 1-3 月，推荐）⭐

**核心思路**：
- 保留 Vercel 主站（海外访问、研发 preview）
- **国内部署一个对内入口**（绑公司已备案的子域，如 `learn.ruijie.cn`）
- 通过企业 SSO / VPN 进入国内入口

**架构草图**：
```
                  ┌────────────────────────┐
海外用户/研发 →    │ Vercel (laixue.work)   │ ← 当前
                  └────────────────────────┘

                  ┌────────────────────────┐
国内办公区/学员 →  │ 阿里云 (learn.ruijie.cn)│ ← 新建
                  │ ├─ Next.js 服务
                  │ ├─ Supabase 国内代理（Neon / 阿里云 RDS）
                  │ ├─ 对象存储 OSS（音频/图片 base64 改造承接）
                  │ └─ 身份认证（企业 SSO）
                  └────────────────────────┘
```

**工程量**：
- 阿里云函数计算部署（3-5 天）
- 数据迁移（Supabase → 国内云数据库，2-3 天）
- 域名解析切换（1 天）
- 灰度切流（1 周观察期）

**同时解决**：
- ✅ GFW 阻断问题
- ✅ 数据合规问题（之前 P0 风险）
- ✅ 私有化部署（之前 P0 立项）

**预算估算**（按 RJ 培训部门规模）：
- 阿里云函数计算 + RDS + OSS：500-2000 元/月
- 一次性工程量：约 15-20 人天

### 5.3 方案 C：彻底迁移（长期 6-12 月）

Vercel 完全退役，所有服务在阿里云/腾讯云。

**风险**：
- 失去 Vercel 自动部署 / preview / Edge Functions 等便利
- 团队要懂运维（K8s / Docker 能力评估）
- 数据从 Vercel Postgres 迁到云数据库要重新做迁移工具

**为什么对 RJ 是"治本"**：
- RJ 的最终用户都是中国大陆（培训部门内部）—— Vercel 海外部署**反自然**
- 私有化部署是 P0 必修项（之前规划）
- GFW 事件**加速**了这件事的紧迫性

## 8. 风险与合规

### 8.1 数据合规（P0 已立项）

当前 Vercel + Supabase 海外部署，**锐捷培训数据出境**的合规问题。私有化部署是必修项。

### 8.2 业务连续性

当前 GFW 阻断影响福州/金山办公区，若扩散到其他办公区需紧急响应。

### 8.3 长期规划

- 私有化部署已纳入 RJ-laixue 2026-07-24 Phase 0 之后的 P0 规划（1-3 月）
- 本次 GFW 事件将原 P0-1 优先级"私有化部署"升级为 P0-0

### 8.4 沟通建议

- **对受影响的福州/金山同事**：发话术"是网络层问题，不是工具 bug；临时用 4G 热点 / VPN；IT 在排查"
- **不要发**："是 GFW 阻断了 laixue.work"——可能引发不必要的法律/合规讨论
- **专业话术**："办公区出口对 Cloudflare 美国 IP 段有策略限制，IT 在协调办公区网络调整"
