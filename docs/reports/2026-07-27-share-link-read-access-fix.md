# 分享链接读取授权修复（2026-07-27）

## 触发

场景顺序迁移的冒烟测试中，另一已登录账号打开课程 `1I_kD25GX1` 的
`?share=1` 链接。课程 API 返回 403，播放器随后在 `stage=null` 时读取
`teacherVoiceConfig`，显示通用 client-side exception。

## 根因

服务端 `GET /api/courses/[id]` 仅允许课程属主、管理员/老师或有
`course_assignments` 记录的学员；客户端没有把 `share=1` 传递给该接口。
这与 RJ 当前确认的产品规则冲突：任意已登录内部学员或老师获得分享链接后
均可只读观看课程。

## 修复

- Classroom 在只读分享模式请求课程 API 时透传 `?share=1`。
- API 对已登录且带该参数的 GET 放行；普通 GET 仍执行既有角色/assignment
  校验，POST/DELETE 的属主校验完全未改动。
- 非 2xx 课程响应现在进入页面的错误状态，不再继续渲染空 stage 而白屏。
- 新增 API 回归测试，固定“已登录、未分配、携带分享参数”应得到 200。

## 验收

待部署后，用另一个已登录账号重新打开该链接，确认能进入并浏览首、中、末场景；
再确认同账号对课程 POST 仍返回 403。
